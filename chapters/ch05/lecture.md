# 5장 강의안 — 문서 군집에서 사람이 읽는 주제로

[전체 목차](../../README.md) · [학습 노트](study.md) · [강의안](lecture.md) · [강의 대본](lecture-script.md) · [시각화](visuals.html) · [실습](lab-guide.md) · [문제와 해설](quiz.md)

이 강의는 85분 동안 설명, 손계산, 시각 실험, 토론을 번갈아 진행한다. 시간은 활동을 포함한 수업 설계 시간이며 대본만 읽는 데 걸리는 시간이 아니다. 준비물은 [시각화](visuals.html)를 열 수 있는 브라우저, Python 3, 종이 또는 필기 도구다. 원문은 *Hands-On Large Language Models* 5장, PDF 192–235쪽이다.

## 수업 전에 확인할 내용

교사는 `python3 chapters/ch05/lab.py --check`를 저장소 루트에서 실행해 결과를 확인한다. 코사인 유사도와 임베딩을 모르는 학습자에게는 학습 노트 4절을 미리 안내한다. 시각화는 교육용 좌표로 단순 DBSCAN을 계산한다. 실제 UMAP/HDBSCAN의 결과로 소개하지 않는다.

칠판을 세 영역으로 나눈다. 왼쪽은 “어떤 문서가 함께 있는가”, 가운데는 “어떤 단어가 설명하는가”, 오른쪽은 “어떤 이름을 붙일까”다. 강의 내내 결과가 어느 영역에 속하는지 표시한다. 학습자가 라벨 품질과 군집 품질을 섞어 말하면 이 구분으로 돌아온다.

## 1. 도입 활동: 문의함을 정리하는 세 가지 요청

**판서할 문장**

- A: 이 문의를 미리 정한 환불/배송/계정 중 하나에 넣어라.
- B: 어떤 종류가 있는지 모르니 비슷한 문의를 모아라.
- C: 각 묶음이 무엇에 관한 것인지 짧은 이름을 붙여라.

학생에게 각각 분류, 군집화, 토픽 표현 중 무엇인지 고르게 한다. A=분류, B=군집화, C=토픽 표현이다. C를 단독으로 전체 토픽 모델링과 완전히 같다고 단정하기보다, 이 장의 토픽 모델링 파이프라인에서 맡는 단계라고 설명한다.

**후속 질문:** 같은 문서 묶음을 “배송”에서 “배송 지연 불만”으로 바꾸면 군집이 바뀌었는가? 기대 답은 “문서의 소속이 그대로라면 이름만 달라졌다”다. 이 구분을 칠판에 남긴다.

## 2. 모양 추적 활동: 44,949는 어디로 갔을까

**판서 도식**

```mermaid
flowchart LR
    A[초록 44,949개] --> B[44,949 × 384]
    B --> C[44,949 × 5]
    C --> D[라벨 44,949개]
```

학습자에게 “UMAP이 문서를 다섯 개로 줄였나요?”라고 묻는다. 정답을 바로 주지 말고 행이 문서라는 사실을 상기시킨다. 차원은 줄어도 문서 수는 유지된다. 임베딩 모델이 의미 기준을 만들고, 축소 모델이 관계를 압축하며, 군집 모델이 묶음의 경계를 정한다.

**미니 활동:** 아래 항목을 단계에 연결한다.

| 상황 | 우선 살펴볼 단계 | 이유 |
|---|---|---|
| 한국어 전문 약어가 전혀 가까워지지 않음 | 임베딩/입력 처리 | 의미 표현 자체의 문제 가능성 |
| 2차원 그림에서 두 주제가 겹침 | 시각화용 차원 축소 | 5차원 군집이 잘못됐다고 바로 결론 불가 |
| 작은 주제가 모두 미배정됨 | 군집 설정과 축소 공간 | 최소 규모·밀도 판단의 영향 가능성 |
| 군집은 일관되지만 이름이 너무 넓음 | 표현 단계 | 구성과 설명의 문제를 분리 |

원인 후보를 하나의 확정 원인으로 표현하지 않는 것도 학습 포인트다.

## 3. 밀도 실험: 군집은 고정된 정답이 아니다

[시각화](visuals.html)의 첫 실험을 연다. 기본 반경 0.45, 최소 이웃 수 3일 때 일반 군집 3개와 미배정 2개를 확인한다. 반경을 0.10으로 내리고, 다시 3.00까지 올린다. 각각 군집이 사라지거나 연결되는 현상을 관찰한다. 이 실험은 DBSCAN의 이웃 관계를 보여주며 HDBSCAN의 계층/안정성 선택은 포함하지 않는다.

**질문:** 같은 좌표인데 정답이 달라진 것인가? 기대 답은 “묶음의 기준을 바꿨으므로 발견하는 구조가 달라진다”다. 좋은 기준은 목적과 실제 문서를 보고 정한다.

**판서:** `{-1, 0, 1, 2}`의 크기는 4지만 일반 토픽은 3개. 원문 156은 일반 토픽 155개와 미배정 라벨을 포함한 고유 라벨 수로 해석한다. 미배정 문서들끼리 비슷하다는 의미가 아니다.

**검토 과제:** 군집 0의 앞 문서 세 개만 읽는 것과 무작위/대표/경계 문서를 읽는 것의 차이를 말해보게 한다. 앞 세 문서는 빠른 시작점이지만 전체를 대표한다고 보장되지 않는다. 원문 코드의 표본 추출은 무작위가 아니라 앞 세 개다.

## 4. c-TF-IDF 손계산 워크시트

세 군집의 총 단어 수가 각각 12다. 음성 토픽에 `speech=4`, `audio=3`, `model=2`, `the=3`이 있다. 다른 두 토픽에도 `model=2`, `the=3`이 있으며 `speech`는 없다.

**판서 순서**

1. `A=(12+12+12)/3=12`.
2. `F_speech=4`, `F_model=6`, `F_the=9`.
3. `cTF_speech=4/12`.
4. `IDF_speech=ln(1+12/4)=ln4`.
5. `weight_speech=(1/3)ln4≈0.4621`.

학습자에게 `model`과 `the`를 계산하게 한다. 계산기는 사용해도 좋다. 중요한 것은 소수점 암기가 아니라 분모가 무엇인지 설명하는 것이다.

| 단어 | 예상 가중치 | 학생에게 물을 해석 |
|---|---:|---|
| speech | 0.4621 | 어떤 점에서 군집을 구별하는가? |
| model | 0.1831 | 여러 군집에 공통이라는 것이 반영되는가? |
| the | 0.2118 | 왜 불용어인데 model보다 높게 남는가? |

**채점 포인트:** `F_x`를 문서 수로 세지 않았는가, 군집 길이로 정규화했는가, 로그 안에 `+1`을 넣었는가, 가중치를 확률로 해석하지 않았는가.

시각화 두 번째 실험에서 `the`의 빈도를 늘린다. IDF가 낮아지는 것과 최종 점수가 낮아지는 것은 항상 같은 일이 아님을 보인다. 빈도 항도 함께 바뀌기 때문이다. 그다음 `the 제거`를 선택하고 A와 다른 단어의 가중치도 달라지는지 확인한다.

## 5. 키워드 개선 활동: 읽기 쉬움, 정확성, 다양성

**첫 목록:** `translation, nmt, machine, neural, bleu`.

**개선된 것처럼 보이는 목록:** `translation, translating, translate, language, text`.

두 번째가 일반 독자에게는 쉬울 수 있지만 `nmt`, `bleu` 같은 분야 정보가 줄었다. 학생에게 “어느 목록이 무조건 좋은가?” 대신 “누가 어떤 목적으로 읽는가?”를 묻는다. KeyBERTInspired는 대표 문서의 평균 임베딩과 후보 단어를 비교하지만 약어를 원하는 방식으로 표현하지 못할 수 있다.

**MMR 손계산:** 후보 A는 관련성 0.95, 중복 0.98; 후보 B는 관련성 0.80, 중복 0.30. 다양성 d=0.2일 때 A=0.564, B=0.580으로 B를 선택한다. 최고 관련성만 선택한 결과와 다르다는 것을 확인한다.

시각화 세 번째 실험에서 d=0과 d=0.7을 비교한다. 관련성 순위는 `summarization`, `summary`, `summaries`를 연속 선택한다. 다양성을 반영하면 `rouge`, `document`, `extractive`가 들어온다. 인위적으로 설계한 벡터이므로 실제 모델 우열의 증거로 제시하지 않는다.

## 6. 생성 라벨 검토 활동

다음 키워드를 제시한다: `medical, clinical, biomedical, patient, ehr`.

후보 이름 세 개를 보여준다.

- “Science/Tech”
- “임상 기록과 의료 자연어 처리”
- “특정 병원의 특정 질병 예측을 위한 최신 초거대 모델”

첫 이름은 너무 넓고, 세 번째는 근거에 없는 좁은 세부 사항을 덧붙였다. 두 번째가 상대적으로 적절하지만 실제 대표 문서를 읽기 전에는 확정하지 않는다. 학생에게 키워드만으로 판단할 수 있는 범위와 문서가 필요한 범위를 구분하게 한다.

**판서:** 대표 문서 + 키워드 + 출력 형식 → 생성 이름 → 근거 검토. 토픽당 한 번의 이름 생성이 문서당 생성보다 호출 수를 줄일 수 있다. 이름의 자연스러움은 군집의 일관성이나 사실성 보증이 아니다.

## 7. 실습 활동과 관찰 기록

[실습 안내](lab-guide.md)에 따라 기본 실행과 아래 두 가지 변경을 수행한다. 컴퓨터가 없으면 시각화로 대체한다.

```bash
python3 chapters/ch05/lab.py --check
python3 chapters/ch05/lab.py --eps 0.1
python3 chapters/ch05/lab.py --drop-stopwords --diversity 0.2
```

| 관찰 기록 | 학생이 채워야 할 내용 |
|---|---|
| 군집 변경 | 설정 → 군집 수/미배정 수 변화 → 왜 그런지 |
| 가중치 변경 | 단어 제거 → A 변화 → 남은 단어의 점수 변화 |
| 다양성 변경 | d 변화 → 선택 단어 변화 → 얻은 정보와 잃을 수 있는 관련성 |

실습은 실제 계산을 하지만 실제 언어 모델을 실행하지 않는다. 이 차이를 학생이 자신의 문장으로 설명해야 활동을 마쳤다고 본다.

## 8. 출구 문제와 성취 기준

학습자는 다음 내용을 1분 동안 연결해서 설명한다.

“문서의 군집을 만드는 세 단계는 무엇이며, c-TF-IDF가 어떤 정보를 추가하고, 생성 모델은 무엇을 바꾸는가?”

성취 기준은 10점 만점이다. 임베딩→축소→군집화 순서와 역할 3점, c-TF-IDF의 군집 내 빈도와 전체 빈도 2점, 표현만 바꿀 수 있다는 모듈성 2점, 이상치·2D 투영·생성 라벨 한계 중 두 가지 2점, 실제 문서 확인의 필요성 1점이다.

과제는 [문제와 해설](quiz.md) 1–12번을 풀고, 응용 설계 문제 중 하나를 선택해 자신의 데이터에 적용 계획을 쓰는 것이다. 학습 노트의 원문 대응 목차로 약한 절을 다시 찾아간다.
