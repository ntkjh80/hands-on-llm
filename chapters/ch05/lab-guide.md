# 5장 실습 안내 — 군집, 단어 가중치, 키워드 다양성 직접 계산하기

[전체 목차](../../README.md) · [학습 노트](study.md) · [강의안](lecture.md) · [강의 대본](lecture-script.md) · [시각화](visuals.html) · [실습](lab-guide.md) · [문제와 해설](quiz.md)

이 실습은 텍스트 군집화와 토픽 표현의 결정을 작은 데이터로 분해해 살펴본다. [lab.py](lab.py)는 표준 Python 라이브러리만 사용하고, [lab-output.txt](lab-output.txt)는 `--check` 옵션으로 실제 실행한 기록이다. 외부 패키지, GPU, 인터넷, API 키가 필요하지 않다.

원문 연결: *Hands-On Large Language Models* 5장, PDF 194–210쪽의 군집화·c-TF-IDF와 226–228쪽의 MMR. 이 실습의 문서·좌표·벡터는 새로 만든 교육용 예제이며 책의 논문 데이터에서 나온 수치가 아니다.

## 이 실습이 하는 일과 하지 않는 일

| 구성 | 실제로 수행하는 계산 | 범위 |
|---|---|---|
| 문서 좌표 | 14개 문서의 수작업 2차원 좌표 사용 | 언어 모델의 임베딩 출력 아님 |
| 군집화 | 이웃 반경과 최소 이웃 수를 사용하는 DBSCAN | HDBSCAN 계층/안정성 선택 아님 |
| 단어 표현 | 군집별 단어 집계, 정규화 cTF, IDF, 가중치 | 기본 c-TF-IDF 원리를 직접 계산 |
| 다양성 | 가상 키워드 벡터의 코사인 유사도와 MMR | 실제 키워드 임베딩 모델 아님 |
| 생성 이름 | 수행하지 않음 | LLM 결과를 만들어내지 않음 |

난수는 사용하지 않는다. 데이터, 순회 순서, 동점 처리 방식이 고정되어 같은 인자에 같은 결과를 얻는다. 보통의 실행 시간은 작지만 여기서는 기계별 속도 측정이나 성능 주장을 하지 않는다.

## 1. 실행 방법

저장소 루트에서 실행한다.

```bash
python3 chapters/ch05/lab.py
python3 chapters/ch05/lab.py --check
python3 chapters/ch05/lab.py --help
```

이미 `chapters/ch05` 폴더 안에 있다면 다음처럼 실행할 수 있다.

```bash
python3 lab.py --check
```

`--check`는 손계산과 비교할 수 있는 가중치, 모든 점이 이상치인 경우, DBSCAN에서 처음 미배정되었던 점이 경계점으로 편입되는 경우 등을 검산한다. 출력의 `PASS`는 이 작은 계산들의 검증이며 실제 BERTopic이나 언어 모델의 품질 검증이 아니다.

## 2. 문서 데이터 읽기

문서 ID는 S1–S4, T1–T4, H1–H4, X1–X2다. 앞의 세 그룹은 음성, 번역, 임상 관련 교육용 단어 조합이며 X1과 X2는 떨어져 있는 점이다. 단어를 작은 영어 목록으로 둔 이유는 형태소 분석이나 모델 다운로드 없이 빈도를 손으로 검산하기 위해서다.

각 정상 그룹은 네 문서로 구성되고 전체 단어 수는 12다. 예를 들어 음성 그룹은 다음과 같다.

| ID | 내용 | 좌표 |
|---|---|---|
| S1 | speech audio model the | (0.0, 0.0) |
| S2 | speech audio the | (0.2, 0.1) |
| S3 | speech audio model | (-0.1, 0.2) |
| S4 | speech the | (0.1, -0.2) |

토큰화는 소문자 변환 후 공백 분리다. 일반 텍스트의 문장부호, 복합어, 한국어 조사를 제대로 다루는 토크나이저가 아니다. 데이터가 이미 이 방식에 맞게 준비되어 있다. 이것을 실제 한국어 토픽 모델링의 전처리 표준으로 사용하지 않는다.

**관찰 질문:** 텍스트를 바꾸고 좌표를 그대로 두면 군집 결과는 바뀔까? 기본 실습의 군집화는 좌표만 보므로 바뀌지 않는다. 그러나 단어 빈도와 키워드 가중치는 바뀐다. 실제 임베딩 파이프라인에서는 텍스트를 바꾸면 임베딩도 다시 계산해야 한다. 이 차이는 두 단계를 분리해 배우기 위한 의도적인 단순화다.

## 3. 밀도 기반 군집화 이해하기

`dbscan()`은 모든 점 쌍 사이의 유클리드 거리를 계산하고 반경 `eps` 이내의 이웃 목록을 만든다. 최소 이웃 수에는 점 자신이 포함된다. 기본 `eps=0.45`, `min_points=3`에서는 네 점씩 세 군집이 형성되고 X1, X2는 미배정된다.

```text
Topics excluding -1: 3; unique labels: 4
Noise: 2/14 = 14.3%
```

처음에는 주변 점이 부족해 미배정된 점도, 나중에 발견된 조밀한 군집의 경계점이면 그 군집에 편입될 수 있다. 코드에서 `labels[j] in (None, -1)`인 점에 군집 라벨을 부여하는 이유다. 모든 미배정 점을 영원히 고정하는 구현은 이 경계점 처리를 놓칠 수 있다.

다음 변경 실험을 실행해보자.

```bash
python3 chapters/ch05/lab.py --eps 0.1
python3 chapters/ch05/lab.py --eps 3
python3 chapters/ch05/lab.py --min-points 5
```

| 변경 | 이 가상 데이터의 결과 | 해석 |
|---|---|---|
| 반경 0.1 | 정상 군집 0, 미배정 14 | 이웃이 충분하지 않음 |
| 반경 3 | 정상 군집 1, 미배정 2 | 원래 세 묶음이 연결됨 |
| 최소 이웃 수 5, 기본 반경 | 정상 군집 0, 미배정 14 | 각 조밀한 묶음은 네 점뿐 |

HDBSCAN의 `min_cluster_size`와 이 실습의 `min_points`는 같은 매개변수가 아니다. 실습은 단순 DBSCAN의 핵심점 판정 기준을 노출한다. 책의 HDBSCAN은 계층과 군집 안정성 등을 활용하여 결과를 고르므로, 실습의 반경과 결과를 그대로 HDBSCAN에 대응시키지 않는다.

## 4. c-TF-IDF를 코드와 손으로 연결하기

`class_tfidf()`는 각 문서의 단어를 군집 라벨별 `Counter`에 합친다. 이 실습에서는 `-1` 문서를 가중치 계산에서 제외한다. 서로 관련 없는 미배정 문서들을 하나의 의미 있는 토픽처럼 가르치지 않기 위한 교육용 규약이다. 실제 BERTopic은 미배정 집합의 표현을 유지할 수 있으며 책도 -1의 키워드 행을 보여준다. 따라서 실제 패키지 결과와 소수점까지 일치시키기 위한 실습은 아니다.

주요 중간값은 다음과 같다.

| 변수 | 의미 | 기본 예제 |
|---|---|---|
| `counts[label][word]` | 군집별 단어 출현 수 | 음성의 speech=4 |
| `totals[label]` | 군집 전체 단어 수 | 각 군집 12 |
| `global_counts[word]` | 계산 대상 군집 전체의 단어 수 | model=6, the=9 |
| `average_length` | 군집당 평균 총 단어 수 A | 12 |
| `idf[word]` | ln(1+A/F) | speech의 ln4 |
| `scores[label][word]` | 군집 상대 빈도×IDF | speech≈0.462098 |

코드가 `math.log1p(A/F)`를 쓰는 것은 `ln(1+A/F)`를 계산하기 위해서다. 별도의 모델을 학습하는 연산이 아니다. 가중치 값은 데이터의 빈도와 공식에서 직접 나온다.

```text
speech       f= 4 idf=1.386294 weight=0.462098
audio        f= 3 idf=1.609438 weight=0.402359
the          f= 3 idf=0.847298 weight=0.211824
model        f= 2 idf=1.098612 weight=0.183102
```

**관찰 질문:** `the`가 `model`보다 높은 이유는 무엇인가? IDF는 낮지만 cTF가 더 크기 때문이다. 점수의 한 항만 보고 최종 순위를 예측해서는 안 된다.

불용어를 제거해본다.

```bash
python3 chapters/ch05/lab.py --drop-stopwords
```

군집당 길이가 12에서 9로 줄어 A도 9가 된다. `speech` 점수는 `(4/9)×ln(1+9/4)≈0.523847`로 변한다. 단어 하나를 제거하면 다른 단어의 상대 빈도와 IDF도 바뀔 수 있다는 것을 확인한다.

모든 점이 미배정이면 계산할 정상 군집이 없다. 코드는 빈 결과와 A=0을 반환하고 “계산할 토픽 표현이 없다”고 출력한다. 0으로 나누거나 빈 결과를 그럴듯한 주제로 포장하지 않는다.

## 5. MMR은 별도의 키워드 선택 실험이다

실습 후반은 앞의 음성·번역·임상 군집과 **별도의 요약 토픽 예제**다. `summarization`, `summary`, `summaries`, `document`, `extractive`, `rouge`에 세 성분의 가상 벡터를 부여했다. summary 계열은 서로 거의 같은 방향이다. 토픽 벡터는 `(1,0,0)`이다.

`mmr()`은 첫 단어를 관련성으로 고른 후, 남은 후보에 아래 점수를 계산한다.

```text
(1 - diversity) * relevance - diversity * maximum_redundancy
```

각 선택 이후 이미 선택한 단어 집합이 달라지므로 중복 점수도 다시 계산한다. 처음 계산한 순위를 고정한 채 위에서 네 개를 자르는 알고리즘이 아니다.

기본 실행은 d=0의 결과와 사용자가 지정한 d(기본 0.7)의 결과를 나란히 보여준다.

| d | 이 가상 벡터에서 선택되는 네 단어 |
|---:|---|
| 0 | summarization, summary, summaries, document |
| 0.7 | summarization, rouge, document, extractive |

```bash
python3 chapters/ch05/lab.py --diversity 0.2
python3 chapters/ch05/lab.py --diversity 1
```

d=1에서는 첫 선택을 제외하면 관련성 항의 비중이 0이 된다. 이 극단은 다양성을 과하게 강조하는 위험을 보여준다. 음수 점수도 가능하며 오류가 아니다. 후보들 사이의 순위 비교에 사용하는 값이기 때문이다. MMR은 새로운 키워드를 생성하지 않으므로 후보에 없는 중요한 단어를 되찾을 수 없다.

## 6. 코드 읽기 순서

1. `DOCUMENTS`에서 텍스트와 좌표가 별도 입력임을 확인한다.
2. `dbscan()`에서 이웃 생성, 핵심점 여부, 큐 확장, 경계점 편입을 찾는다.
3. `class_tfidf()`에서 군집 단위 집계와 정규화, 전역 빈도를 분리한다.
4. `cosine()`에서 0벡터와 차원 불일치를 왜 거부하는지 생각한다.
5. `mmr()`에서 `selected`가 커질 때 중복 벌점이 어떻게 달라지는지 따라간다.
6. `run_checks()`에서 앞의 세 점이 일렬로 놓인 경계 사례를 종이에 그려본다.
7. `main()`에서 사용자 입력 범위 검사와 결과 해석 문장을 확인한다.

좌표 쌍을 모두 비교하므로 이 DBSCAN 구현은 작은 예제를 위한 O(N²) 방식이다. 큰 문서 데이터에 그대로 적용할 생산용 구현이 아니다. 성능 최적화보다 결정의 원리를 읽을 수 있게 만드는 것이 목적이다.

## 7. 원문의 실제 모델 실습으로 확장하기

아래는 2024년 원문의 단계와 필요한 준비를 연결한 실행 계획이다. **이 자료에서는 arXiv 다운로드, 실제 임베딩, UMAP/HDBSCAN/BERTopic, Flan-T5, 외부 API 호출을 실행하지 않았다.** 현재 환경 호환성과 정확한 설치 버전은 사용할 공식 예제의 버전에서 확인해야 한다.

| 단계 | 준비와 실행 흐름 | 저장할 중간 산출물 |
|---|---|---|
| 데이터 | `datasets`로 원문 데이터셋 로드, ID/제목/초록의 행 정렬 확인 | 정제 규칙, 데이터 버전, 행 ID |
| 임베딩 | `sentence-transformers`, 선택 모델의 입력 길이·언어 확인 | 임베딩 배열과 모델 정보 |
| 차원 축소 | `umap-learn`, 군집용 5차원과 그림용 2차원 분리 | 두 좌표 배열, 설정, 시드 |
| 군집화 | `hdbscan`, 최소 군집 크기와 미배정 비율 관찰 | 라벨 배열, 토픽 수, 크기 분포 |
| 토픽 표현 | `bertopic`, 단어 전처리와 c-TF-IDF 확인 | 키워드, 대표 문서, 원본 표현 복사 |
| 표현 개선 | KeyBERTInspired와 MMR을 같은 군집에서 비교 | 개선 전후 목록과 도메인 용어 검토 |
| 생성 이름 | 선택한 모델의 접근 조건·비용·문서 길이 점검 | 프롬프트, 입력 근거, 생성 이름 |
| 결과 탐색 | 문서 지도, 키워드 막대, 유사도 행렬, 계층도 | 원문으로 돌아갈 수 있는 연결 |

실제 모델 환경에는 모델 가중치 다운로드와 추가 패키지가 필요하고, 임베딩 및 생성 모델은 하드웨어에 따라 시간이 크게 달라진다. 모델을 실행할 자원이 부족하면 작은 표본으로 시작하고 임베딩을 저장해 재사용한다. 원문은 모델 실행을 위한 Colab 환경을 안내하지만, 무료 GPU 제공이나 특정 서비스 접근이 지금도 동일하다고 가정하지 않는다.

실행 후 원문과 토픽 ID나 수치가 달라도 곧바로 실패로 판단하지 않는다. 데이터 버전, 모델 버전, 라이브러리, 난수, 순서가 결과에 영향을 줄 수 있다. 비교의 핵심은 의미상 타당한 문서 묶음인지, 미배정의 내용은 무엇인지, 키워드와 이름이 근거를 잘 나타내는지다.
