## 1. 분류와 군집화의 차이

고객 문의를 이미 정한 “환불·배송·계정”에 넣는 작업과, 범주를 모른 채 비슷한 문의를 모으는 작업은 어떻게 다른가? 각 작업에서 필요한 사전 정보를 설명하라.

<details>
<summary>해설과 채점 기준</summary>

첫 작업은 정해진 범주를 예측하는 분류다. 지도학습이라면 범주별 학습 라벨도 필요하다. 두 번째는 군집화이며 정답 범주를 미리 주지 않고 선택한 표현 공간에서 유사한 문서 집합을 찾는다. 군집 결과에 사람이 읽는 키워드나 이름을 붙이는 일은 토픽 표현 단계와 연결된다.

**3점:** 정해진 범주 여부 1점, 정답 정보와 유사성 구조의 차이 1점, 군집과 이름 붙이기 구분 1점. “분류는 AI, 군집화는 통계”처럼 모델 종류로만 나누면 오답이다.

</details>

## 2. 행렬의 모양 추적

문서 44,949개를 384차원으로 임베딩한 뒤 UMAP으로 5차원으로 줄이고 군집화했다. 각 단계의 데이터 모양을 적어라. “UMAP 후 문서가 5개가 되었다”는 주장을 반박하라.

<details>
<summary>해설과 채점 기준</summary>

임베딩은 `44949×384`, 축소 후는 `44949×5`, 문서별 라벨은 길이 44,949다. 행은 문서이고 열은 좌표 성분이므로 열 수만 줄었다. 문서 수를 줄이는 표본 추출과 다르다.

**3점:** 각 모양 1점씩. 행/열의 의미를 뒤집으면 해당 점수를 얻지 못한다. 원문 PDF 195–199쪽과 연결된다.

</details>

## 3. 5차원과 2차원을 구분하기

5차원 좌표로 HDBSCAN을 실행한 후 원래 임베딩에서 별도로 2차원 UMAP을 만들었다. 2차원 그림에서 두 군집이 겹쳐 보이면 HDBSCAN이 잘못되었다고 결론 내려도 되는가?

<details>
<summary>해설과 채점 기준</summary>

바로 결론 내릴 수 없다. 군집화는 5차원 공간에서 이루어졌고 그림은 별도의 2차원 투영이다. 투영은 정보를 잃어 서로 다른 구조를 겹쳐 보이게 할 수 있다. 원래 의미 임베딩과 군집용 공간, 실제 문서 내용을 함께 확인해야 한다.

**3점:** 두 공간의 목적 구분 1점, 정보 손실 설명 1점, 실제 문서 검토라는 후속 조치 1점. “시각화는 항상 틀린다”는 극단적 답도 적절하지 않다.

</details>

## 4. 정상 토픽은 몇 개인가

라벨 배열이 `[0, 0, 1, 1, 2, -1, -1]`이다. 고유 라벨 수, 일반 토픽 수, 미배정 비율을 구하라. 두 개의 `-1` 문서가 같은 주제라고 말할 수 있는가?

<details>
<summary>해설과 채점 기준</summary>

고유 라벨 수는 4, 일반 토픽은 3, 미배정 비율은 `2/7≈28.57%`다. -1은 어느 군집으로도 배정되지 않았음을 뜻할 뿐 두 문서끼리 의미상 비슷하다는 보장은 없다. 같은 이유로 원문의 고유 라벨 156과 일반 토픽 155를 구분한다.

**4점:** 숫자 세 개 각 1점, -1 해석 1점.

</details>

## 5. c-TF-IDF의 각 기호

`w(x,c) = [f(x,c)/L_c] × ln(1+A/F_x)`에서 f, L, A, F를 설명하라. F를 “단어가 나타난 문서 수”로 계산해도 되는가?

<details>
<summary>해설과 채점 기준</summary>

f는 군집 c의 단어 x 출현 횟수, L은 그 군집의 총 단어 수, A는 군집별 총 단어 수의 평균, F는 계산 대상 전체 군집에 걸친 x의 총 출현 횟수다. 여기서 F는 문서 빈도가 아니다. 일반 문서 TF-IDF의 익숙한 형태와 혼동하지 않는다.

**5점:** 기호 정의 각 1점, 문서 수와 출현 수 구분 1점. 로그의 +1은 괄호 안에 있다는 점도 설명하면 좋다.

</details>

## 6. 가중치 손계산

세 군집의 길이가 모두 12다. 첫 군집의 `speech`는 4회이고 다른 군집에는 없다. `model`은 각 군집에 2회씩 있다. 첫 군집에서 두 단어의 c-TF-IDF를 계산하라. 자연로그를 사용한다.

<details>
<summary>해설과 채점 기준</summary>

A=12. speech의 F=4, cTF=4/12, IDF=ln4이므로 가중치는 약 0.462098이다. model의 F=6, cTF=2/12, IDF=ln3이므로 약 0.183102다. speech는 해당 군집에서 더 많이 등장하고 전체적으로 더 드물어 구별력이 더 크게 반영된다.

**4점:** 두 단어의 중간값 설정 각 1점, 최종 수치 각 1점. 계산기 오차는 소수 셋째 자리 수준까지 허용한다. 가중치를 확률이라고 설명하면 해석은 수정해야 한다.

</details>

## 7. 불용어가 높은 이유

위 세 군집 각각에 `the`가 3회씩 있다. the의 IDF는 model보다 작은데 최종 가중치는 더 높다. 왜 가능한가? 이것을 보고 “c-TF-IDF 구현 오류”라고 단정해도 되는가?

<details>
<summary>해설과 채점 기준</summary>

the의 cTF=3/12, F=9, IDF=ln(1+12/9)≈0.847298이며 가중치는 약 0.211824다. model보다 IDF는 작지만 cTF가 크므로 곱이 더 크다. 이는 공식에 따른 정상 결과다. c-TF-IDF는 불용어를 완전히 제거하는 의미 판별기가 아니다. 전처리와 표현 개선 블록을 고려할 수 있다.

**3점:** 곱의 두 항 설명 1점, 계산 또는 타당한 비교 1점, 불용어 처리의 한계와 후속 대안 1점.

</details>

## 8. KeyBERTInspired의 순서

다음 작업을 올바른 순서로 배열하고 왜 전체 임베딩·군집화를 다시 할 필요가 없는지 설명하라.

- A. 후보 키워드 임베딩과 토픽 의미 벡터를 비교한다.
- B. c-TF-IDF로 대표 문서를 고른다.
- C. 대표 문서를 임베딩하고 평균한다.
- D. 키워드를 의미 관련성으로 재정렬한다.

<details>
<summary>해설과 채점 기준</summary>

B→C→A→D. 후보 키워드 임베딩은 비교 전에 준비한다. 이 작업은 이미 정해진 군집을 어떻게 표현할지 바꾸므로 기존 문서 소속을 유지할 수 있다. 전체 문서 임베딩·축소·군집화의 재학습과 구분한다.

**3점:** 순서 1점, 대표 문서 평균과 키워드의 비교 1점, 구성과 표현의 분리 1점. 원문 PDF 223–225쪽.

</details>

## 9. MMR 손계산

이미 한 키워드를 선택했다. 후보 A의 관련성은 0.95, 최대 중복은 0.98이고, 후보 B는 각각 0.80, 0.30이다. d=0.2일 때 다음에 선택할 후보를 구하라. d=0이라면 어떻게 되는가?

<details>
<summary>해설과 채점 기준</summary>

A=`0.8×0.95−0.2×0.98=0.564`, B=`0.8×0.80−0.2×0.30=0.580`이므로 B다. d=0에서는 관련성만 남으므로 A다. MMR이 관련성만 높은 중복 표현보다 다른 정보를 담은 후보를 선택할 수 있음을 보여준다.

**4점:** 점수 두 개 각 1점, B 선택 1점, d=0의 A와 이유 1점.

</details>

## 10. 약어가 사라진 개선

원래 키워드가 `translation, nmt, neural, bleu`이고 개선 후 `translation, translating, translate, language`가 되었다. 더 읽기 쉬워졌으므로 무조건 좋은 개선이라고 평가할 수 있는가?

<details>
<summary>해설과 채점 기준</summary>

그렇게 단정할 수 없다. 일반 독자에게 쉬운 단어가 늘었지만 nmt, bleu처럼 전문가에게 중요한 정보가 사라졌고 유사한 translation 계열의 중복이 늘었다. 독자·목적에 따라 의미 관련성, 전문 용어 보존, 다양성, 대표 문서와의 일치를 평가한다. MMR은 중복을 줄일 수 있지만 초기 후보에서 사라진 단어를 새로 생성하지는 않는다.

**4점:** 대상 독자/목적 1점, 약어 손실 1점, 중복 문제 1점, 후보 제약과 평가 계획 1점.

</details>

## 11. 생성 라벨 호출 수

문서 1,000,000개와 토픽 200개가 있다. 문서마다 생성 모델을 호출하는 방식 대신 토픽마다 대표 문서 네 개와 키워드를 넣어 한 번 이름을 만든다. 기본 호출 횟수는 각각 얼마인가? 실제 총 비용이 정확히 5,000분의 1이라고 주장할 수 있는가?

<details>
<summary>해설과 채점 기준</summary>

기본 호출 수는 1,000,000회와 200회로 5,000배 차이다. 하지만 입력 길이, 출력 길이, 모델 요금, 재시도, 대표 문서 선택·임베딩 비용이 다르므로 총 비용까지 정확히 그 비율이라고 주장할 수 없다. 구조적인 호출 수 절감과 실제 비용 산정을 구분한다.

**3점:** 호출 횟수 1점, 비율 1점, 총 비용 조건 1점.

</details>

## 12. 같은 번호, 다른 주제

수작업 군집 결과에서 cluster 0은 수어였는데, BERTopic의 topic 0은 음성 인식이다. 이것만으로 데이터가 손상되었다고 판단할 수 있는가?

<details>
<summary>해설과 채점 기준</summary>

아니다. 군집/토픽 ID는 의미 이름이 아니라 식별자이며 후속 처리나 재학습에서 재정렬될 수 있다. 실제 문서 집합의 대응과 라벨 매핑을 확인해야 한다. 같은 번호가 같은 주제를 뜻한다고 가정하지 않는다. 물론 행 정렬 오류도 가능한 원인 후보이므로 문서 ID를 기준으로 검토한다.

**3점:** ID의 의미 1점, 재정렬 가능성 1점, 문서 ID에 의한 확인 1점.

</details>

## 13. 디버깅: 이상치가 사라지지 않는다

`df["cluster"]`를 `str(label)`로 저장한 뒤 `df[df["cluster"] != -1]`을 실행했다. 모든 행이 남았다. 원인과 수정 방법을 설명하라. 원문의 그리기 코드에서 `to_plot`과 `clusters_df`처럼 변수 이름이 다르게 등장하는 경우도 함께 처리하라.

<details>
<summary>해설과 채점 기준</summary>

문자열 `"-1"`과 정수 `-1`은 다르기 때문에 모든 행이 조건을 만족했다. 열을 정수로 유지하거나 비교값을 문자열로 맞춘다. 이름 불일치는 같은 역할의 데이터 프레임 이름을 일관되게 사용해 수정한다. 예를 들어 `clusters_df`, `outliers_df`로 통일하고 이후 그 이름만 쓴다.

**4점:** 타입 차이 1점, 일관된 수정 1점, 변수 이름 연결 1점, 이후 집계/플롯에서도 같은 규약 유지 1점.

</details>

## 14. 디버깅: 원본 비교 결과까지 바뀐다

표현 갱신 전 `original = topic_model.topic_representations_`를 저장했다. 갱신 후 original도 달라진 듯하다. 어떤 문제가 생길 수 있으며 어떻게 비교 자료를 보존할까?

<details>
<summary>해설과 채점 기준</summary>

단순 대입은 같은 변경 가능한 객체를 참조할 수 있다. 내부 자료가 갱신되면 비교용 이름에서도 변경이 보일 수 있으므로 중첩 자료를 보존하려면 `deepcopy`처럼 독립 복사를 고려한다. 토픽 ID와 문서 구성도 고정하고 동일 ID의 전후 키워드를 비교한다. 단어 목록만 달라졌는지 문서 구성까지 바뀌었는지 구분한다.

**3점:** 참조 문제 1점, 독립 복사 1점, 비교 조건 통제 1점.

</details>

## 15. 응용 설계: 한국어 고객 문의의 새로운 유형 발견

라벨 없는 한국어 고객 문의 20만 건을 분석한다. 배송·환불 외에 새 문제를 발견하는 것이 목적이다. 데이터 준비부터 군집 검토와 이름 붙이기까지 계획을 쓰고, 결과가 실패했을 때 서로 다른 단계에서 확인할 원인 세 가지를 적어라.

<details>
<summary>예시 해설과 채점 기준</summary>

문의 ID와 메타데이터를 유지하고 중복·짧은 무의미 문의·언어와 길이 분포를 확인한다. 한국어와 해당 분야의 유사성을 적절히 표현하는 임베딩을 선택하고 작은 표본에서 검토한다. 군집화용 차원 축소와 시각화용 축소를 분리하며, 최소 군집 규모를 새 문제의 예상 규모와 함께 조정한다. 미배정 문서도 검토하여 새로운 문제를 무조건 버리지 않는다.

군집별 키워드와 대표 문서, 무작위 표본, 경계 사례를 읽는다. 키워드는 분야 용어와 동의어·중복을 고려해 개선하고, 생성 이름은 대표 문서와 키워드에 근거하도록 만든다. 기존 범주와 다르다고 오류로 보지 않고 실제 새로운 유형인지 확인한다.

원인 후보에는 임베딩의 한국어/도메인 부적합, 문서 잘림·중복·행 정렬 오류, 과도한 차원 축소, 너무 큰 최소 군집 규모, 불용어 중심 표현, 대표 문서에 편향된 생성 이름 등이 있다.

**6점:** 데이터 1점, 임베딩/공간 1점, 군집과 이상치 1점, 표현/이름 1점, 단계가 다른 원인 세 가지 1점, 실제 문서로 검증하는 절차 1점. 특정 모델 이름을 외웠는지로 채점하지 않는다.

</details>

## 16. 응용 설계: 예쁜 이름인데 서로 모순되는 문서

같은 토픽 안에 약물 부작용과 병원 예약 오류 문서가 섞여 있다. 생성 모델이 “의료 서비스 경험”이라는 읽기 좋은 이름을 붙였다. 팀원은 문제가 해결되었다고 말한다. 어떤 추가 확인을 제안할 것인가?

<details>
<summary>예시 해설과 채점 기준</summary>

목적에 따라 넓은 의료 서비스 토픽이 적절할 수도 있지만, 부작용 탐지나 예약 개선이 목적이라면 중요한 차이를 숨기는 지나치게 큰 묶음이다. 먼저 원하는 분석 단위를 합의하고 실제 문서 표본을 비교한다. 입력 표현과 차원 축소·군집 설정을 점검하고 필요하면 하위 토픽을 구분한다. 이름을 바꾸는 것과 문서 구성을 바꾸는 것을 분리해 평가한다.

대표 문서만 보고 이름을 지었다면 선택되지 않은 하위 주제가 빠졌는지도 확인한다. 해결 여부는 이름의 유창성이 아니라 사용 목적에 필요한 구조가 드러나는지로 판단한다.

**5점:** 분석 목적과 추상도 1점, 구성/설명 구분 1점, 문서 표본 확인 1점, 앞 단계 검토 1점, 대표성 편향 1점.

</details>

## 17. 응용 설계: 미배정 비율을 0으로 만들라는 요청

책의 예처럼 미배정 비율이 약 32%다. “모든 문서에 이름이 있어야 하니 미배정을 0으로 만들어라”는 요청을 받았다. 가능한 접근 두 가지와 비교할 품질 기준을 제시하라.

<details>
<summary>예시 해설과 채점 기준</summary>

k-means처럼 모든 문서를 배정하는 군집법으로 바꾸거나, 기존 토픽에 대한 유사성 등으로 미배정 문서를 재배정하는 후속 절차를 고려할 수 있다. 다만 미배정 수가 줄었다는 이유만으로 개선이라고 판단하지 않는다. 재배정 문서와 해당 토픽의 일치, 작은 신규 주제가 기존 주제에 묻히는지, 애매함을 기록할 수 있는지, 실제 사용 목적에 맞는지를 평가한다.

미배정 원인도 분석한다. 독특한 문서인지, 텍스트 품질 문제인지, 표현 공간/설정 문제인지에 따라 대응이 다르다. 단순히 모든 -1을 토픽 0으로 바꾸는 것은 타당한 기준이 아니다.

**5점:** 두 접근 각 1점, 실제 품질 기준 1점, 미배정 원인 분석 1점, 강제 배정의 절충 1점.

</details>

## 18. 검증 범위 말하기

`lab.py --check`가 PASS했고 시각화도 작동했다. “실제 arXiv 데이터에서 BERTopic과 생성 모델의 품질까지 검증했다”고 보고해도 되는가? 정확한 완료 보고를 두 문장으로 써라.

<details>
<summary>예시 해설과 채점 기준</summary>

보고하면 안 된다. 예시 답: “가상 문서·좌표를 사용하는 표준 Python 실습에서 DBSCAN, c-TF-IDF, MMR의 계산과 경계 사례를 확인했다. 실제 arXiv 다운로드, 임베딩 모델, UMAP/HDBSCAN/BERTopic 및 생성 모델 실행과 품질 평가는 수행하지 않았다.”

학습용 시뮬레이션도 유용한 실제 계산이지만 어떤 모델을 실행했는지 구분해야 한다.

**3점:** 수행한 계산 1점, 수행하지 않은 실제 모델 1점, 과장하지 않은 설명 1점.

</details>
