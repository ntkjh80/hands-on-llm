## 이 실습에서 실제로 하는 일

Python 표준 라이브러리만으로 다음을 **실제로 계산**한다. 문장에서 두 개의 고정 특징을 추출하고, 그 위에 로지스틱 회귀를 학습한다. 같은 특징 공간에서 라벨 설명과의 코사인 유사도를 계산하고, 혼동 행렬과 지표를 구한다. 사람이 만든 가상 생성 문자열을 검증해 후처리 정책에 따른 평가 차이도 계산한다.

이 코드는 실제 문장 임베딩 모델·LLM·API를 호출하지 않는다. 데이터는 직접 쓴 짧은 교육용 문장이다. 원문 Rotten Tomatoes 성능을 재현하는 실험이 아니며, 아래 성능은 이 작은 예제에만 해당한다. GPU·API 키·추가 패키지가 필요 없다.

## 실행 방법

저장소 루트에서 실행한다.

```bash
python3 chapters/ch04/lab.py
```

장 폴더에서 실행할 때는 다음과 같다.

```bash
python3 lab.py
python3 lab.py --help
python3 lab.py --threshold 0.8
python3 lab.py --epochs 20
```

[lab-output.txt](lab-output.txt)는 기본 명령을 실행해 저장한 실제 출력이다. 기본 설정은 800회 경사하강, 학습률 0.4, L2 계수 0.02, 분류 임계값 0.5다. 데이터와 가중치 초기값이 고정이고 난수를 사용하지 않는다. 운영체제에 따라 마지막 부동소수점 자릿수는 달라질 수 있지만 핵심 해석은 같다.

## 단계 1: 특징 추출기를 관찰한다

`features`는 정해진 긍정 단어와 부정 단어를 세고, 감성 단어 전체 개수로 나눠 두 숫자를 만든다. 좌표 순서는 `(긍정 비율, 부정 비율)`이다. 사전에 있는 감성 단어가 없으면 `(0,0)`을 반환한다.

| 문장 | 특징 | 관찰할 점 |
|---|---|---|
| `great fun film` | `(1,0)` | 긍정 단어만 발견 |
| `terrible dull film` | `(0,1)` | 부정 단어만 발견 |
| `not good` | `(1,0)` | `not`이 버려져 부정 의미를 잃음 |
| `good but boring` | `(.5,.5)` | 단어 순서가 버려짐 |
| `boring but good` | `(.5,.5)` | 앞 문장과 같은 표현 |
| `a masterpiece` | `(0,0)` | 사전에 없는 의미는 표현하지 못함 |

**먼저 생각할 질문:** 같은 벡터를 가진 두 문서의 정답이 다르다면, 그 벡터만 보는 결정적 분류기가 둘을 모두 맞힐 수 있을까?

**해설:** 없다. 같은 입력에는 같은 예측을 내기 때문이다. 더 큰 가중치나 더 많은 학습 반복만으로 잃어버린 입력 정보를 복원할 수 없다. 실제 언어 모델의 문맥 임베딩은 이 장난감 특징보다 훨씬 풍부하지만, “표현이 무엇을 보존하는가”는 실제 모델에서도 중요한 질문이다.

## 단계 2: 작은 분류기를 학습한다

`train_logistic`는 특징을 한 번 만든 뒤, `w·x+b`와 시그모이드로 긍정 점수를 계산한다. 정답과의 이진 교차 엔트로피에 가중치 L2 벌점을 더한 목적함수를 줄인다. 편향은 L2 항에 포함하지 않는다.

```text
z = w₀x₀ + w₁x₁ + b
p = sigmoid(z)
가중치 기울기 = 문서 평균[(p-y)x] + L2 계수 × w
편향 기울기 = 문서 평균[p-y]
새 가중치 = 이전 가중치 - 학습률 × 기울기
```

기본 실행에서 손실은 0.693147에서 약 0.285866으로 줄고, 가중치는 약 `[2.17875, -2.17875]`, 편향은 약 0이 된다. 긍정 좌표가 커지면 점수를 올리고, 부정 좌표가 커지면 내리는 규칙을 학습한 것이다. 이 수치는 코드의 교육용 데이터와 설정에서 실제 계산한 값이다.

**관찰 질문:** loss가 0이 되지 않는 이유를 하나 이상 찾아보자.

**해설:** 같은 특징 `(.5,.5)`에 서로 다른 라벨을 부여한 문장 쌍이 학습 데이터에 있다. 이 표현만으로 두 예시를 구분할 수 없다. 또한 L2 벌점이 가중치 크기를 제한한다. 손실에 벌점이 포함되어 있으므로 단순 오분류 개수와 같지 않다.

학습 14문장과 관찰용 10문장은 **일반화 성능 추정용 독립 분할이 아니다.** 충돌 쌍 일부가 양쪽에 의도적으로 들어 있다. 목적은 표현의 한계와 결정 규칙의 동작을 드러내는 것이다. 실제 모델 비교에서는 중복 없는 학습·검증·시험 분할을 따로 만들어야 한다.

## 단계 3: 라벨 설명과 코사인으로 분류한다

부정 설명은 `bad boring`, 긍정 설명은 `good enjoyable`로 설정했다. 같은 특징 추출기를 적용하면 각각 `(0,1)`, `(1,0)`이 된다. 문서 벡터와 두 라벨 벡터의 코사인 유사도를 계산해 큰 쪽을 고른다. 동점이면 클래스 0을 선택한다는 정책을 코드에 명시했다.

이 과정에는 과제 예제를 이용한 분류기 학습이 없다. 그러나 특징 사전은 사람이 정했고, 설명 문구도 사람이 골랐다. 따라서 실제 사전학습 임베딩을 쓰는 제로샷 모델과 성능을 비교하면 안 된다. 이 실습은 “라벨 설명도 같은 공간에 넣어 비교한다”는 계산 형태를 이해하기 위한 것이다.

기본 결과에서 지도학습과 코사인 방식은 모두 accuracy .600, macro/weighted F1 .583을 얻는다. **같은 점수지만 혼동 행렬은 다르다.** 지도학습은 `[[2,3],[1,4]]`, 코사인은 `[[4,1],[3,2]]`다. 지도학습의 `p≥.5`는 경계에서 긍정을 택하고 코사인은 동점에서 부정을 택하기 때문이다. 한 점수만 보면 놓치는 차이다.

**변경 실험:** `--threshold 0.8`을 실행하고 0.5 경계였던 문서가 어디로 이동하는지 보자. 원문 모델의 임계값을 조정한 실험이 아니라 이 장난감 분류기의 결정을 바꾸는 실험이다.

## 단계 4: 지표를 직접 검산한다

코드는 `TP=3, FP=1, FN=2, TN=4`인 정답·예측 목록을 구성한다. 혼동 행렬의 행은 실제 라벨, 열은 예측 라벨이며 배열 순서는 `[[TN,FP],[FN,TP]]`다. 결과는 다음과 같다.

| 항목 | 실제 계산값 |
|---|---:|
| 긍정 precision | .750 |
| 긍정 recall | .600 |
| 긍정 F1 | .667 |
| 부정 F1 | .727 |
| accuracy | .700 |
| macro F1 | .697 |
| weighted F1 | .697 |

코드는 긍정 F1이 `2/3`과 같은지, 벡터를 양수 배로 늘려도 코사인이 유지되는지 검산한다. 두 검산은 수학적 기대와 구현 결과의 일치 확인이다.

다음 출력은 부정 90개·긍정 10개를 전부 부정으로 예측한 경우다. accuracy .900, macro F1 .474, weighted F1 .853으로 벌어진다. 긍정 recall은 0이다. “weighted가 두 클래스를 공평하게 대한다”는 문장을 왜 일반화하면 안 되는지 설명해 보자. 이 실습은 분모가 0인 지표를 0으로 정의해 표시한다.

## 단계 5: 생성 출력의 형식을 검증한다

`parse_generated_label`은 공백을 제거하고 소문자로 바꾼 뒤 `negative`, `positive`, `0`, `1`만 허용한다. `mixed`, `negative.`, `2`는 `None`으로 보류한다. 실제 모델이 아니라 사람이 만든 테스트 문자열 8개를 사용한다.

원문의 간단한 `negative가 아니면 1` 규칙을 그대로 확대하면 `mixed`도 긍정이 된다. 형식 오류를 의미 판단으로 몰래 바꾼 것이다. 반면 허용 집합 검사에서는 8개 중 5개만 유효하고, 이 5개는 모두 맞는다. 유효 응답만의 accuracy는 1.000이지만 coverage는 5/8=.625, 전체 요청 중 올바른 자동 처리 비율도 .625다.

**변경 실험:** 마침표 하나를 허용하도록 정책을 바꾸고 어떤 문자열이 새로 유효해지는지 생각해 보자. 임의의 문장을 부분 문자열 검색으로 처리하는 것과, 명시적으로 허용한 끝 마침표를 제거하는 것은 다르다. 정책을 바꾼다면 규칙과 평가 분모를 함께 기록해야 한다.

## 원문 실제 모델 실습으로 확장하기

아래는 **미실행 확장 절차**다. 원문의 실제 신경망·GPU·API 실험은 이 자료 작성 과정에서 실행하지 않았다. 모델 다운로드, 패키지 호환성, 이용 조건은 사용 환경에서 별도로 확인해야 한다.

1. `rotten_tomatoes`를 불러오고 train/validation/test의 행 수와 라벨 매핑을 확인한다. 문서 ID를 유지하고 중복을 점검한다.
2. TF-IDF와 작은 분류기를 기준선으로 만든다. validation으로 설정을 정하고 test 평가를 남겨 둔다.
3. 원문 감성 RoBERTa 체크포인트를 불러오고 반환 라벨 이름을 확인한다. 부정·중립·긍정을 이진 과제로 변환하는 규칙을 명시한다.
4. MPNet 문장 임베딩을 만들어 train `(8530,768)`, test `(1066,768)`이라는 원문 형태와 대응을 확인한다. 실제 사용하는 버전에서 차원과 출력 구조를 읽어 확인한다.
5. 같은 임베딩 위에 로지스틱 회귀를 학습하고, 별도로 두 라벨 설명을 임베딩해 코사인 분류를 수행한다. 설명 문구 선택은 validation에서 한다.
6. Flan-T5를 불러와 분류 지시를 붙인다. 출력은 허용 집합으로 검사하고 무효 비율을 별도 보고한다.
7. API 비교를 추가한다면 현재 제공 모델·공식 API 형식·가격·계정 조건을 먼저 확인한다. 키를 코드나 Git 저장소에 넣지 않고 환경 변수 등으로 관리한다. 호출 예산과 재시도 상한을 정한다.
8. 모든 방법에 같은 test 분할과 클래스별 지표를 적용한다. 학습 라벨 사용량, 출력 실패, 지연·비용, 원본 결과와 설정을 함께 기록한다.

원문은 `datasets`, `transformers`, `sentence-transformers`, `numpy`, `scikit-learn`, `tqdm` 등을 사용한다. 패키지 이름 목록은 책의 실행 구성을 이해하기 위한 것이며, 최신 버전끼리의 호환을 검증한 설치 명세가 아니다. 큰 모델 추론에는 GPU가 유용할 수 있고 작은 분류기의 학습은 CPU에서 가능하다. 필요한 메모리는 모델 크기·정밀도·입력 길이·배치에 따라 달라진다.
