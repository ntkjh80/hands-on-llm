## 실습의 목적과 범위

[lab.py](lab.py)는 표준 Python 라이브러리만으로 다섯 가지를 직접 계산한다. 한 head의 attention, logits에서 확률로의 변환과 샘플링, 작은 causal Transformer의 KV 캐시, 이론 캐시 메모리, RoPE의 상대 위치 성질이다. 별도의 모델 파일·인터넷·API 키·GPU가 필요하지 않다.

작은 Transformer는 **학습되지 않은 고정 난수 파라미터**를 사용한다. 자연어를 이해하거나 좋은 문장을 생성하는 실습이 아니다. 2개 층, 2개 attention head, 모델 차원 4, head 차원 2, 어휘 크기 8을 사용하며 각 토큰은 단순 ID다. 구조는 pre-RMSNorm, MHA, RoPE, residual, ReLU FFN을 결합한 교육용 모델이다. Phi-3 또는 Llama의 수치 재현이 아니다.

원문 연결: PDF 물리 페이지 121–143쪽의 순전파·선택·캐시·attention, 147–150쪽의 KV 공유, 153–156쪽의 RoPE. 아래 손계산 수치는 원문 모델의 측정 결과가 아니라 이 실습이 실제 계산한 결과다.

## 1. 실행하기

저장소의 최상위 폴더에서 실행한다.

```bash
python3 chapters/ch03/lab.py
```

해당 장 폴더 안에서는 다음과 같다.

```bash
python3 lab.py
python3 lab.py --help
```

인자를 바꿔 실험할 수도 있다.

```bash
python3 chapters/ch03/lab.py --tokens 12 --temperature 1.5 --seed 11
```

| 인자 | 기본값 | 의미 | 제한 |
|---|---:|---|---|
| `--tokens` | 8 | 비교하며 선택할 생성 토큰 수 | 1–64 |
| `--temperature` | 0.8 | 두 번째 시연의 softmax 온도 | 유한한 양수 |
| `--seed` | 7 | 무작위 가중치와 표본을 재현하는 seed | 정수 |

온도 인자는 두 번째 softmax·sampling 시연에만 적용한다. 세 번째 Transformer 생성 비교는 cache와 full의 동치를 쉽게 확인하기 위해 greedy를 쓴다. 따라서 온도만 바꿨는데 세 번째 token ID가 같다고 해서 오류는 아니다.

검증된 기본 실행 출력은 [lab-output.txt](lab-output.txt)에 저장되어 있다. 명령을 실행하지 않고 이 파일을 읽어도 계산의 흐름을 따라갈 수 있지만, 가능한 경우 직접 실행하고 자신의 결과와 비교한다. 부동소수점 표시와 난수 표본의 세부 값은 Python 환경에 따라 차이가 날 수 있으며 핵심 검증은 허용 오차 안의 수치 관계다.

## 2. 한 head의 attention 계산

첫 단계에서는 학습된 투영을 생략하고 Q·K·V 벡터 자체를 작은 숫자로 제공한다.

```text
q = [1,0]
K = [[0,1], [2,0], [1,1]]
V = [[1,0], [0,2], [2,1]]
```

`dot`은 두 벡터의 내적, `softmax`는 점수를 확률로 변환, `weighted_sum`은 value 가중합이다. 기본 결과는 다음과 같다.

```text
scaled scores: [0.0, 1.414214, 0.707107]
attention weights: [0.140029, 0.575975, 0.283995] sum=1.0
weighted value: [0.708020, 1.435946]
```

**관찰 질문:** 가장 큰 가중치는 어느 위치인가? 출력은 왜 그 위치의 value와 같지 않은가? 가중치 합이 1이어도 출력의 두 좌표 합은 왜 1이 아닌가?

답은 두 번째 위치가 가장 큰 비중을 가지지만 다른 value도 합산되기 때문이다. 확률인 것은 위치별 가중치이며, 출력은 특징 벡터이므로 좌표 합이 1일 이유가 없다. `weighted_sum` 함수에서 “토큰 ID”나 “key”가 아니라 value를 합치는지 확인하자.

**변경 실험:** 코드의 q를 `[0,0]`으로 바꾸면 모든 내적이 0이 되어 가중치가 각각 1/3이 된다. 결과는 세 value의 평균인 `[1,1]`이다. 원본 파일을 보존하려면 별도 사본에서 바꾸거나 [시각화](visuals.html)의 q 좌표를 0으로 맞춘다.

## 3. Logits와 확률, greedy와 sampling

두 번째 단계의 logits는 `[2,1,0,-1]`이다. 온도 0.8을 적용한 확률은 약 `[0.718335,0.205807,0.058965,0.016894]`다. Greedy는 최고 점수 ID인 0을 고르고, sampling은 그 확률로 20번 추출한다.

`softmax`는 최댓값을 뺀 후 지수함수를 적용한다. 모든 점수에서 같은 값을 빼도 분포가 변하지 않으므로 큰 값에 의한 overflow를 줄일 수 있다. 이 함수는 0 이하의 온도를 거부한다. Greedy를 수학적 식의 `T=0` 나눗셈으로 구현하지 않고 `argmax`로 따로 처리하는 이유를 살펴보자.

**관찰 질문:** 기본 출력에서 ID 3이 한 번도 나오지 않아도 분포가 잘못된 것인가? 아니다. 작은 유한 표본은 이론 비율과 다를 수 있다. ID 3의 확률은 0이 아니지만 20회에서 선택되지 않을 가능성이 있다.

**변경 실험:** 온도만 0.2와 2.0으로 바꾸고 확률 벡터를 비교한다. 낮은 온도에서는 가장 높은 logits에 집중하고 높은 온도에서는 분포가 완만해진다. 이 실험은 정답률이 좋아지는지 평가하지 않는다. 실제 과제에서 온도를 고르려면 과제의 기준으로 별도 평가해야 한다.

## 4. 작은 Transformer의 전체 재계산과 KV 캐시

`TinyTransformer.full(tokens)`는 주어진 토큰들의 표현을 각 층에서 모두 계산한다. `TinyTransformer.step(token, position, cache)`는 현재 새 토큰의 표현만 계산하고 각 층의 과거 K·V를 재사용한다.

한 블록의 계산은 다음 순서다.

1. 현재 입력 벡터를 RMSNorm한다. 이 실습의 학습 가능한 scale은 모두 1로 고정한다.
2. Q·K·V 투영을 계산한다.
3. Q와 K의 2차원 쌍을 해당 위치만큼 RoPE 회전한다.
4. 각 head에서 query와 허용 key의 점수를 만들고 softmax한 뒤 value를 합친다.
5. Head 결과를 이어 붙여 출력 투영하고 원래 입력에 더한다.
6. 다시 RMSNorm하고 확장 선형층, ReLU, 축소 선형층을 거쳐 residual에 더한다.
7. 두 블록을 통과한 표현을 최종 RMSNorm과 LM head로 보낸다.

`full`에서는 각 위치의 attention 대상에 `range(pos+1)`만 넣는다. 미래 위치를 제외하고 자기 위치는 포함하는 causal mask의 직접적인 구현이다. `step`에서는 캐시에 과거와 현재만 들어 있으므로 같은 허용 범위가 만들어진다.

기본 설정은 프롬프트 ID `[0,1,2]`에서 8개를 greedy 선택한다. 결과 ID는 `[4,3,2,4,3,2,4,3]`이며 의미 있는 문장을 나타내지 않는다. 핵심은 각 단계에서 full과 step의 전체 logits가 일치하는지다. 기본 실행의 최대 차이는 0이며 코드에서는 `1e-10`보다 작아야 통과하게 했다.

### 계산 횟수를 해석하기

기본 실행에서 QKV를 투영하는 **토큰 위치 수에 층 수를 곱한 값**은 full 104, cache 20이다.

```text
full = 2층 × (3+4+5+6+7+8+9+10) = 104
cache = 2층 × (최초 3 + 추가 7) = 20
```

8번째 토큰을 선택한 뒤에는 그다음 분포가 필요 없으므로 새로 선택한 마지막 토큰을 다시 모델에 넣지 않는다. 마지막 토큰까지 처리하는 다른 측정 기준을 쓰면 횟수가 하나 달라질 수 있다. 같은 작업 경계를 비교해야 한다.

이 수치는 FLOPs 전체나 실제 wall-clock 시간, GPU 가속 배율이 아니다. Cache 경로에서도 현재 query는 과거 K·V를 읽는다. 실습은 **중복 투영을 줄였다**는 것을 검산 가능한 방식으로 드러내기 위해 이 지표를 선택했다.

### 추가 검증이 의미하는 것

코드는 `[0,1,2]`의 출력과 `[0,1,2,7]`의 앞 세 위치 출력을 비교한다. 미래 토큰을 추가해도 이전 출력이 같아야 causal 구조를 지킨 것이다. 이 검증이 깨지면 마스크, 위치 처리, 시퀀스 전체를 섞는 연산 등을 의심해야 한다. 단순히 최종 greedy ID가 같다는 것보다 전체 logits를 비교하는 검증이 더 강하다. 다른 점수 벡터라도 같은 argmax를 가질 수 있기 때문이다.

## 5. KV 메모리 비교

`kv_bytes`는 다음 식을 계산한다.

```text
2 × batch × layers × length × kv_heads × head_dim × bytes_per_element
```

고정한 값은 batch=1, layers=32, length=4096, head_dim=128, bytes_per_element=2다. 이 가상 모델에서 query head는 32개로 생각하고 KV head만 32, 8, 1로 비교한다.

| 방식 | KV head | 이론 캐시 크기 |
|---|---:|---:|
| MHA | 32 | 2.0000 GiB |
| GQA | 8 | 0.5000 GiB |
| MQA | 1 | 0.0625 GiB |

GiB는 `1024³` 바이트다. 십진 GB와 단위를 혼동하지 말자. 여기에는 모델 가중치, attention 작업 버퍼, 메모리 관리 오버헤드가 없다. 실제 GPU 메모리 사용량보다 작은 수치라고 해서 계산이 틀렸다고 결론 내리면 안 된다.

**변경 실험:** 배치만 2로 늘리면 모든 값이 두 배, 길이만 두 배면 역시 두 배가 된다. Query head가 같아도 KV head가 줄면 캐시가 줄어든다는 점을 확인한다. 이 식만으로 품질이나 실행 시간을 예측하지 않는다.

## 6. RoPE의 두 가지 성질 확인

`rope`는 인접 좌표 두 개씩 회전시킨다. 예제에서는 q=`[1,2]`, k=`[3,-1]`, m=2, n=5를 쓴다. 두 차원에서는 첫 좌표 쌍의 주파수가 1이므로 각도가 위치 숫자와 같은 radian 값이다. 고차원은 좌표 쌍마다 서로 다른 주파수를 사용한다.

첫 검증은 회전 전후 q의 길이 제곱이 5로 유지되는지다. 둘째는 두 벡터를 각자 회전한 뒤 내적한 결과가 상대 위치만 사용한 계산과 같은지다.

```text
dot(R(m)q, R(n)k) = dot(q, R(n−m)k)
```

셋째는 m과 n에 모두 10을 더해도 내적이 같은지 확인한다. 기본 실행의 세 내적 값은 약 `-0.002152440181`로 일치한다. 이 실험은 RoPE가 문서 경계를 지킨다거나 무한 문맥을 처리한다는 증거가 아니다. 회전의 상대 위치 성질만 검증한다.

## 7. 원문의 학습된 모델 실습으로 확장하기

원문 GPU 실습은 이 자료 제작 과정에서 실행하지 않았다. 다음은 책의 예제를 재현할 때 관찰할 순서다. 실제 설치·호환 버전·모델 접근 조건은 실행 시 해당 모델과 라이브러리의 공식 안내를 확인한다.

1. 원문의 `microsoft/Phi-3-mini-4k-instruct`와 짝이 맞는 tokenizer를 준비한다. 모델 파일과 실행 정밀도에 맞는 메모리를 확보한다. 책의 `cuda`는 NVIDIA GPU 경로이며 CPU나 다른 장치에 그대로 적용하는 보편 설정이 아니다.
2. 모델을 평가 모드로 두고 gradient를 기록하지 않는 추론 문맥에서 짧은 입력을 실행한다. 모델 본체 출력과 LM head 출력의 shape를 기록한다.
3. 마지막 위치 logits와 softmax 확률을 구별하고, argmax 전후로 선택 ID가 같은지 확인한다. 디코딩한 문자열과 token ID를 함께 기록한다.
4. 같은 프롬프트·생성 정책·토큰 한도에서 `use_cache=True/False`를 비교한다. 종료 시점이 다르면 실제 생성 수를 기록한다. 장치 초기 실행과 워밍업, GPU 동기화가 시간 측정에 영향을 줄 수 있다.
5. 출력의 동일성, 생성 토큰 수, 시간, 메모리 사용량을 함께 기록한다. 책에 나온 4.5초·21.8초와 다르더라도 환경 차이를 먼저 확인한다.

원문에서 쓰는 `%%timeit`은 Jupyter/Colab의 셀 명령이다. 일반 `.py` 파일에 그대로 넣으면 문법 오류가 발생한다. 또한 `trust_remote_code=True`는 저장소의 추가 구현을 실행하도록 허용하는 옵션이므로 무조건 붙이는 관용구로 외우지 말고 사용하는 모델의 구현 요구 사항을 읽는다. 이 기본 실습은 원격 코드를 실행하지 않는다.

## 8. 문제를 만났을 때

| 증상 | 먼저 확인할 부분 |
|---|---|
| Cache와 full의 logits가 다름 | 현재 토큰을 두 번 넣었는지, 위치 ID를 다시 0으로 시작했는지, 층별 cache가 분리되었는지 |
| 미래 토큰을 추가했더니 앞 출력이 변함 | Causal 범위에 미래 위치가 들어갔는지 |
| Softmax 값이 overflow하거나 NaN | 최댓값을 빼는 안정화와 양수 온도 검사 |
| RoPE 내적이 이동 후 달라짐 | 양쪽에 같은 위치 이동을 적용했는지, 두 회전의 주파수가 일관적인지 |
| 같은 seed인데 표본 목록이 조금 다름 | Python 환경과 난수 사용 순서; 핵심 수치 관계는 별도로 확인 |
| GPU 사용량이 계산식보다 큼 | 가중치·작업 버퍼·할당 오버헤드를 캐시 식에 포함하지 않았음을 확인 |
