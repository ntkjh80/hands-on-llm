# 3장 복습 문제와 해설

[전체 목차](../../README.md) · [학습 노트](study.md) · [강의안](lecture.md) · [강의 대본](lecture-script.md) · [시각화](visuals.html) · [실습 안내](lab-guide.md) · [복습 문제](quiz.md)

원문 범위: *Hands-On Large Language Models* 3장, PDF 물리 페이지 116–158. 문제와 숫자는 학습을 위해 새로 구성했다. 먼저 답을 적고 해설을 열어 보자. 각 문항 5점, 총 80점이다. 용어만 맞힌 답보다 이유와 계산 경계를 설명한 답을 높게 평가한다.

## 1. 생성 루프를 설명하기 · 개념

프롬프트 토큰이 `[a,b,c]`이고 처음 선택한 토큰이 d다. 다음 토큰을 고를 때 모델이 사용하는 문맥은 무엇인가? 이때 모델 가중치를 다시 학습했다고 말할 수 있는가?

<details><summary>해설과 채점 기준</summary>

문맥은 `[a,b,c,d]`다. 이전 출력이 다음 예측의 조건이 되는 자동 회귀 구조다. 입력 문맥이 바뀌는 것이며, 일반적인 추론에서는 가중치를 갱신하지 않는다. KV 캐시를 쓰면 논리적으로 이 문맥을 사용하면서도 앞 토큰의 계산을 재사용할 수 있다.

문맥 2점, 자동 회귀 설명 1점, 추론과 학습의 구별 2점.

</details>

## 2. 텐서 모양 추적 · 손계산

배치 3, 입력 길이 7, 모델 차원 16, 어휘 크기 100이다. 임베딩 행렬, 블록 스택 출력, LM head 가중치, 전체 logits, 마지막 위치 logits의 모양을 적어라. LM head를 행벡터에 오른쪽 곱하는 표기로 쓰자.

<details><summary>해설과 채점 기준</summary>

각각 `100×16`, `3×7×16`, `16×100`, `3×7×100`, `3×100`이다. 실제 라이브러리의 선형층 가중치 저장 방향은 반대일 수 있지만 질문의 수학적 곱셈 약속에서는 위 모양이다. 모양 하나당 1점.

</details>

## 3. 확률이 아닌 출력 · 디버깅

LM head가 `[-2, 0, 3]`을 출력했다. “음수가 있으므로 모델이 망가졌다”라는 진단이 맞는가? 최고 후보만 찾으려면 softmax가 꼭 필요한가?

<details><summary>해설과 채점 기준</summary>

틀린 진단이다. 선형 head의 직접 출력은 logits이므로 음수가 가능하고 합이 1일 필요도 없다. 확률로 해석하려면 softmax를 적용한다. 최고 후보 ID만 찾으려면 바로 argmax해도 된다. Softmax가 순위를 보존하기 때문이다.

Logits 설명 2점, 확률 변환 1점, argmax와 순위 보존 2점.

</details>

## 4. Attention 가중합 · 손계산

세 위치의 attention 가중치가 `[0.2,0.3,0.5]`, value가 각각 `[1,0]`, `[0,2]`, `[2,1]`이다. 출력 벡터를 계산하고, 왜 세 번째 value 그대로가 아닌지 설명하라.

<details><summary>해설과 채점 기준</summary>

첫 좌표는 `0.2×1 + 0.3×0 + 0.5×2 = 1.2`, 둘째는 `0.2×0 + 0.3×2 + 0.5×1 = 1.1`이다. 출력은 `[1.2,1.1]`이다. 가장 큰 비중만 선택하는 argmax가 아니라 여러 value를 가중합하기 때문에 세 번째 value와 다르다. 두 좌표 계산 3점, 가중합 설명 2점.

</details>

## 5. Q·K·V의 역할 · 개념

한 attention 계산에서 Q와 K를 고정한 채 V만 바꾼다. 관련도 가중치와 출력 벡터 중 무엇이 달라질 수 있는가? W_K와 K는 무엇이 다른가?

<details><summary>해설과 채점 기준</summary>

가중치는 Q와 K의 점수로 정하므로 변하지 않는다. V를 합한 출력은 달라질 수 있다. W_K는 학습된 투영 가중치이고 K는 현재 입력에 W_K를 적용해 만든 중간 표현이다. 캐시에서 재사용하는 것은 입력별 K·V다.

가중치 1점, 출력 1점, 파라미터와 activation 구분 2점, 캐시 연결 1점.

</details>

## 6. Causal mask 고치기 · 디버깅

토큰 위치가 0,1,2,3일 때 위치 2가 key 위치 0,1,2,3을 모두 보도록 구현했다. 표준 causal self-attention에서 어떤 위치를 가려야 하는가? 위치 2 자신도 가려야 하는가?

<details><summary>해설과 채점 기준</summary>

미래 위치 3을 가려야 한다. 일반적인 causal self-attention은 자기 위치 2를 포함하므로 0,1,2가 허용된다. 미래를 보는 오류는 학습 중 정보 누출을 일으키며, 뒤에 토큰을 추가했을 때 앞 위치가 달라지는 현상으로도 드러날 수 있다.

미래 위치 판별 2점, 자기 위치 허용 1점, 결과의 영향 2점.

</details>

## 7. 병렬성과 자동 회귀 · 개념

“Transformer가 입력 토큰을 병렬로 처리하므로 답변의 미래 토큰도 모두 한 번에 정해진다.” 이 문장을 고쳐라.

<details><summary>해설과 채점 기준</summary>

이미 알려진 입력 토큰들의 연산은 행렬 단위로 병렬 처리할 수 있다. 하지만 일반적인 자동 회귀 생성에서 미래 출력은 앞서 선택한 토큰을 조건으로 하므로 순차적으로 정해진다. 한 생성 단계 내부의 병렬성은 여전히 가능하다. 학습 때는 정답 시퀀스가 주어져 여러 위치를 causal mask와 함께 처리할 수 있다는 점을 덧붙이면 좋다.

입력 병렬 2점, 출력 의존성 2점, 학습 또는 단계 내부의 구분 1점.

</details>

## 8. KV 캐시 비용 계산 · 손계산

프롬프트가 4토큰이고 앞으로 6토큰을 선택한다. 층은 3개다. 마지막 선택 이후에는 추가 순전파를 하지 않는다. 전체 재계산과 KV 캐시에서 QKV 투영 대상 위치 수를 층 수까지 포함해 계산하라. 두 수의 비율을 실제 속도 배율이라고 불러도 되는가?

<details><summary>해설과 채점 기준</summary>

전체 재계산은 `3×(4+5+6+7+8+9)=117`이다. 캐시는 `3×(4+5)=27`이다. 첫 4토큰과 이후 새로 입력하는 5토큰을 처리한다. 여섯 번째 선택 토큰은 다음 분포가 필요 없으므로 처리하지 않는다. 비율 약 4.33은 특정 계산 대상 수의 비율이며 실제 실행 시간 비율이 아니다. 다른 연산과 메모리 비용이 남는다.

각 계산 2점씩, 속도 해석 1점.

</details>

## 9. 메모리 공식 적용 · 손계산

배치 2, 층 16, 토큰 2048, KV head 4, head 차원 64, 원소당 2바이트다. K와 V를 모두 포함한 이론 캐시 크기를 MiB로 구하라. 모델 가중치도 포함한 값인가?

<details><summary>해설과 채점 기준</summary>

`2×2×16×2048×4×64×2 = 67,108,864`바이트다. `1024²`로 나누면 64 MiB다. 첫 2는 K와 V이고 두 번째 2는 배치다. 모델 가중치나 작업 버퍼는 포함하지 않는다.

공식과 대입 2점, 결과·단위 2점, 제외 항목 1점.

</details>

## 10. Head 공유의 의미 · 개념

Query head가 12개이고 KV head가 3개인 GQA를 생각하자. 균등한 그룹이라면 하나의 KV 그룹을 몇 개 query head가 공유하는가? 공유한 query들은 반드시 같은 출력을 내는가?

<details><summary>해설과 채점 기준</summary>

그룹마다 4개 query head가 공유한다. Query 벡터가 다르면 같은 K·V를 보더라도 점수와 가중합이 달라질 수 있으므로 출력이 같을 필요는 없다. GQA는 KV의 공유 정도를 바꾸며 모든 query를 하나로 합치는 것이 아니다.

그룹 계산 2점, query 차이에 따른 결과 2점, 공유 대상 구분 1점.

</details>

## 11. 효율화 선택 · 응용 설계

팀원이 “긴 문서의 모든 위치를 계속 참고하면서 attention의 중간 메모리 사용을 줄이고 싶다. 그러니 local attention이 dense attention과 정확히 같은 결과를 줄 것이다”라고 말한다. 어떤 부분이 잘못되었고 어떤 종류의 방법을 검토해야 하는가?

<details><summary>해설과 채점 기준</summary>

Local attention은 허용 위치쌍을 바꾸므로 일반적으로 dense attention과 같은 계산이 아니다. Dense attention의 수학적 목표를 유지하면서 메모리 이동·중간 저장을 줄이는 FlashAttention 계열 실행 방식을 검토할 수 있다. 다만 장치·dtype·모델 구현의 지원과 실제 병목을 확인해야 하며, 부동소수점 오차까지 완전히 같다고 보장할 수는 없다.

구조 변경 지적 2점, 적절한 범주 제안 2점, 조건·수치 정밀도 1점.

</details>

## 12. FFN 설명 수정 · 개념

“FFN은 토큰별로 동작하므로 문맥과 무관하고, 모델의 사실은 모두 FFN 한 곳에 데이터베이스처럼 저장된다.” 이 설명을 수정하라.

<details><summary>해설과 채점 기준</summary>

FFN은 직접 위치 사이를 섞지 않는 위치별 비선형 변환이지만, 입력 표현에는 앞선 attention과 층을 통해 문맥이 들어 있을 수 있다. 학습된 정보와 행동은 여러 파라미터·층에 분산되며, FFN을 사실별 독립 레코드 저장소로 단정할 수 없다. 원문의 저장·보간 비유는 이해를 위한 직관이지 일대일 매핑 주장으로 읽지 않는다.

문맥 입력 구분 2점, 분산된 파라미터 설명 2점, 비유의 한계 1점.

</details>

## 13. RMSNorm 손계산 · 손계산

학습 가능한 scale을 1, ε를 0으로 단순화하자. x=`[3,4]`의 RMS는 얼마이고 RMSNorm 결과는 무엇인가? 결과 평균은 0인가?

<details><summary>해설과 채점 기준</summary>

제곱 평균은 `(9+16)/2=12.5`, RMS는 `sqrt(12.5)≈3.5355`다. 결과는 약 `[0.8485,1.1314]`이다. 평균은 약 0.9900으로 0이 아니다. RMSNorm은 평균을 빼는 연산이 아니다. 실제 구현의 ε는 수치 안정성을 위해 사용한다.

RMS 2점, 벡터 2점, 평균 제거 여부 1점.

</details>

## 14. Packing 버그 찾기 · 응용 설계

두 문서 A와 B를 한 시퀀스에 붙였다. B의 위치 ID를 다시 0부터 시작하고 RoPE를 적용했지만, B가 A의 내용에 영향을 받는다. 이것이 반드시 RoPE 구현 버그인가? 어떤 설정을 확인할 것인가?

<details><summary>해설과 채점 기준</summary>

반드시 RoPE 버그는 아니다. 위치 ID를 다시 시작하는 것과 문서 간 attention을 차단하는 것은 별개다. B의 query가 A의 key/value를 볼 수 있는 마스크인지 확인한다. 학습 목적상 문서 격리가 필요하다면 문서별 블록 마스크 등 적절한 허용 범위와 위치 정책을 함께 사용해야 한다. 경계 토큰만 넣었다고 수학적으로 모든 교차 attention이 자동 차단되는 것도 아니다.

문제 분리 2점, 마스크 확인 2점, 목적에 맞는 경계 설계 1점.

</details>

## 15. RoPE의 상대 위치 · 손계산과 개념

두 위치가 m=3, n=8이다. 둘 다 20씩 이동하면 상대 위치는 어떻게 되는가? 동일한 q·k와 같은 주파수에서 회전 후 내적이 유지되는 이유를 설명하라. 이것이 문서 전체 출력의 완전한 이동 불변성을 보장하는가?

<details><summary>해설과 채점 기준</summary>

이동 전후 n−m은 5다. 회전 행렬의 관계로 `(R(m)q)ᵀR(n)k=qᵀR(n−m)k`이므로 해당 내적은 유지된다. 그러나 전체 모델에는 내용 벡터의 변화, 다른 문맥, 마스크, 경계와 위치 정책 등이 관련되므로 문서를 옮겨도 전체 출력이 무조건 같다고 확대할 수 없다.

상대 거리 1점, 회전 관계 2점, 전체 모델 주장 제한 2점.

</details>

## 16. 캐시 검증 계획 세우기 · 응용 설계

개발자가 KV 캐시 구현을 추가했다. “캐시를 켜도 최종 greedy token ID가 같았으니 완전히 검증했다”고 말한다. 더 강한 검증 계획을 제시하라.

<details><summary>해설과 채점 기준</summary>

동일한 가중치, 평가 설정, 입력과 위치 ID에서 여러 생성 단계의 **전체 logits**를 허용 오차로 비교한다. 서로 다른 logits도 같은 argmax를 가질 수 있으므로 ID만 비교하면 오류를 놓친다. 프롬프트 길이와 생성 길이를 바꾸고, 첫 prefill과 이후 step의 경계, 각 층 cache의 분리, 현재 토큰 중복 삽입 여부도 확인한다. 미래 토큰을 붙였을 때 기존 위치 출력이 같은지 확인하면 causal 처리가 잘 되었는지도 볼 수 있다. 속도 측정은 이 정확성 검증과 별도로 수행한다.

Logits 비교 2점, 경계·다양한 길이 1점, causal 검사 1점, 정확성과 속도 분리 1점.

</details>
