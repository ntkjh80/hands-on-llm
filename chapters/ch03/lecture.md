# 3장 강의안 — 한 토큰이 만들어지는 계산을 따라가기

[전체 목차](../../README.md) · [학습 노트](study.md) · [강의안](lecture.md) · [강의 대본](lecture-script.md) · [시각화](visuals.html) · [실습 안내](lab-guide.md) · [복습 문제](quiz.md)

원문 범위: *Hands-On Large Language Models* 3장, PDF 물리 페이지 116–158. 이 강의는 **90분** 수업을 기준으로 설계했다. 시간에는 질문, 손계산, 화면 조작, 실습이 포함된다. 대본을 읽기만 해서 90분이 된다는 뜻은 아니다. 60분으로 진행하려면 표에 표시한 축약안을 적용하고 실습 후반과 복습 문제는 과제로 돌린다.

## 수업 전 준비

교사는 [학습 노트](study.md)를 읽고 `python3 lab.py`의 결과를 먼저 확인한다. 네트워크나 GPU는 기본 수업에 필요 없다. 학습자는 2장의 토큰·임베딩 개념을 복습하고 종이와 펜을 준비한다. [visuals.html](visuals.html)을 브라우저로 열어 두면 좋다. 실습은 자신의 터미널에서 실행하거나 저장된 [실제 출력](lab-output.txt)을 보며 추적할 수 있다.

수업의 최종 산출물은 학습자가 직접 그린 **한 토큰 생성 흐름도**다. 단순히 기술 이름을 모두 적는 것이 아니라, 토큰 ID·벡터·logits·확률·선택 결과가 각각 어디에 있는지 구별해야 한다. 추가로 “캐시가 있어도 과거 K·V를 읽는다”와 “RoPE가 문서 경계 마스크를 대신하지 않는다”를 말로 설명하게 한다.

## 90분 진행표

| 시간 | 내용 | 교사의 준비·행동 | 학습자 활동 | 확인할 답 |
|---|---|---|---|---|
| 0–7분 | 사전 지식 진단 | 토큰 수와 어휘 크기를 구별하는 질문 | 예시의 n·d·V 적기 | 길이·폭·후보 수는 별개 |
| 7–17분 | 자동 회귀와 순전파 | 이메일 생성 루프를 판서 | 두 단계 생성 입력 그리기 | 이전 출력이 다음 입력 조건 |
| 17–27분 | 텐서 모양과 LM head | `[B,n,d] → [B,n,V]` 제시 | 작은 차원의 행렬 크기 계산 | LM head 출력은 logits |
| 27–42분 | Q·K·V와 attention | 세 key/value 숫자 제시 | 내적·softmax·가중합 계산 | 점수 결정과 정보 결합 구분 |
| 42–50분 | Multi-head·FFN·잔차 | 블록의 두 종류 경로 판서 | 정보가 위치 사이를 넘는 단계 찾기 | attention이 직접 문맥을 섞음 |
| 50–62분 | 병렬성·KV 캐시 | 전체 재계산과 step 결과 비교 | 실습 출력 해석, 횟수 검산 | 같은 계산 재사용, 과거 조회는 유지 |
| 62–73분 | Local·GQA·FlashAttention | 비교 카드 3개 제시 | 각 최적화의 변경 대상 분류 | 참조 범위·공유 구조·실행 방식 |
| 73–84분 | RoPE·packing | 회전과 문서 경계 도식 | 상대 위치 유지 실험 | 회전과 마스크의 역할 구분 |
| 84–90분 | 통합 점검 | 빈 흐름도 배포 | 핵심 구조 채우고 설명 | 전체 연결을 자기 언어로 서술 |

**60분 축약안:** 도입 5분, 생성과 shape 12분, attention 15분, 블록·캐시 12분, 효율화 7분, RoPE 6분, 마무리 3분. 손계산은 score 한 개와 출력 첫 좌표만 함께 계산하고, `lab.py` 전체 실행과 고급 비교 질문은 과제로 지정한다.

## 장면 1 — 먼저 잘못된 그림을 고치기

칠판에 “질문 → LLM → 답변 한 문단”을 그린다. 학습자에게 이 그림에서 생략된 반복을 넣어 달라고 한다. 정답 그림에는 “다음 토큰 점수 → 한 토큰 선택 → 입력 뒤에 추가 → 다음 순전파”가 들어간다.

**질문:** “모델이 방금 쓴 답을 다시 입력으로 받으면, 그때 가중치도 학습되나요?”

**기대 답:** 생성 문맥이 바뀌는 것이며, 일반적인 추론에서는 가중치를 갱신하지 않는다. 학습이라면 손실·역전파·옵티마이저 갱신 같은 별도 과정이 있어야 한다.

**판서 예제:** 프롬프트 토큰을 `[a,b,c]`라고 두고 첫 출력이 d이면 다음 조건이 `[a,b,c,d]`가 됨을 쓴다. 둘째 출력이 e이면 `[a,b,c,d,e]`다. 이때 실제 구현은 KV 캐시로 앞부분 연산을 재사용할 수 있다고 예고한다.

**오해 진단:** “한 문장을 생각해 놓고 토큰별로 화면에만 보여 준다”는 답이 나오면 내부 선택의 조건이 다음 단계마다 달라진다는 점을 다시 강조한다.

## 장면 2 — 모양을 먼저 쓰고 계산하기

학습자에게 `B=2, n=5, d=4, V=10`을 준다. 임베딩 행렬, 입력 표현, LM head 가중치, 전체 logits, 마지막 위치 logits의 모양을 적게 한다.

| 대상 | 정답 |
|---|---|
| 임베딩 E | `10×4` |
| 입력 표현 X | `2×5×4` |
| LM head W | `4×10` |
| 전체 logits | `2×5×10` |
| 마지막 위치 logits | `2×10` |

**질문:** “어휘가 커지면 입력 토큰의 개수도 반드시 늘어나나요?”

**기대 답:** 아니다. 어휘 크기와 시퀀스 길이는 다른 축이다. 다만 tokenizer 설계가 달라지면 같은 텍스트의 분절 결과가 달라질 수 있다. 직접적인 텐서 축의 동일성으로 말하면 안 된다.

**교사 설명:** 선형 head가 내는 값은 음수도 가능하고 합도 1이 아니다. 확률을 보려면 softmax가 필요하다. argmax만 할 때는 softmax를 생략해도 순위가 같다. 원문이 점수를 확률처럼 묘사하는 부분은 구현 수준에서 이 차이를 보완한다.

## 장면 3 — attention을 한 번 직접 계산하기

다음 값은 교육용 가상 데이터다.

```text
q = [1, 0]
k₁ = [0, 1], k₂ = [2, 0], k₃ = [1, 1]
v₁ = [1, 0], v₂ = [0, 2], v₃ = [2, 1]
```

1. 각 q·k를 계산한다: 0, 2, 1.
2. √2로 나눈다: 약 0, 1.4142, 0.7071.
3. Softmax를 적용한다: 약 0.1400, 0.5760, 0.2840.
4. 가중합 첫 좌표를 계산한다: `0.1400×1 + 0.5760×0 + 0.2840×2 ≈ 0.7080`.
5. 둘째 좌표를 계산한다: 약 1.4359.

**질문:** “2번 토큰이 가장 관련 있으니 출력은 v₂와 완전히 같나요?”

**기대 답:** 아니다. 세 value가 비중을 달리해 모두 기여한다. Argmax 선택과 weighted sum을 구별해야 한다.

[시각화](visuals.html)의 query 첫 좌표를 낮추거나 둘째 좌표를 높인다. 학습자는 어떤 key가 더 유리해질지 먼저 예측한 뒤 확인한다. 화면을 단순히 구경하지 않도록, 변경 전 “가중치가 커질 토큰”과 “출력 벡터가 이동할 방향”을 말하게 한다.

**깊이 질문:** K는 그대로 두고 V만 바꾸면 가중치가 변하는가? 답은 이 단일 attention 계산에서는 변하지 않는다는 것이다. 출력만 달라진다. Q·K가 “어디서 가져올지”, V가 “무엇을 가져올지”라는 구분을 확인하는 질문이다.

## 장면 4 — 블록 안의 경로와 여러 head

판서에는 두 화살표 종류를 쓴다. 수평 화살표는 attention에서 위치 간 정보가 전달됨을, 수직 화살표는 같은 위치가 층을 통과함을 나타낸다. FFN은 각 위치에서 같은 함수를 적용하지만 입력에는 이미 문맥이 반영될 수 있음을 말한다.

**활동:** “FFN은 문맥을 사용하지 않는다”라는 문장을 수정하게 한다. 좋은 답은 “FFN이 직접 위치 간 정보를 섞는 것은 아니지만 그 입력 표현은 문맥을 포함할 수 있다”다.

**판서:** `y=x+Attention(Norm(x))`, `z=y+FFN(Norm(y))`. Attention과 FFN을 통과한 결과를 기존 흐름에 더하는 residual을 표시한다. Norm은 확률 분포를 만드는 softmax와 다름을 한 번 더 확인한다.

**주의:** Head를 몇 개 두는 것과 층을 몇 개 쌓는 것을 같은 것으로 설명하지 않는다. Head는 한 층 안의 병렬 관계 계산이며, 층은 앞 층 결과를 받아 순서대로 변환한다.

## 장면 5 — 캐시를 “정확성”과 “비용”으로 나누어 보기

[실습 출력](lab-output.txt)의 두 결과를 보게 한다. 기본 설정에서는 전체 재계산과 캐시의 최대 logits 차이가 0이며, QKV 투영 대상 위치 수는 전체 104, 캐시 20이다. 이 수치는 학습되지 않은 2층 교육용 모델의 계산 결과다.

**손계산:** 프롬프트 3개에서 8개 토큰을 고를 때 전체 재계산은 각 층에서 `3+4+…+10=52`개 위치를 투영한다. 층이 2개이므로 104다. 캐시는 최초 3개와 이후 7개만 처리하므로 각 층 10개, 합 20이다. 마지막 선택 이후에는 다음 분포가 필요 없어 추가 계산하지 않았다는 기준을 명시한다.

**질문:** “104/20=5.2이므로 GPU에서도 5.2배 빠를까요?”

**기대 답:** 아니다. 이것은 특정 연산의 대상 위치 수이고 전체 실행 시간에는 attention 읽기·행렬 곱·메모리 이동·장치 병렬성·기타 연산이 포함된다.

**추가 확인:** 미래 토큰을 붙여도 이전 위치 logits가 바뀌지 않는다는 실습 결과를 본다. 이 causal 성질이 없으면 캐시 재사용 논리가 흔들릴 수 있음을 설명한다. 양방향 encoder에 같은 논리를 무조건 적용하지 않는다.

## 장면 6 — 효율화 기법 분류 게임

세 설명을 읽고 해당 기법을 고르게 한다.

- “이 위치에서 멀리 떨어진 많은 토큰을 직접 보지 않게 한다.” → Local/sparse attention.
- “여러 query head가 같은 key·value 표현을 참고한다.” → MQA/GQA.
- “계산할 attention의 수학적 목표를 유지하면서 GPU 메모리 이동을 줄인다.” → FlashAttention.

**설계 질문:** 길어진 대화에서 KV 메모리가 부족한데 local attention으로 먼 근거가 사라지는 것을 피하고 싶다면 무엇을 검토할 수 있을까? 좋은 답은 구조가 지원하는 GQA/MQA, 캐시의 정밀도·운영 전략 등을 조건부로 고려하되, 임의로 기존 모델의 head를 지워도 된다고 하지 않는 것이다. 이 강의의 범위를 넘어서는 운영 방법은 추가 학습으로 표시한다.

[시각화](visuals.html)에서 문맥 길이와 KV head 수를 바꾸며 이론 메모리를 확인한다. 수치가 실제 GPU 총 사용량과 같지 않다는 점을 직접 말하게 한다.

## 장면 7 — RoPE와 문서 경계를 나눠 보기

Q와 K를 서로 다른 위치만큼 회전시킨 그림을 보인다. 두 위치를 함께 같은 수만큼 이동하고 상대 거리가 유지되는지 확인한다. 단위 주파수의 2차원 그림은 고차원 RoPE 전체를 대체하지 않으며, 좌표 쌍 하나의 원리를 보여 준다.

**판서:** `(R(m)q)ᵀ(R(n)k)=qᵀR(n−m)k`.

**질문:** “두 짧은 문서를 한 시퀀스에 붙이고 두 번째 위치 번호를 0부터 다시 시작하면 첫 문서를 못 보나요?”

**기대 답:** 아니다. 위치 번호 정책과 attention 허용 마스크는 다른 것이다. 격리가 필요하면 별도의 경계 처리가 필요하다. RoPE 자체가 문서 구분 토큰의 의미를 자동으로 판단하는 장치가 아니다.

## 퇴실 과제와 채점 기준

3분 동안 다음 빈칸을 채운다.

```text
텍스트 → (         ) → 토큰 ID → (         ) → 블록 스택
블록의 문맥 결합: (         ) / 위치별 비선형 변환: (         )
최종 표현 → LM head → (         ) → 선택 전략 → 새 토큰
과거 계산 재사용: (         ) / Q·K 위치 회전: (         )
```

정답은 tokenizer, 임베딩 조회, attention, FFN, logits, KV 캐시, RoPE다. 용어만 맞으면 4점, 각 입력·출력의 의미까지 설명하면 7점, 병렬성과 순차 생성의 관계까지 설명하면 10점으로 평가한다. 추가 과제는 [복습 문제](quiz.md)의 8·11·14·16번과 [실습 안내](lab-guide.md)의 변경 실험이다.
