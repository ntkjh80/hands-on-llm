# 12장 실습 안내 작은 행렬과 확률로 미세 조정 이해하기

## 무엇을 실행하는가

[lab.py](lab.py)는 Python 표준 라이브러리만으로 LoRA 계산, 균일 양자화, 응답 마스킹, 쌍별 보상 손실, DPO 경사하강을 수행한다. GPU·모델 다운로드·API 키가 필요 없다. 이 코드는 실제 LLM을 훈련하지 않으며 생성 결과나 벤치마크 성능을 흉내 내지 않는다. 원문 12장의 모델 훈련과 연결되는 작은 원리 실험이다.

프로젝트 루트에서 실행한다.

```bash
python3 chapters/ch12/lab.py
python3 chapters/ch12/lab.py --help
python3 chapters/ch12/lab.py --rank 1 --bits 3 --beta 0.2
python3 chapters/ch12/lab.py --json
```

현재 챕터 폴더에서라면 `python3 lab.py`로 실행할 수 있다. [lab-output.txt](lab-output.txt)는 기본 인수로 실제 실행하여 저장한 결과다. 난수는 LoRA 예시에서만 seed 12를 고정하여 사용한다. 파이썬 부동소수점의 마지막 자릿수는 환경에 따라 미세하게 달라질 수 있다.

## 1. LoRA의 두 경로와 병합 결과

`lora_demo`는 4×6 기반 가중치와 rank 2의 A·B를 만든다. 원래 가중치 24개는 고정되어 남고, 변화량을 표현하는 20개가 별도로 존재한다. 이 실험은 A·B를 실제 데이터로 최적화하지 않고 이미 정해진 작은 행렬로 계산 경로의 등가성을 확인한다.

```text
분리 계산: W₀x + (α/r)B(Ax)
병합 계산: [W₀ + (α/r)BA]x
```

기본 출력의 두 경로 최대 오차는 약 `4.44e-16`이며, 부동소수점 계산 오차 범위에서 같은 결과다. 큰 행렬 예시에서는 `150,994,944`개와 rank 8 변경분 `196,608`개가 출력된다. 책의 PDF 499에서 숫자와 차원을 검산하는 데 사용하자.

**실험:** rank를 1, 2, 4로 바꾸고 파라미터 수를 적는다. 4×6에서는 각각 10, 20, 40개다. rank 4가 전체 행렬 24개보다 많다는 사실이 이상한가? LoRA가 효율적이려면 충분히 작은 rank를 골라야 한다는 뜻이다. 출력 값 자체의 차이를 모델 품질 차이라고 해석하지 않는다. 각 rank에서 가상 행렬의 난수 구성이 달라지기 때문이다.

## 2. 전역과 블록별 균일 양자화

`quantize_uniform`은 주어진 배열의 min/max 사이에 `2^bits`개 대표값을 균일하게 둔다. 각 원래 값을 가장 가까운 대표값에 대응시키고 다시 실수로 복원한다. NF4의 비균일 코드북이나 bitsandbytes 커널을 구현한 코드는 아니다.

입력은 `[-0.31,-0.12,0.08,0.27,-0.4,0.1,0.3,8.0]`이다. 전체 범위를 쓰면 마지막 8.0의 영향으로 작은 수 사이의 차이가 많이 사라질 수 있다. 처음 네 값과 뒤 네 값을 각각 처리하면 첫 블록의 작은 범위에 더 적합한 간격을 쓸 수 있다.

기본 4비트에서 전역 MSE는 `0.016025`, 블록 MSE는 약 `0.002903`이다. MSE는 원래 값과 복원 값 차이의 제곱을 평균한 값이다. 이 사례에서 블록 방식의 수치 오차가 작지만 모든 가능한 데이터에 대한 성능 보장은 아니다. 블록 스케일·메타데이터의 저장 비용은 여기서 계산하지 않는다.

**실험:** `--bits 2`, `--bits 8`로 실행한다. 저장 단계 수, 복원 값, MSE를 비교한다. 비트수가 늘면 가능한 코드 수가 지수적으로 늘지만 모델 전체 메모리에는 코드 외의 정보도 들어간다. 비트수와 실제 GPU 메모리를 그대로 등치시키지 않는다.

## 3. 응답만 손실에 포함하기

`sft_demo`는 이미 주어진 정답 토큰 확률에 손실 마스크를 적용한다. 토큰 확률을 모델에서 추론하는 코드는 아니며 손실 계산의 의미를 분리해 보여 주는 실험이다.

| 위치 | 토큰 역할 | 정답 확률 | 손실에 포함 |
|---|---|---:|---:|
| 1 | 사용자 표식 | 0.2 | 0 |
| 2 | 질문 | 0.1 | 0 |
| 3 | 어시스턴트 표식 | 0.6 | 0 |
| 4 | 응답 첫 토큰 | 0.8 | 1 |
| 5 | 응답 둘째 토큰 | 0.5 | 1 |
| 6 | 응답 종료 | 0.25 | 1 |
| 7 | 패딩 | 0.99 | 0 |

응답 확률은 `0.8×0.5×0.25=0.1`, 평균 NLL은 `0.767528`, PPL은 `2.154435`다. 마스크 없이 모든 위치를 평균하면 NLL은 `0.962212`다. 어느 숫자가 “더 좋다”보다 무엇을 평가한 숫자인지 먼저 묻는다. 서로 다른 토큰 집합을 평균했기 때문이다.

**실험:** 패딩 확률을 0.99에서 0.01로 바꿔 보자. 올바르게 마스킹된 응답 손실은 바뀌지 않아야 한다. 마스크 없는 손실은 바뀐다. 이 실험은 패딩을 잘못 학습할 때 손실 해석이 흔들리는 이유를 보여 준다.

## 4. 보상 모델 점수의 차이

`reward_demo`는 정해진 점수 쌍의 sigmoid 선호 확률과 손실을 계산한다. 보상 모델 자체를 학습하는 코드는 아니다. `[2,0]`과 `[102,100]`이 모두 차이 2를 가지므로 선호 확률 약 `0.880797`, 손실 약 `0.126928`로 같다.

**질문:** 102점의 응답이 2점의 응답보다 51배 좋은가? 이 쌍별 모델에서는 그렇게 해석할 근거가 없다. 점수의 공통 이동은 쌍별 순서를 바꾸지 않는다. 실제 보상 모델을 평가할 때도 절대 숫자의 범위보다 새로운 쌍의 선호를 얼마나 잘 맞히는지 확인한다.

## 5. DPO 목적함수와 실제 경사하강

`dpo_terms`는 학습 모델과 기준 모델의 chosen·rejected 로그확률 네 개로 손실을 계산한다. 기본 고정 예제에서 기준 `(-4,-5)`, 학습 `(-3,-5.5)`이므로 Δ=1.5, β=0.1일 때 손실은 약 `0.620957`이다.

`dpo_demo`는 질문 하나, 가능한 응답 두 개만 있는 매우 작은 정책을 최적화한다. 학습 변수는 스칼라 θ 하나이며 `P(chosen)=sigmoid(θ)`다. 기준 확률은 0.35로 고정한다. 두 응답뿐이므로 로그확률 비율 차이는 `θ−θref`로 단순해진다.

```text
손실 = softplus[-β(θ−θref)]
기울기 = β{sigmoid[β(θ−θref)]−1}
θ ← θ − learning_rate × 기울기
```

기본 실행은 40 step, 학습률 0.5, β=0.1이다. 선택된 응답의 확률은 0.35에서 약 0.5883으로, 손실은 0.6931에서 약 0.6455로 바뀐다. **단일 가상 선호 쌍의 목적함수를 최적화한 결과이며, 실제 LLM의 일반화·사실성·안전성이 향상되었다는 증거가 아니다.** 같은 선호만 반복하므로 실제 데이터의 충돌·다양성·길이 효과를 재현하지 않는다.

**실험:** β를 0.05와 0.5로 바꾸고 40 step 후 값을 비교한다. 이 특정 스칼라 최적화에서 기울기와 진행 속도가 달라진다. 그 관찰을 실제 DPO 모델에서 “β가 높을수록 무조건 좋다”라는 규칙으로 일반화하지 않는다. β와 기준 정책 제약의 의미는 [학습 노트](study.md#sec-22)에서 다시 읽자.

## 검산은 무엇을 확인했는가

코드의 assert는 네 가지 수학적 성질을 검사한다.

- 같은 LoRA 변환을 분리 계산해도 병합 계산해도 같은 값이 나온다.
- 로그확률 합에 지수를 취한 값은 정답 확률의 곱과 같다.
- 보상 점수 양쪽에 같은 상수를 더해도 쌍별 손실은 같다.
- DPO 해석적 기울기는 작은 유한차분으로 얻은 기울기와 일치한다.

이는 학습 원리의 계산 검증이다. 실제 모델이나 특정 라이브러리 구현의 정확성을 대신 검증한 것은 아니다.

## 원문 GPU 실습으로 확장하는 순서

원문 예제에는 PyTorch, Transformers, Datasets, PEFT, TRL, bitsandbytes와 모델을 처리할 수 있는 GPU 환경이 등장한다. 이 자료에서는 그 모델을 다운로드하거나 실제 SFT·DPO 훈련을 실행하지 않았다. 원문의 버전과 현재 설치 버전을 섞어 실행 가능한 코드라고 가정하지 말고, 선택한 환경에서 지원되는 인터페이스를 확인해야 한다.

1. 기반 모델·토크나이저·채팅 템플릿과 라이브러리 버전을 고정한다. 원문 모델명은 학습 노트에 기록되어 있다.
2. SFT 데이터와 검증 질문을 분리한다. 원문에서 훈련에 사용한 `test_sft` 분할을 다시 독립 테스트로 쓰지 않는다.
3. 실제 토큰화 결과를 확인한다. 역할 구분, 응답 손실 마스크, 패딩 제외, 길이 제한 후 남는 응답을 검사한다.
4. 양자화된 기반 모델을 로드하고 LoRA 학습 대상의 이름과 개수를 출력한다. 실제 메모리 사용을 측정한다.
5. 짧은 훈련으로 손실·저장·재로드·템플릿 추론을 확인한 뒤 계획한 데이터로 진행한다.
6. 기반 모델과 SFT 모델을 같은 평가 질문·생성 설정에서 비교한다.
7. 선호 쌍을 정제하고 SFT 모델을 DPO 출발점과 고정 기준으로 명확히 설정한다.
8. DPO 후 평가하고 어댑터 계보에 맞게 병합한다. 병합 전후의 생성 결과도 비교한다.

학습률·rank·epoch를 바꿀 때는 한 번에 무엇을 바꿨는지 기록한다. 학습 로그만 보지 말고 별도 평가 질문에서 어떤 실패가 줄고 늘었는지 적어야 다음 실험의 근거가 된다.
