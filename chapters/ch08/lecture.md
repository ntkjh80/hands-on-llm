## 수업 전 준비

학습자는 벡터와 코사인 유사도를 가볍게 복습한다. 교사는 이 폴더의 `visuals.html`을 브라우저로 열고 `python3 lab.py`가 실행되는지 확인한다. 기본 실습은 Python 표준 라이브러리만 사용하며 외부 계정·GPU·모델 다운로드가 필요 없다. 실습 문서의 제품·영화·수치는 모두 교육용 가상 자료다.

판서는 세 칸을 유지한다. 왼쪽은 **자료와 질의**, 가운데는 **계산과 선택**, 오른쪽은 **결과와 검증**이다. 새로운 구성 요소가 나오면 어느 칸에 속하는지 표시한다. 학생이 “모델이 찾았다”라고 말하면 어떤 입력을 어떤 계산에 넣어 무엇을 얻었는지 한 단계 더 구체적으로 설명하게 한다.

## 0–8분 도입: 문장을 잘 만들면 질문에 잘 답하는가

**판서**: `질문: 해외 판매일?` → `문서 A: 국내 판매는 4월` / `문서 B: 해외 판매는 미정` → `답: 전 세계 4월 판매`.

교사는 학생에게 답이 왜 틀렸는지 묻는다. 기대 답은 “국내와 해외라는 조건을 구분하지 않고 확장했다”다. “문서가 부족하다”라고만 답하면 B에 미정이라는 근거가 이미 있음을 지적한다. 이 예는 검색 성공과 생성 성공이 다름을 보여준다.

이어서 같은 문서에서 답을 직접 찾는 것, 후보의 순서를 바꾸는 것, 답 문장을 쓰는 것을 각각 밀집 검색·재순위화·RAG의 위치와 연결한다. 검색이 반드시 벡터 검색일 필요는 없다는 점도 짧게 말한다.

**활동 2분**: 학생이 아는 검색 서비스의 화면을 떠올려 “결과 목록”, “요약 답”, “출처”를 분리해 적는다. 특정 서비스가 지금 어떤 내부 모델을 사용하는지 추측하게 하지 않는다. 보이는 입출력만으로 분류한다.

**통과 질문**: “RAG에 생성기가 빠지면 무엇이 남는가?” 기대 답은 검색 시스템 또는 근거 조회 단계다.

## 8–22분 밀집 검색과 BM25

**판서 자료**:

```text
질문 q = (1, 0)
문서 A = (0.8, 0.6)
문서 B = (0, 1)
코사인: A=0.8, B=0
제곱 L2: A=0.4, B=2
```

학생이 먼저 순서를 예측하고 계산한다. 벡터가 모두 단위 길이이므로 `L2² = 2 − 2cos`가 성립함을 보여준다. 임계값 방향은 유사도 `이상`, 거리 `이하`라고 색을 달리하지 말고 텍스트로 명확히 쓴다.

원문 영화 예제에서 질문의 “정확함”과 문서의 “과학적 정확성을 칭찬함”이 다른 단어로 표현될 수 있음을 설명한다. BM25는 질의 단어 빈도·희귀도·길이를 사용한다. 밀집 검색이 다른 표현을 연결하는 장점과 정확한 코드 검색에서 어휘 검색이 가지는 장점을 함께 적는다.

**시각 실험 3분**: [시각화](visuals.html)의 첫 패널에서 질의 좌표를 이동한다. top-k를 키운 뒤 임계값을 높인다. 기대 관찰은 “top-k는 최대 결과 수, 거리 임계값은 허용 영역이며 서로 다른 선택”이다. 모든 점이 교재 설명용 좌표임을 확인한다.

**오개념 대응**: “유사도 0.8이면 정답 확률 80%”라고 말하면 코사인의 기하학적 정의로 되돌아간다. 확률로 쓰려면 별도 보정과 평가가 필요하다고 설명한다.

**통과 질문**: “문서 벡터와 질의 벡터의 차원이 같으면 다른 모델을 섞어도 되는가?” 기대 답은 “아니다. 같은 좌표계라는 보장이 없다”다.

## 22–33분 청킹과 색인

**활동용 원문**:

> 제품 아우로라는 2030년 4월 국내 출시된다. 해외 출시는 인증 완료 후 결정한다. 보증 기간은 국내 구매일로부터 2년이다. 단, 소모품에는 별도 기준을 적용한다.

학생 둘이 각각 한 문장 청킹과 두 문장 겹침 청킹을 만든다. “해외에서도 4월 구매 가능한가?”, “모든 부품의 보증은 2년인가?”를 던지고 어떤 청크가 필요한지 표시하게 한다. 정답은 유일한 길이가 아니라 조건 보존과 비용의 설명에 있다.

**판서 비교**: 문서 앞부분만 벡터화 / 청크 평균 벡터 / 청크별 벡터. 각 방법 옆에 `누락`, `압축`, `세부 검색과 저장량`을 적는다. 문서 제목을 붙일 때 대상 식별이 쉬워지지만 중복도 증가함을 설명한다.

색인은 벡터를 빠르게 찾는 구조이며 벡터 DB는 저장·갱신·필터 등 운영 기능을 포함할 수 있다고 설명한다. FAISS라는 이름을 ANN과 동의어로 쓰지 않는다. 원문의 `IndexFlatL2`는 정확 검색이라는 코드 읽기 포인트를 준다.

**통과 질문**: “overlap을 무조건 크게 하면 좋은가?” 기대 답은 경계 문맥은 보존되지만 중복·비용·다양성 문제를 만든다는 것이다.

## 33–45분 재순위화

**카드 활동**: 전체 정답이 A와 D인데 1차 후보가 `[B, A, C]`라고 제시한다. “최고의 재순위화 모델이 얻을 수 있는 정답 문서는 몇 개인가?”를 묻는다. 정답은 A 하나다. D는 후보 밖이므로 순서 변경으로 가져올 수 없다.

이어 후보를 `[B, A, C, D]`로 늘리고 상위 2개를 고르게 한다. 후보 수를 늘릴 때 정확도뿐 아니라 계산 비용이 늘어남을 연결한다. 후보 수 K와 최종 결과 수 k를 서로 다른 글자로 쓴다.

**판서**: `bi-encoder: f(q), f(d) → similarity` / `cross-encoder: f(q,d) → relevance`. 문서 임베딩을 미리 저장할 수 있는 쪽을 학생이 고르게 한다. 교사는 cross-encoder를 배치로 계산해도 각 질문-문서 쌍은 독립 평가라는 원문 설명을 보탠다.

**실습 출력 읽기**: `lab.py`의 Q1을 본다. 수작업 특징 벡터는 D2·D8을 앞에 놓지만 RRF는 다른 순위를 낸다. “하이브리드를 붙였으니 무조건 낫다”라는 주장을 반박하게 한다. 규칙 재순위화는 신경망이 아니라 공개된 규칙이라는 점을 강조한다.

## 45–58분 AP와 MAP 손계산

**배부 문제**:

- Q1의 전체 정답 `{A,D}`, 반환 `[A,C,D]`.
- Q2의 전체 정답 `{B}`, 반환 `[C,D,B]`.
- Q3의 전체 정답 `{A,D}`, 반환 `[A,C,F]`.

학생은 각 위치 P@i와 AP 기여를 두 줄로 쓴다. Q1은 `(1 + 2/3)/2 = 5/6`, Q2는 `1/3`, Q3은 `1/2`다. Q3에서 분모를 1로 썼다면 미검색 정답 D를 빨간색 대신 문구 `놓친 정답도 분모에 남음`으로 표시한다.

Q1과 Q2의 MAP는 `7/12 ≈ 0.5833`이다. 질문을 연결해 긴 순위 하나로 만들지 않도록 확인한다. 원문의 그림에서 0.3과 0.8은 반올림 표현임을 알려준다.

**시각 실험 3분**: 순위 패널의 각 위치를 관련/무관으로 바꾸고 전체 관련 수 R을 3으로 늘린다. 같은 반환 목록인데 R이 커지면 AP가 낮아지는 이유를 설명하게 한다.

**확장 질문**: “답이 없는 질의 R=0은 AP를 어떻게 계산할까?” 이 강의는 MAP에서 제외하고 무응답 동작을 별도로 평가한다고 명시한다. 다른 정책을 쓰더라도 문서화해야 한다.

## 58–71분 RAG 구성과 원문 코드 읽기

**판서 흐름**: 질문 → 검색 문서 → `{context}` → 생성 모델 → 답변 → 문장별 출처.

관리형 예제는 문서 목록과 질문을 API에 전달하고 응답의 인용 span과 문서 ID를 받는다. 로컬 예제는 생성 모델, 임베딩 모델, FAISS, 프롬프트, RetrievalQA를 각각 연결한다. 생성 모델이 임베딩 모델과 다른 역할임을 두 번 확인한다.

**코드 독해 질문**:

1. `embeds.shape=(15,4096)`에서 문서 수와 차원은 무엇인가?
2. `input_type`의 문서·질의 역할은 왜 구분하는가?
3. `chain_type='stuff'`는 문서를 어떻게 전달하는가?
4. 모델 파일 이름의 `fp16`과 GGUF 형식은 같은 개념인가?
5. 설명은 BGE, 코드 이름은 GTE일 때 어떤 모델이 실제 요청되는가?

기대 답은 각각 15·4096, 검색 역할 차이, 문맥에 함께 넣기, 정밀도와 파일 형식의 구분, 실제 코드의 식별자 확인이다. API 현재 동작을 검증하지 않았으므로 오늘 수업은 구조 독해와 표준 Python 실습에 한정한다.

**활동 3분**: 국내 출시·해외 미정 문서를 프롬프트에 넣고 답변 규칙을 작성한다. 근거 부족 처리, 각 사실 주장에 자료 ID 부여를 넣게 한다. “출처 번호만 있으면 검증 완료인가?”의 기대 답은 아니다.

## 71–80분 고급 RAG 분류

| 상황 카드 | 주된 기법 | 이유 |
|---|---|---|
| “아까 그 제품 지원 종료일은?” | 재작성 | 앞 대화의 대상을 질의에 포함 |
| 두 제품의 보증 조건 비교 | 다중 질의 | 두 검색을 처음부터 만들 수 있음 |
| 판매량 상위 제품을 찾은 뒤 각 보증 확인 | 다단계 | 첫 결과가 다음 질의를 결정 |
| 고객 문의는 CRM, 직원 휴가는 인사 문서 | 라우팅 | 자료원 선택 |
| 중간 결과에 따라 추가 검색 또는 종료 결정 | 에이전트형 | 실행 흐름을 동적으로 판단 |

학생이 한 상황을 다른 방식으로도 풀 수 있다고 하면 이유를 듣는다. 기법 이름 맞히기가 목적이 아니라 의존관계를 설명하는 것이 목적이다. 고급 구조의 단계 증가가 오류 전파와 비용을 늘릴 수 있다는 점을 함께 평가한다.

## 80–90분 RAG 평가와 종료 과제

**평가 카드**: “국내 출시는 4월이며 [D1], 해외도 4월 출시된다 [D2]. 제품 색상은 세 가지다.” D1은 국내 출시를, D2는 해외 미정을 말한다고 가정한다.

학생은 문장을 원자적 주장 세 개로 나누고, 각 주장에 대해 질문 관련성·문맥 지원·인용 지원을 체크한다. 유창한 문장이 잘못된 주장을 감출 수 있음을 확인한다. 인용 재현율은 주장 기준, 정밀도는 인용 연결 기준임을 다시 말한다.

**종료 과제**: 다음 세 문장을 자신의 말로 완성한다.

1. “재순위화가 복구할 수 없는 오류는 ______이다.”
2. “AP 계산에서 전체 정답 수를 분모로 두는 이유는 ______이다.”
3. “검색 정답 문서를 넣었는데 최종 답이 틀리면 먼저 ______를 확인한다.”

기대 답은 후보 누락, 놓친 정답도 반영, 실제 문맥과 답변의 주장·출처 연결이다. 세 문장을 설명할 수 있으면 이번 장의 핵심 연결을 이해한 것이다.

## 60분으로 줄일 때

원문 코드의 세부 독해와 고급 RAG 분류를 사전 읽기로 옮긴다. 밀집 검색·청킹 20분, 재순위화 10분, AP·MAP 10분, RAG와 인용 평가 15분, 종료 과제 5분으로 진행한다. 계산 활동과 근거 검증 활동은 줄이지 않는다. 이 두 활동이 용어 암기와 실제 이해를 구분해 준다.

## 과제와 채점

[복습 문제](quiz.md)에서 1–8번은 개념·계산 확인, 9–16번은 디버깅·설계 과제로 사용한다. 실습 보고서에는 “변경한 설정, 예상한 변화, 실제 출력, 예상과 달랐던 이유” 네 항목을 적게 한다. 높은 MAP만 제출하면 불충분하다. 어떤 가상 데이터와 어떤 수작업 규칙에서 얻은 수치인지 밝혀야 한다.
