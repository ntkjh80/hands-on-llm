# 1장 복습 문제와 해설

원문 범위: *Hands-On Large Language Models*, 1장, PDF 물리 페이지 23–66쪽. 먼저 답을 적고 해설을 여세요. 각 문항의 채점 기준을 이용해 “용어를 안다”와 “이유를 설명할 수 있다”를 구분합니다. 총점은 48점입니다. 40점 이상이면 다음 장으로 진행하고, 부족한 주제는 연결된 학습 노트 절을 다시 읽어 보세요.

## 1. 언어 AI와 생성형 AI의 범위 · 개념 · 2점

새 문장을 생성하지 않고 질문과 관련된 문서 세 개만 반환하는 시스템도 언어 AI인가요? 이유와 출력 형태를 설명하세요.

<details><summary>해설과 채점 기준</summary>

그렇습니다. 언어 AI는 언어의 처리·표현·검색·분류·생성 등을 포함하는 넓은 범위입니다. 이 시스템의 출력은 새로 작성한 답변이 아니라 문서 또는 문서 순위입니다. 1점은 언어 AI에 포함된다는 판단, 1점은 생성과 검색의 출력 차이 설명에 줍니다. 관련 절: [언어 AI](study.md#language-ai).

</details>

## 2. BoW를 직접 만들기 · 손계산 · 3점

어휘 순서가 `[사과, 배, 먹다]`일 때 A=`사과 배 먹다`, B=`배 사과 먹다`, C=`사과 사과 먹다`의 BoW를 적으세요. 어떤 정보가 사라지나요?

<details><summary>해설과 채점 기준</summary>

A와 B는 `[1,1,1]`, C는 `[2,0,1]`입니다. 단어가 나타난 순서가 사라집니다. A/B 두 벡터를 맞히면 1점, C를 맞히면 1점, 순서 정보 손실을 설명하면 1점입니다. 이 예에서는 의미 차이가 크지 않을 수 있지만, 표현 자체는 어떤 경우든 단어 순열을 구별하지 못합니다. 주어와 목적어가 바뀌는 사례가 더 강한 반례입니다. 관련 절: [BoW](study.md#bow).

</details>

## 3. 코사인 유사도 계산 · 손계산 · 3점

u=(1,0), v=(0.8,0.6), w=(0,0)입니다. u와 v의 코사인 유사도를 계산하고, u와 w에서는 무엇이 달라지는지 설명하세요.

<details><summary>해설과 채점 기준</summary>

u와 v의 길이는 모두 1이고 내적은 0.8이므로 유사도는 0.8입니다. w는 길이가 0이라 통상적인 코사인 공식의 분모가 0이 되어 정의되지 않습니다. 1점은 내적, 1점은 길이와 최종 결과, 1점은 영벡터 예외 설명입니다. 영벡터 유사도를 임의로 0으로 반환하는 구현은 응용상의 약속이며 수학적 공식의 직접 결과와 구분해야 합니다. 관련 절: [밀집 임베딩](study.md#dense).

</details>

## 4. 임베딩 좌표의 이름 · 개념 · 2점

“임베딩 첫 차원은 인간성, 둘째 차원은 감정이며, 모든 모델에서 같은 의미다”라는 설명의 문제를 지적하세요.

<details><summary>해설과 채점 기준</summary>

일반적인 학습 임베딩의 개별 차원에 그러한 고정된 인간 해석이 보장되지 않습니다. 의미 관계가 여러 차원에 분산될 수 있으며 모델마다 좌표계와 목표가 다를 수 있습니다. 차원 해석의 한계를 설명하면 1점, 서로 다른 모델 간 좌표 의미를 동일시할 수 없다고 하면 1점입니다. 교육용으로 이름 붙인 축은 실제 학습 좌표라고 주장하지 않아야 합니다.

</details>

## 5. 단어 벡터와 문장 벡터 · 응용 판단 · 3점

질문 한 개의 관련 문서를 찾으려는데 모델 출력이 토큰 20개 각각의 384차원 벡터입니다. “384차원 문장 벡터를 얻었다”고 바로 말해도 되나요?

<details><summary>해설과 채점 기준</summary>

아닙니다. 현재 출력은 20×384의 토큰별 표현입니다. 문장 전체의 벡터를 만들려면 어떤 풀링이나 학습된 문장 표현을 사용할지 정해야 합니다. 평균을 사용할 수는 있지만 항상 최적의 의미 검색 표현이라는 보장은 없습니다. 출력 모양 설명 1점, 집계/문장 표현 필요성 1점, 학습 목표와 평가의 필요성 1점입니다. 관련 절: [임베딩 종류](study.md#embedding-types).

</details>

## 6. 어텐션 가중합 · 손계산 · 3점

h₁=(2,0), h₂=(0,2), 가중치가 0.25와 0.75입니다. 문맥 벡터를 구하고, 가중치가 가장 큰 h₂만 그대로 선택한 결과와 비교하세요.

<details><summary>해설과 채점 기준</summary>

가중합은 `0.25(2,0)+0.75(0,2)=(0.5,1.5)`입니다. h₂만 고르면 `(0,2)`이므로 다릅니다. 어텐션은 이 예에서 여러 정보를 연속적으로 섞습니다. 좌표별 계산과 결과에 2점, 가장 높은 항만 고르는 연산과 다르다는 설명에 1점입니다. 관련 절: [RNN과 어텐션](study.md#rnn-attention).

</details>

## 7. RNN에 어텐션을 붙이면 해결되는 것 · 개념 · 2점

어텐션이 인코더의 마지막 상태 하나만 사용하는 번역 구조를 어떻게 개선하나요? RNN의 모든 순차 의존도 함께 사라지나요?

<details><summary>해설과 채점 기준</summary>

디코더가 입력의 여러 위치에 해당하는 상태를 다시 참조하고 현재 출력 단계에 맞게 가중합할 수 있어 고정된 문맥 벡터 하나에만 의존하는 병목을 완화합니다. 그러나 RNN의 상태 갱신은 이전 상태에 의존하므로 순차 구조가 그대로 남습니다. 각각 정확하게 설명하면 1점씩입니다.

</details>

## 8. 인과 마스크의 대각선 · 디버깅 · 4점

다음 토큰 예측을 학습하는 동료가 “대각선을 허용하면 정답을 볼 수 있으므로 대각선까지 전부 차단해야 한다”고 말합니다. 입력과 목표 배열을 들어 검토하세요.

<details><summary>해설과 채점 기준</summary>

입력을 `[나는, 사과를, 먹었다]`, 목표를 `[사과를, 먹었다, 종료]`로 두면 각 위치의 목표는 입력의 다음 토큰입니다. 첫 위치는 입력 “나는”을 보고 목표 “사과를”을 예측합니다. 따라서 자기 위치를 보는 것은 그 위치의 정답을 보는 것과 다릅니다. 일반적인 인과 마스크는 자기 위치와 이전 위치를 허용하고 이후 위치를 차단합니다. 입력/목표 이동 예시에 2점, 자기 위치 허용의 이유 1점, 미래 차단의 이유 1점입니다. 관련 절: [트랜스포머](study.md#transformer).

</details>

## 9. 병렬 학습과 순차 생성 · 설명 과제 · 3점

“트랜스포머는 병렬 처리가 되므로 답변의 모든 토큰을 일반적으로 한 번에 선택한다”는 문장을 바로잡으세요.

<details><summary>해설과 채점 기준</summary>

학습 때는 정답 시퀀스가 주어지므로 인과 마스크를 적용한 여러 위치의 계산을 함께 할 수 있습니다. 일반적인 자기회귀 생성에서는 앞서 선택한 토큰을 다음 조건으로 포함해야 하므로 한 단계씩 선택합니다. “병렬화”가 어떤 단계에 적용되는지 구분해야 합니다. 학습 조건 1점, 생성 의존 관계 1점, 두 설명이 모순이 아니라는 연결 1점입니다.

</details>

## 10. BERT와 GPT의 역할 · 개념 · 3점

BERT의 대표 사전 학습 목표와 GPT의 대표 사전 학습 목표를 비교하고, GPT로 분류를 할 수 있는지 설명하세요.

<details><summary>해설과 채점 기준</summary>

BERT는 양쪽 문맥을 활용해 가려진 토큰을 예측하는 마스크 언어 모델링이 대표적이고, GPT는 앞선 문맥에 조건부로 다음 토큰을 예측합니다. GPT에 라벨을 출력하게 하거나 적절히 과제에 맞추면 분류에 사용할 수 있습니다. 각각 1점씩입니다. 주요 모델 목적과 응용 과제는 서로 다른 축이며, 생성 모델 내부에도 표현 벡터가 존재합니다.

</details>

## 11. 프롬프트와 미세 조정 · 디버깅 · 3점

프로그램이 모델을 불러온 뒤 프롬프트에 예시 10개를 추가했습니다. 모델 파일은 저장하지 않았습니다. 개발자는 “이제 모델 가중치에 그 예시를 학습시켰다”고 말합니다. 무엇을 확인해야 하나요?

<details><summary>해설과 채점 기준</summary>

예시를 프롬프트에 넣는 것만으로는 일반적으로 파라미터 갱신이 일어나지 않습니다. 손실 계산, 역전파나 최적화 등 실제 학습 절차가 수행되었는지 확인해야 합니다. 현재 문맥에 조건부로 행동이 바뀌는 것과 저장된 가중치가 바뀌는 것을 구분해야 합니다. 문맥/파라미터 구분 1점, 실제 갱신 절차 확인 1점, 예시 제거 시 영향과 저장 상태의 설명 1점입니다.

</details>

## 12. 메모리 산술 · 손계산 · 3점

파라미터 38억 개를 각각 2바이트로 저장하면 가중치만 몇 GB인가요? 이 값으로 GPU의 전체 필요 VRAM을 확정할 수 있나요? GB는 십진 단위를 사용합니다.

<details><summary>해설과 채점 기준</summary>

38억×2바이트=76억 바이트=7.6GB입니다. 실행에는 캐시, 활성값, 런타임 등의 메모리가 더 필요하며 학습에는 기울기와 최적화 상태 등도 필요합니다. 계산 1점, 전체 필요량과 다름 1점, 추가 요소의 구체적 예 1점입니다. 관련 절: [자원](study.md#resources).

</details>

## 13. 문의 처리 시스템 설계 · 사고 과제 · 4점

매일 들어오는 문의를 부서에 배정하고, 비슷한 해결 사례를 찾고, 응답 초안을 작성해야 합니다. 구성 요소 세 개와 각각의 평가 기준을 제안하세요.

<details><summary>해설과 채점 기준</summary>

한 설계는 ① 표현 모델+분류기로 부서 라벨 예측, ② 문서 검색기로 유사 사례 탐색, ③ 생성 모델로 근거를 참고한 초안 작성입니다. 분류는 정답 부서와 오류 유형, 검색은 관련 문서가 상위에 나타나는지, 생성은 근거 일치·정확성·어조·완결성 등을 평가할 수 있습니다. 세 기능 구분에 2점, 기능별 평가 연결에 2점입니다. 다른 타당한 설계도 가능합니다. 큰 모델 하나로 전부 처리할 수 있다는 주장만으로는 왜 그 설계가 적합한지 설명하지 못합니다.

</details>

## 14. API와 공개 모델의 선택 · 사고 과제 · 4점

공개 자료로 일주일짜리 시제품을 만들 팀과, 외부 반출이 제한된 문서를 장기간 처리할 팀이 있습니다. 두 팀의 선택에서 확인할 항목을 제안하세요. 하나의 정답 제품을 고를 필요는 없습니다.

<details><summary>해설과 채점 기준</summary>

시제품 팀은 구현 시간, 과제 품질, 호출 비용, 서비스 이용 조건을 중심으로 API를 후보로 볼 수 있습니다. 내부 문서 팀은 데이터 경계와 운영 조건, 로컬 또는 허용된 환경의 메모리·처리량, 라이선스, 유지 관리 책임을 확인해야 합니다. 공개 모델도 API로 제공될 수 있고, 로컬 실행도 주변 소프트웨어의 데이터 흐름을 확인해야 합니다. 데이터 흐름 1점, 비용/운영 1점, 실제 품질 평가 1점, 이분법을 피한 조건부 판단 1점입니다.

</details>

## 15. 생성 파이프라인 설정 오류 · 디버깅 · 3점

`return_full_text=False`, `max_new_tokens=500`, `do_sample=False`를 설정했습니다. “모델은 프롬프트를 보지 않고, 정확히 500토큰을 쓰며, 사실 오류도 사라진다”는 설명을 수정하세요.

<details><summary>해설과 채점 기준</summary>

`return_full_text=False`는 반환 결과에서 입력을 제외하도록 하는 설정이지 입력을 모델에 주지 않는다는 뜻이 아닙니다. `max_new_tokens`는 상한이므로 종료 조건에 따라 더 일찍 멈출 수 있습니다. 원문의 기본 설정에서 표본 선택을 끄면 가장 높은 확률을 고르는 방식이지만 사실성 보장은 아닙니다. 각 오해 교정에 1점씩입니다. 관련 절: [첫 텍스트 생성](study.md#first-generation).

</details>

## 16. 작은 실습의 범위를 정직하게 설명하기 · 사고 과제 · 3점

이 장의 `lab.py`가 “오늘 날씨가 좋다”를 출력했습니다. 이것을 “우리 LLM이 한국어 의미를 이해하고 현재 날씨를 추론했다”라는 결과로 발표해도 되나요? 정확한 설명으로 바꾸세요.

<details><summary>해설과 채점 기준</summary>

안 됩니다. 이 실습은 여섯 문장에서 바로 앞 토큰 다음의 빈도를 세는 bigram 모형입니다. 고정된 말뭉치 통계에서 높은 확률 후보를 반복 선택한 결과이며, 실제 LLM이나 날씨 데이터 조회를 수행하지 않았습니다. “작은 빈도 기반 모형에서 다음 토큰 선택과 종료 루프를 확인했다”라고 설명해야 합니다. 실제 계산 범위 1점, 현대 LLM/사실 추론과의 차이 1점, 정확한 결과 문장 1점입니다.

</details>

## 점수보다 중요한 오답 기록

틀린 문제마다 “내가 혼동한 두 개념”, “반례 하나”, “다시 확인할 절”을 한 줄씩 적으세요. 예를 들어 11번을 틀렸다면 문맥 변경과 파라미터 갱신을 혼동한 것입니다. 같은 모델에 다른 프롬프트를 넣어 결과가 바뀌더라도 모델 파일을 학습한 것은 아니라는 반례를 기록하면 좋습니다.
