# 1장 실습 안내 — 세 가지 작은 계산으로 언어 모델의 흐름 익히기

이 실습은 원문 1장의 BoW(PDF 26–28쪽), 어텐션(PDF 32–42쪽), 자기회귀 생성(PDF 45–49쪽), 첫 텍스트 생성(PDF 61–64쪽)을 연결합니다. 신경망이나 실제 LLM을 실행하지 않습니다. 작은 말뭉치와 교육용 벡터를 이용해 계산을 모두 확인하는 개념 실습입니다. 외부 패키지, GPU, 인터넷, API 키가 필요 없습니다.

## 실행과 실제 결과

저장소 최상위 폴더에서 다음 명령을 실행합니다.

```bash
python3 chapters/ch01/lab.py
```

현재 챕터 폴더 안이라면 다음처럼 실행합니다.

```bash
python3 lab.py
```

옵션 설명은 `python3 lab.py --help`로 확인합니다. 기본 실행의 실제 결과는 [lab-output.txt](lab-output.txt)에 저장되어 있습니다. 변경 조건의 실행 결과도 [어텐션·표본 선택 변경](lab-variant-output.txt), [길이 상한 변경](lab-length-output.txt)에서 확인할 수 있습니다. 이 파일의 출력은 실행한 Python 프로그램의 결과이며, 실제 Phi-3가 생성한 문장이나 성능 수치가 아닙니다.

## 실험 1 — 공유 어휘와 순서 손실

`tokenize`는 공백으로 문장을 나눕니다. `bow`는 어휘 순서에 맞춰 각 단어의 출현 횟수를 반환합니다. 어휘는 세 문장에 등장하는 단어를 처음 등장한 순서대로 모아 구성합니다.

A는 “고양이 가 강아지 를 쫓는다”, B는 “강아지 가 고양이 를 쫓는다”입니다. 둘 다 `[1,1,1,1,1,0]`이 됩니다. C는 “고양이 고양이 잠잔다”로 `[2,0,0,0,0,1]`입니다. 코사인 계산은 같은 어휘 좌표계를 공유하는 벡터에 적용합니다.

실행 전에 A와 B의 유사도를 예상해 보세요. 정답은 1입니다. A와 C는 내적이 2이고 각 길이는 √5이므로 `2/(√5×√5)=0.4`입니다. 이 결과가 문장 의미의 완전한 일치를 뜻하지 않는 이유도 설명해야 합니다. A와 B에서 주어와 목적어가 바뀌었지만 BoW는 순서를 저장하지 않습니다.

**코드 관찰 질문:** 왜 `bow` 안에서 문서마다 새로운 어휘 순서를 만들지 않을까요? 두 벡터의 같은 위치가 같은 단어를 뜻해야 숫자 비교가 의미 있기 때문입니다. 왜 빈 문장의 코사인은 별도 처리가 필요할까요? 영벡터의 길이가 0이라 분모가 0이 되기 때문입니다.

**변경 실험:** 코드의 C 문장에서 고양이를 한 번 더 반복하세요. 고양이 좌표가 3으로 바뀌고 코사인도 바뀝니다. 변화가 문장 의미의 중요도와 동일하다고 단정하지 말고, 빈도와 벡터 길이가 계산에 어떻게 들어가는지 확인하세요. [시각 실험 1](visuals.html)에서는 파일을 수정하지 않고 같은 실험을 할 수 있습니다.

## 실험 2 — 점수, 가중치, 가중합을 분리하기

입력 상태는 `[(1,0),(0,1),(1,1)]`이고 기본 점수는 `[1,2,3]`입니다. `softmax`는 점수의 최댓값을 빼고 지수 함수를 적용한 뒤 합으로 나눕니다. 최댓값을 빼도 비율은 유지되며 큰 지수값으로 인한 수치 문제를 줄일 수 있습니다. 이 안정화는 실습 구현의 보충 설명입니다.

기본 가중치는 약 `[0.090031,0.244728,0.665241]`이고 합은 1입니다. 문맥 벡터의 첫 좌표는 첫 번째와 세 번째 가중치의 합인 0.755272, 둘째 좌표는 두 번째와 세 번째 가중치의 합인 0.909969입니다. 원문이 설명한 “필요한 입력에 더 높은 비중을 주기”가 실제 숫자 계산으로 바뀐 것입니다.

```bash
python3 chapters/ch01/lab.py --attention-score 0
```

이 명령은 세 번째 점수를 3에서 0으로 바꿉니다. 실행 전에 세 번째 가중치가 작아지고 문맥 벡터가 두 번째 상태 `(0,1)`에 상대적으로 가까워질 것이라고 예측해 보세요. 실제로는 첫 두 점수가 그대로여도 정규화 분모가 달라져 세 가중치가 모두 바뀝니다.

**검산:** 코드에는 가중치 합이 1인지, 이 입력의 가중합이 각 좌표 0과 1 사이에 있는지 확인하는 검산이 있습니다. 이는 신경망의 성능 평가가 아니라 계산의 성질을 확인하는 것입니다. 점수에서 언어적 의미를 학습하는 과정, 쿼리·키·값 투영, 다중 헤드와 위치 정보는 이 실습에 없습니다.

## 실험 3 — 빈도 기반 bigram 모형으로 생성 루프 확인하기

말뭉치는 여섯 문장입니다. `fit_bigram`은 각 토큰 다음에 어떤 토큰이 몇 번 등장했는지 셉니다. 각 문장 끝에는 `<끝>`을 붙입니다. `next_probabilities`는 횟수를 합으로 나눠 조건부 확률을 만듭니다. 신경망 최적화나 임베딩 학습을 수행하는 함수가 아닙니다.

“오늘”은 네 번 등장하고 그 뒤에는 날씨가 세 번, 기분이 한 번 나옵니다. 따라서 다음 후보 확률은 0.75와 0.25입니다. 기본 생성은 가장 높은 확률의 후보를 선택합니다. 이후에는 날씨가 뒤의 분포에서 좋다를, 좋다 뒤에서는 종료 토큰을 고릅니다. 출력은 “오늘 날씨가 좋다”입니다.

중요한 한계는 바로 앞 토큰 하나만 조건으로 사용한다는 점입니다. 앞에 아무리 긴 문장을 넣어도 이 모형은 마지막 토큰의 통계만 봅니다. 현대 트랜스포머 LLM의 긴 문맥 처리를 모사하지 않습니다. 또한 관측된 전이만 사용하므로 보지 못한 토큰에는 분포가 없습니다. `--prompt`에 말뭉치에 없는 단어를 넣으면 오류를 명확하게 표시합니다. 그럴듯한 분포를 임의로 만들어내지 않습니다.

### 길이와 종료 조건

```bash
python3 chapters/ch01/lab.py --max-new-tokens 1
python3 chapters/ch01/lab.py --context-window 2
```

두 경우 모두 기본 입력에서는 첫 새 토큰을 선택한 뒤 길이 제한에 도달합니다. 종료 토큰을 고르기 전에도 길이 상한으로 멈출 수 있습니다. `max_new_tokens`는 새 토큰 선택 횟수의 상한이며, 문맥 창은 입력과 추가된 문장의 길이를 제한합니다. 이 모형의 공백 토큰과 종료 처리는 실제 LLM 토크나이저의 세부 동작을 대신하지 않습니다.

### 탐욕적 선택과 표본 선택

```bash
python3 chapters/ch01/lab.py --sample --seed 7
python3 chapters/ch01/lab.py --sample --seed 13
```

표본 선택은 가장 큰 확률만 고르는 대신 분포의 비율로 토큰을 뽑습니다. 같은 시드와 조건으로 이 작은 실험을 반복하면 같은 선택을 재현할 수 있습니다. 두 시드가 항상 다른 문장을 내는 것은 아닙니다. 가능한 경로가 적기 때문에 같은 결과를 뽑을 수도 있습니다. 이 실습의 표본 선택에는 온도나 top-p 같은 고급 설정을 넣지 않았습니다. 그러한 생성 제어는 6장에서 다룹니다.

## 원문의 실제 모델 실행으로 확장하기

원문은 `microsoft/Phi-3-mini-4k-instruct`의 모델과 토크나이저를 로드하고, 텍스트 생성 파이프라인에 대화 메시지를 전달합니다. 이 자료 제작에서는 모델 다운로드, NVIDIA GPU 실행, 원문의 닭 농담 생성 재현을 수행하지 않았습니다. 실행 절차를 공부할 때는 다음 순서로 확인하세요.

1. 원문 PDF 61–64쪽에서 모델 로딩과 파이프라인 구성을 읽고, [책의 공식 저장소](https://github.com/HandsOnLLM/Hands-On-Large-Language-Models)에서 해당 장의 환경을 확인합니다.
2. [공식 모델 카드](https://huggingface.co/microsoft/Phi-3-mini-4k-instruct)에서 사용하려는 구현, 라이브러리 버전, 입력 형식과 요구 조건을 확인합니다. 모델·토크나이저·코드 버전을 기록합니다.
3. 사용 가능한 장치와 메모리에 맞는 환경을 준비합니다. 책의 CUDA 설정은 NVIDIA GPU를 전제로 합니다. 책에서 말한 당시 무료 Colab 제공 조건을 현재 보장으로 해석하지 않습니다.
4. 모델과 토크나이저가 서로 대응하는지, 대화 템플릿이 적용되는지 확인합니다. `trust_remote_code`가 필요한 구현인지도 확인하고 원문의 옵션을 무조건 복사하지 않습니다.
5. 짧은 입력과 작은 새 토큰 상한으로 시작합니다. 생성 설정과 사용한 입력을 기록하고, 결과 문자열이 반환 형식의 어느 부분에 있는지 확인합니다.
6. 결과를 사실성이나 학습 능력의 증거로 과대 해석하지 말고, 먼저 입력→토큰화→모델 계산→선택→문자열 변환의 흐름을 설명합니다.

실습을 마치면 “숫자 결과가 왜 그렇게 나왔는가”를 말할 수 있어야 합니다. 단순히 오류 없이 실행됐다는 사실만으로는 학습이 끝나지 않습니다. [복습 문제](quiz.md)에서 손계산과 디버깅 문항을 풀어 보세요.
