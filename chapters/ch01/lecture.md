# 1장 강의안 — 언어를 숫자로 표현하고 생성하는 원리

이 강의의 목표는 학습자가 모델 이름을 외우는 것을 넘어, 표현·문맥·생성·학습·실행 방식의 관계를 자신의 말로 설명하게 하는 것입니다. 원문 범위는 *Hands-On Large Language Models* 1장, PDF 물리 페이지 23–66쪽입니다. 아래 80분은 설명, 학생 활동, 답변, 실습을 합친 수업 설계 시간입니다. 대본을 읽는 데 정확히 80분이 걸린다는 뜻이 아닙니다.

## 수업 준비

학습자는 Python의 문자열과 리스트를 알고 있으면 좋습니다. 강사는 [상세 노트](study.md), [교사용 대본](lecture-script.md), [시각 실험](visuals.html), [실습 코드](lab.py)를 준비합니다. 시각 실험은 파일을 브라우저에서 열면 동작하며 외부 네트워크가 필요 없습니다. 실습도 GPU와 API 키를 요구하지 않습니다. 원문의 Phi-3 실행은 별도 확장 과제로 안내하며 이 수업에서 실행했다고 가정하지 않습니다.

칠판이나 메모 공간을 세 칸으로 나눕니다. 왼쪽은 “입력과 표현”, 가운데는 “학습과 계산”, 오른쪽은 “출력과 평가”입니다. 새 용어를 소개할 때마다 어느 칸에 해당하는지 표시하세요. 학생이 토크나이저, 모델, API, 채팅 제품을 같은 층의 이름으로 혼동하지 않게 하는 장치입니다.

## 0–7분 — 하나의 문장, 여러 과제

**판서:** “배송이 이틀 늦어졌어요. 주문을 취소하고 싶습니다.”

교사는 “이 문장을 받으면 컴퓨터가 어떤 일을 할 수 있을까요?”라고 물은 뒤, 답변을 목적과 출력 형태로 분류합니다. 불만 여부를 라벨로 만들면 분류, 비슷한 문의를 찾으면 검색, 여러 문의에서 유형을 발견하면 군집화, 사과문을 쓰면 생성입니다. 이 장에서 큰 모델을 공부하지만 모든 일을 큰 생성 모델 하나로 해야 하는 것은 아니라는 관점을 만듭니다.

**질문:** “검색 결과 문서를 그대로 반환하고 새 문장을 쓰지 않는 시스템도 언어 AI인가요?”

**기대 답:** 그렇습니다. 언어 AI는 생성보다 넓은 범위입니다. 검색과 표현도 포함합니다.

**미니 활동:** 학생이 과제 하나를 고르고 입력, 출력, 정답을 어떻게 확인할지 한 줄씩 씁니다. “사과문 생성”을 고른 학생에게는 단일 정답 문자열이 아니라 정확성·어조·정책 준수 같은 기준이 필요할 수 있음을 짚습니다.

**진행상의 주의:** “이해한다”는 말을 인간과 동일한 내면 상태로 해석하지 않도록, 관찰 가능한 기능과 평가 결과를 중심으로 설명합니다.

## 7–19분 — 빈도와 의미는 다른 정보를 담는다

**판서:** A = “고양이 가 강아지 를 쫓는다”, B = “강아지 가 고양이 를 쫓는다”. 어휘 순서 = 고양이, 가, 강아지, 를, 쫓는다.

학생 두 명에게 각각 A와 B의 벡터를 적게 하면 둘 다 `[1,1,1,1,1]`이 됩니다. 그런데 사건의 주체가 다릅니다. 교사는 이것을 “BoW가 계산에 실패했다”가 아니라 “순서를 버리기로 한 표현 설계의 결과”라고 설명합니다. 장점인 단순성과 해석 가능성도 함께 다뤄야 합니다.

**미니 활동:** C = “고양이 고양이 잠잔다”를 추가하고 공유 어휘에 잠잔다를 넣습니다. 모든 벡터가 같은 길이로 확장되어야 하는 이유를 묻습니다. 학생이 각 문서별로 임의의 어휘 순서를 사용하면 비교가 무의미해진다는 점을 설명하도록 유도합니다.

**질문:** “자동차와 승용차가 뜻이 비슷해도 BoW는 자동으로 그 사실을 아나요?”

**기대 답:** 아닙니다. 다른 어휘 좌표입니다. 의미 관계를 표현하려면 추가 학습이나 다른 특징이 필요합니다.

이어서 word2vec의 주변 단어 예측 직관을 설명합니다. 실제 임베딩 좌표를 “동물성”처럼 고정된 이름으로 부르지 말고, 함께 학습된 여러 숫자의 관계로 이해시킵니다. 시각 실험 1에서 단어 순서만 바꾼 결과와 반복 횟수를 늘린 결과를 비교합니다.

**학습 확인:** “희소”와 “밀집”을 각각 0의 비율과 벡터 표현 방식으로 설명할 수 있는지, “밀집이면 항상 더 정확하다”는 과도한 주장을 하지 않는지 확인합니다.

## 19–31분 — 문맥을 압축하고 다시 참조하기

**판서:** “배를 먹었다”, “배를 탔다”. 그 아래에 `hₜ = f(hₜ₋₁, xₜ)`를 적습니다.

같은 단어를 고정된 벡터 하나로 표현할 때의 한계를 먼저 말하게 합니다. RNN이 입력 순서를 따라 상태를 갱신하는 과정을 학생이 직접 읽어주는 방식으로 보여줍니다. 마지막 상태 한 개로 긴 문장을 전달하면 어떤 정보가 어려워질지 토론합니다.

**가중합 활동:** `h₁=(1,0), h₂=(0,1), h₃=(1,1)`과 `α=(0.1,0.2,0.7)`을 제시합니다. 1분 동안 문맥 벡터를 계산하게 합니다. 정답은 `(0.8,0.9)`이며, 각 좌표를 별도로 계산해야 합니다.

**시각 실험:** 실험 2를 열고 세 번째 점수를 바꾸기 전에 “어느 점으로 가까워질까요?”를 예측하게 합니다. 여기의 점수는 실제 학습된 어텐션이 아니라 교육용 값입니다. 점수와 softmax 이후 비율이 다르다는 점을 확인합니다.

**예상 오해와 대응:** “가중치가 가장 높은 단어만 선택한다”는 답이 나오면, 나머지 가중치가 0이 아니라면 그 정보도 섞인다고 정정합니다. “어텐션은 사람이 보기에 중요한 단어의 객관적 순위”라는 답이 나오면, 특정 모델 계산에서 쓰이는 가중치이며 매 출력 단계에 달라질 수 있다고 설명합니다.

## 31–44분 — 인코더와 디코더를 정보 흐름으로 비교하기

**판서:** 네 위치의 4×4 표를 그리고, 대각선과 아래쪽을 “볼 수 있음”, 위쪽을 “차단”으로 칠합니다. 입력 `나는 / 사과를 / 먹었다`와 목표 `사과를 / 먹었다 / 종료`를 나란히 적습니다.

교사는 한 칸 이동한 입력과 정답을 보여주어 대각선 허용과 미래 정보 유출의 차이를 설명합니다. 학습 때는 정답 문장이 있어 여러 위치를 함께 계산하지만, 실제 생성 때는 방금 고른 토큰을 다음 조건에 넣어야 한다고 연결합니다.

**짝 활동:** 한 명은 “BERT가 무엇을 보는지”, 다른 한 명은 “GPT가 무엇을 예측하는지”를 30초씩 설명합니다. BERT는 입력 전체의 문맥을 활용해 가린 토큰을 예측하며 표현을 학습하고, GPT는 이전 토큰을 조건으로 다음 토큰을 예측한다는 핵심이 포함되어야 합니다.

**질문:** “GPT로 긍정/부정 분류를 하면 더 이상 생성 모델이 아닌가요?”

**기대 답:** 주요 구조와 학습 방식은 생성 모델이고, 그것을 사용하는 응용 과제가 분류입니다. 모델의 기능적 분류와 업무 목적은 다른 축입니다.

**학습 확인:** 학생에게 “학습 병렬화”와 “생성 순서” 두 말을 모두 포함해 트랜스포머를 설명하게 합니다. 설명이 “문장 전체를 한 번에 생성한다”로 끝나면 생성 루프로 돌아갑니다.

## 44–54분 — 사전 학습을 재사용해 응용을 만들기

**판서:** 대규모 텍스트 → 사전 학습 → 기반 모델 → 과제별 미세 조정. 별도로 “프롬프트에 예시 추가 → 추론 입력 변경”을 적습니다.

**분류 활동:** 다음 세 행동을 학습/추론으로 나누게 합니다. ① 질문에 예시 세 개를 넣는다. ② 정답 리뷰 데이터로 가중치를 갱신한다. ③ 저장된 모델을 불러와 문장 벡터를 계산한다. 정답은 각각 추론 입력 구성, 미세 조정, 추론/특징 추출입니다.

**설계 활동:** 고객 문의 처리 시스템을 “부서 분류 → 관련 사례 검색 → 응답 초안 생성”으로 나눕니다. 각 단계의 입력·출력·평가 항목을 적게 합니다. 분류 오류와 답변 사실 오류를 같은 문제로 다루지 않도록 합니다.

**원문 연결:** 표현 모델 분류는 4장과 11장, 군집과 주제 발견은 5장, 프롬프트는 6장, 도구 구성은 7장, 검색과 RAG는 8장, 멀티모달은 9장, 임베딩 학습은 10장, 생성 미세 조정은 12장으로 연결합니다.

## 54–63분 — API와 로컬 실행을 조건에 따라 선택하기

**시나리오 A:** 짧은 기간 동안 공개 데이터로 기능을 시험하는 소규모 팀.

**시나리오 B:** 외부 반출이 제한된 내부 문서를 장기간 처리하는 팀.

두 시나리오에서 품질, 데이터 흐름, 장비, 유지 관리, 비용을 비교하게 합니다. 정답을 “항상 API” 또는 “항상 로컬”로 정하지 않습니다. API는 원격 실행 인터페이스이고 공개 모델도 API로 제공할 수 있다는 점을 확인합니다.

**손계산:** 38억 파라미터 × 2바이트 = 76억 바이트. “8GB 장치면 반드시 된다”라는 결론이 왜 틀릴 수 있는지 묻습니다. 캐시와 런타임 등 다른 메모리가 필요하다는 답을 기대합니다.

책의 책임 있는 사용 항목은 실제 과제의 검토 질문으로 바꿉니다. 어떤 입력 집단에서 오류가 많을 수 있는가, 사용자는 자동 응답임을 아는가, 사실 확인은 어떻게 하는가, 모델과 데이터의 사용 조건은 무엇인가를 묻습니다. 이 수업은 현행 규정의 상세 법률 판단을 제공하는 자리가 아닙니다.

## 63–75분 — 실행 전 예측과 실제 결과 비교

작업 폴더에서 `python3 chapters/ch01/lab.py`를 실행합니다. 실행 전 다음 세 가지를 학생에게 적게 합니다.

1. A와 B의 코사인 유사도는 얼마일까? 정답 1.
2. 세 번째 어텐션 점수가 가장 크면 어느 입력의 비중이 가장 클까? 정답 h₃.
3. “오늘” 다음의 빈도가 날씨가 3회, 기분이 1회라면 탐욕적 선택은? 정답 날씨가.

결과를 보며 `lab-output.txt`와 비교합니다. 생성 예제는 여섯 문장의 빈도만 센 작은 bigram 모형입니다. 이 출력으로 Phi-3의 품질이나 현대 LLM의 추론 능력을 평가하면 안 됩니다. “반복적으로 다음 토큰을 선택한다”는 구조만 학습하는 실습입니다.

**변경 실험:** `--attention-score 0`, `--max-new-tokens 1`, `--sample --seed 7`을 각각 적용합니다. 한 번에 한 가지 조건만 바꾸고 관찰하도록 안내합니다. 표본 선택은 작은 말뭉치에서 가능한 경로를 바꿀 수 있지만 새로운 의미 지식을 추가하지 않습니다.

마지막으로 원문의 실제 모델 코드에서 tokenizer, model, pipeline, messages, max_new_tokens의 역할을 손으로 표시합니다. 설치나 모델 다운로드를 수업 완료 조건으로 삼지 말고, 모델 카드와 재현 환경을 확인하는 확장 학습으로 안내합니다.

## 75–80분 — 출구 질문과 평가

종이에 다음 세 질문에 각각 두 문장 이내로 답하게 합니다.

- BoW에서 같은 벡터인데 의미가 다른 문장의 예와 그 이유를 쓰세요.
- 어텐션이 무엇을 가중합하며, 왜 단계마다 가중치가 달라질 수 있는지 쓰세요.
- 프롬프트에 예시를 추가하는 것과 미세 조정의 차이를 쓰세요.
