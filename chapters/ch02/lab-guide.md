## 1. 실행과 재현

Python 3.9 이상에서 프로젝트 루트 기준으로 실행한다.

```bash
python3 chapters/ch02/lab.py
python3 chapters/ch02/lab.py --help
```

기본 설정은 `seed=42`, `epochs=60`, `dims=8`, `window=2`, `negatives=3`이다. [lab-output.txt](lab-output.txt)는 기본 명령을 실제로 실행해 저장한 출력이다. 학습률은 0.08에서 0.02로 선형 감소하고, 무작위 초기화·학습 쌍·순서를 각 고정 seed로 만든다. 고정된 작은 데이터에 대한 결정적 실습이며 특정 Gensim 설정의 완전한 재구현은 아니다.

실습 결과를 별도로 저장하고 싶으면 다음처럼 실행할 수 있다.

```bash

```

Python을 쓸 수 없는 경우에도 [시각 실험](visuals.html)을 브라우저에서 열어 단위 비교, 벡터 업데이트, 패딩 평균을 조작할 수 있다. GitHub는 HTML의 JavaScript를 문서 화면에서 실행하지 않으므로, 저장소를 내려받은 뒤 파일을 로컬 브라우저에서 연다.

## 2. 실행 전에 예상하기

코드를 읽기 전에 다음 다섯 답을 적는다.

1. `A가😊`의 코드 포인트 수와 UTF-8 바이트 수는 같은가?
2. `low`, `lower`, `lowest`가 여러 번 나오면 어떤 문자열 조각이 재사용될까?
3. 패딩 벡터를 평균에 넣으면 결과가 바뀌는가?
4. 직각인 두 벡터를 양성 쌍으로 한 번 학습하면 내적이 올라가는가?
5. 노래 제목과 장르 이름을 학습에 넣지 않아도 그룹이 생길 수 있는가?

출력을 보고 원래 예측을 지우지 말고 옆에 수정 이유를 쓴다. 틀린 예측은 어떤 개념이 아직 모호한지 알려준다.

## 3. 문자와 바이트

`text.encode("utf-8")`는 문자열을 UTF-8 바이트로 바꾼다. 기본 예제는 코드 포인트 3개, 바이트 8개다. 바이트 값은 다음과 같다.

```text
A: [65]
가: [234,176,128]
😊: [240,159,152,138]
```

마지막에 전체 바이트를 디코딩하면 원문이 복원되는지 검산한다. `len(text)`는 이 실습에서 코드 포인트 수를 읽는 데 쓰이며, 모든 결합 문자·이모지 시퀀스의 화면상 글자 수를 세는 도구가 아니다.

**변경 실험:** 영문 문장, 한글 문장, 이모지를 각각 넣고 길이를 비교한다. “한국어 토큰 수는 언제나 영어의 몇 배”처럼 고정 배율로 결론 내리지 않는다. 이 단계는 모델 토크나이저가 아니라 문자 인코딩의 단위를 비교한다.

## 4. 작은 BPE를 직접 추적하기

`learn_bpe`는 단어 빈도와 글자 배열에서 출발한다. 각 단어 뒤에 `</w>`라는 교육용 끝 표지를 붙이고, 인접 기호 쌍의 가중 빈도를 센다. 가장 빈번한 쌍을 하나의 기호로 합친 뒤 이를 반복한다. 동률은 문자열 순서로 정해 결과를 재현한다.

기본 데이터에서 처음 두 병합은 `e+r → er`, `er+</w> → er</w>`다. 여러 단어 끝에서 `er`가 반복되기 때문이다. 이후 `l+o → lo`, `lo+w → low`가 생긴다. 최종적으로 `low`는 `['low</w>']`, `lower`는 `['low','er</w>']`로 표현된다. 같은 조각을 재사용하는 모습을 확인한다.

**코드의 역할 구분:** `learn_bpe`는 병합 규칙을 학습하고, `encode_word`는 이미 학습한 규칙을 새 단어에 순서대로 적용한다. 입력할 때마다 규칙을 다시 학습하지 않는다. `merge_symbols`는 겹치지 않는 인접 쌍을 왼쪽부터 합친다.

**변경 실험:** `word_counts`에서 `wider`의 빈도를 30으로 바꾸고 첫 네 병합을 비교한다. 같은 알고리즘과 병합 횟수라도 데이터 분포가 달라지면 규칙이 달라진다. 이것은 실제 모델에서도 데이터 영역이 토크나이저에 영향을 준다는 원리와 연결된다.

**범위:** 이 구현은 단어별 교육용 BPE다. 실제 제품의 정규화, 사전 분할, 바이트 fallback, 특수 토큰, 어휘 제한을 모두 구현하지 않는다. 훈련에 없던 문자는 초기 기호로 그대로 남길 수 있으므로 완전한 고정 어휘 토크나이저가 아니다. 여기서는 알고리즘의 병합과 복원 원리만 관찰한다.

## 5. lookup과 마스크 평균

`E`는 직접 지정한 작은 행렬이다. ID `[1,2,3]`로 행을 골라 벡터 세 개를 만든다. 이 단계는 수치를 학습하는 과정이 아니라 **임베딩 표에서 행을 찾는 과정**이다.

```text
내용1: [2,0]
내용2: [0,2]
패딩:  [10,10]
```

`masked_mean(vectors, [1,1,0])`은 `[1,1]`, 모든 위치를 포함하면 `[4,4]`를 출력한다. 두 결과의 차이를 보고 패딩이 왜 마스크와 함께 다뤄져야 하는지 설명한다. 모든 위치를 제외하면 분모가 0이 되므로 함수가 오류를 낸다. 서로 다른 차원의 벡터를 넣는 경우도 점검한다.

`cosine([1,0],[1,1])`은 약 0.707107이다. 내적만 쓴 값 1과 코사인 값이 다른 이유는 벡터 길이로 나누기 때문이다. 영벡터는 이 실습에서 0.0으로 처리한다. 실제 시스템에서는 영벡터 입력을 오류·제외·별도 상태 등으로 처리할 수 있으므로 정책을 명시해야 한다.

**변경 실험:** 패딩을 `[0,0]`으로 바꾸어 무조건 평균이 `[2/3,2/3]`가 되는지 확인한다. 값이 0이어도 잘못된 분모 때문에 평균의 크기는 바뀐다. 코사인은 같은 방향의 크기 차이를 무시할 수 있지만 모든 후속 계산이 그렇지는 않다. “패딩이 0이니까 마스크가 필요 없다”는 일반화는 피한다.

## 6. 경사 한 번을 검산하기

`update_pair`는 중심 벡터와 문맥 벡터를 받아 이진 교차 엔트로피의 경사를 적용한다. 먼저 원래 벡터를 복사하고, 내적과 sigmoid를 계산한 뒤 `p-y`를 사용한다. 두 업데이트 모두 같은 원래 상태를 사용한다.

기본 손계산의 실제 출력은 다음과 같다.

```text
u=[1.0,0.05], v=[0.05,1.0]
sigmoid: 0.500000 → 0.524979
```

수치 검산은 양성 쌍에서 점수가 올라가고, 같은 초기값의 음성 쌍에서는 내려가는지 확인한다. 이것은 전체 모델 성능 테스트가 아니라 수학과 구현이 같은 방향을 가리키는지 확인하는 작은 검증이다.

**변경 실험:** 학습률을 0.01, 0.1, 0.3으로 바꿔 한 번의 변화량을 비교한다. 더 큰 학습률이 언제나 좋은 학습이라는 결론을 내리지 않는다. 여러 쌍이 서로 다른 방향을 요구하는 전체 학습에서는 불안정성이 생길 수 있다.

## 7. 가상 재생목록과 학습 쌍

노래는 12개이며 4개씩 세 그룹으로 배치한 인공 데이터다. 각 그룹의 순서를 섞어 8개의 재생목록을 만들므로 총 24개다. 이 그룹 설계는 관계가 학습되는 모습을 쉽게 관찰하기 위한 것이다. 제목과 장르 이름은 `SONGS`에 있지만 학습에는 ID만 사용한다.

`positive_pairs`는 각 재생목록에서 중심과 좌우 창의 이웃을 뽑는다. 길이 4, 창 크기 2이면 중심별 이웃 수는 2,3,3,2여서 목록당 10쌍이다. 따라서 24개 목록에서 양성 쌍은 240개다. 양성마다 음성 3개를 붙이면 총 960개의 학습 쌍이 된다. 출력 숫자를 직접 이 계산과 맞춰본다.

음성은 전체 어휘에서 균등하게 뽑되 중심과 현재의 양성 항목만 제외한다. 다른 실제 관련 항목은 음성이 될 수 있다. 이는 false negative가 남는 단순한 교육용 방식이다. 원래 Word2vec 구현의 빈도 기반 잡음 분포나 여러 최적화를 모두 따르지는 않는다. 음성 예제는 한 번 만든 뒤 고정하고 각 epoch에서 순서만 섞는다.

## 8. 실제 학습 결과 해석

`train_sgns`는 중심용 행렬 U와 문맥용 행렬 V를 무작위로 초기화한다. 각 예제에서 두 행만 업데이트하고, 정해진 epoch에서 고정 학습 쌍 전체의 평균 손실을 계산한다. 기본 실행의 결과는 다음과 같다.

| epoch | 고정 학습 쌍의 평균 BCE |
|---:|---:|
| 0 | 0.694397 |
| 1 | 0.628455 |
| 10 | 0.295571 |
| 60 | 0.277562 |

손실은 실제 계산했지만 **훈련 데이터에서 측정한 값**이다. 검증 데이터나 실제 사용자의 만족도를 측정한 것이 아니다. 최종 추천은 중심용 행렬 U의 코사인으로 계산하며 질의곡 자신을 제외한다.

기본 실행에서 `햇살 산책` 주변에는 `여름 편지`, `반짝이는 길`, `도시의 오후`가 나온다. 모두 같은 가상 그룹이다. 음원 특성을 읽은 것이 아니라, 함께 등장하도록 만든 시퀀스에서 관계를 배운 결과다. 점수를 “추천을 좋아할 확률”로 읽지 않는다.

## 9. 바꿔볼 실험

한 번에 한 조건만 바꿔 비교한다. 추천 순위가 달라지면 변화의 이유를 코드·데이터·학습 신호 중 어디에서 찾을지 적는다.

```bash
python3 chapters/ch02/lab.py --window 1
python3 chapters/ch02/lab.py --epochs 1
python3 chapters/ch02/lab.py --seed 7
python3 chapters/ch02/lab.py --dims 2
python3 chapters/ch02/lab.py --negatives 1
```

- `window=1`: 길이 4 목록당 양성 쌍은 6개가 된다. 가까운 순서에 더 좁게 집중한다.
- `epochs=1`: 아직 덜 학습된 공간과 최종 결과를 비교한다. 무작위 초기값의 영향이 남을 수 있다.
- seed 변경: 순서와 음성 표본·초기값이 달라진다. 예시 한 번의 순위가 얼마나 안정적인지 본다.
- 2차원: 계산 용량을 줄여 관계가 얼마나 표현되는지 본다. 시각화가 쉬워진다는 이유만으로 2차원이 좋은 모델은 아니다.
- 음성 수 변경: 학습 쌍의 구성 자체가 바뀌므로 서로 다른 실험의 BCE 숫자만 직접 비교해 우열을 정하지 않는다.

## 10. 원문의 실제 모델 실습으로 확장하기

아래는 **확장 절차이며 이 자료 제작 과정에서 실행하지 않았다.** 외부 모델·데이터를 내려받거나 GPU를 사용한 결과를 검증했다는 뜻이 아니다. 원문은 2024년 환경을 기준으로 한다.

### 토큰화와 생성

먼저 Phi-3와 같은 원문 체크포인트의 토크나이저만 불러와 ID·토큰 표기·전체 디코딩을 확인한다. 이어 모델을 준비할 때는 라이브러리 버전, 하드웨어, 모델 카드의 입력 형식을 확인한다. 모델과 토크나이저를 같은 체크포인트로 맞추고, 입력과 모델 장치를 일치시킨다. `max_new_tokens`와 전체 반환 길이의 관계를 확인한 뒤 생성한 부분만 분리해 본다. 코드 실행을 수반하는 원격 구현 옵션은 모델이 요구하는 이유를 확인한 후 선택한다.

### 문맥 임베딩

원문 DeBERTa 예제는 서로 다른 모델 이름이 섞여 있으므로 동일 체크포인트를 사용한다. 출력은 이름 있는 `last_hidden_state`로 읽으면 의도가 명확하다. `eval()`과 추론 모드를 적용하고, `input_ids`·특수 토큰·출력 모양을 직접 출력한다. 책에 적힌 토큰 수와 다르면 실제 토크나이저 결과를 기준으로 해석한다.

```python
# 확장용 예시. 여기서는 실행하지 않았음.
import torch
from transformers import AutoTokenizer, AutoModel

checkpoint = "microsoft/deberta-v3-xsmall"
tokenizer = AutoTokenizer.from_pretrained(checkpoint)
model = AutoModel.from_pretrained(checkpoint).eval()
inputs = tokenizer("Hello world", return_tensors="pt")
with torch.inference_mode():
    hidden = model(**inputs).last_hidden_state
print(tokenizer.convert_ids_to_tokens(inputs["input_ids"][0]))
print(hidden.shape)
```

체크포인트 정보는 [공식 모델 카드](https://huggingface.co/microsoft/deberta-v3-xsmall)에서 확인한다. 위 코드는 결과 모양을 고정해 단언하지 않고 직접 점검하도록 구성했다.

### 문장 벡터와 노래 벡터

문장 임베딩은 원문의 Sentence Transformers 모델을 불러와 한 문자열과 문자열 리스트를 각각 넣고 출력 모양을 비교한다. 임의 평균 벡터와 목적에 맞게 학습한 문장 모델을 작은 검색 질의 집합에서 비교해보면 좋은 후속 실습이 된다.

노래 데이터로 확장할 때는 원문 데이터 형식을 확인하고 ID 타입을 통일한다. Gensim에서 skip-gram을 의도한다면 `sg=1`을 명시한다. 메타데이터는 ID 라벨로 조회하고, 학습에 없는 곡·희귀 곡·인기 편향을 점검한다. [Gensim 공식 문서](https://radimrehurek.com/gensim/models/word2vec.html)
