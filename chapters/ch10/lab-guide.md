# 10장 실습 안내 대조 학습을 직접 계산하기

[전체 목차](../../README.md) · [학습 노트](study.md) · [강의안](lecture.md) · [강의 대본](lecture-script.md) · [시각화](visuals.html) · [실습 안내](lab-guide.md) · [복습 문제](quiz.md)

**연결되는 원문**: *Hands-On Large Language Models*, Chapter 10, PDF 399–445쪽. 특히 MNR 손실 420–426쪽, 평가 411–416쪽, TSDAE 435–441쪽.

이 실습은 표준 Python 라이브러리만 사용하여 작은 문장 인코더의 파라미터를 실제로 학습한다. 모델 다운로드·GPU·API 키가 필요 없다. Transformer를 생략한 교육용 모형이며, 원문 BERT·MiniLM·TSDAE 학습을 실행한 결과가 아니다. 문장에 등장하는 단어 벡터를 평균하여 임베딩을 만든 뒤 MNR 손실을 미분하고 경사 하강으로 업데이트한다.

## 1 실행하기

저장소 최상위 폴더에서 다음 명령을 실행한다.

```bash
python3 chapters/ch10/lab.py
```

이 장 폴더 안에서 실행한다면 다음과 같다.

```bash
python3 lab.py
python3 lab.py --help
```

기본값은 seed 17, 200단계, 학습률 0.12, temperature 0.2이다. 실제 기본 실행 결과는 [lab-output.txt](lab-output.txt)에 저장되어 있다. 라이브러리 설치가 필요 없는 순수 Python 계산이며, 수치의 마지막 자리는 환경의 부동소수점 처리에 따라 약간 다를 수 있다.

실습 파일은 [lab.py](lab.py)이다. 코드를 보기 전에 실행 결과의 다섯 묶음을 먼저 읽는다. 첫째는 손계산, 둘째는 학습, 셋째는 평가 지표, 넷째는 손상 데이터, 다섯째는 관계 데이터 점검이다.

## 2 실험 데이터와 인코더

학습 데이터는 직접 만든 고객 지원 문장 6쌍이다. ‘암호 재설정 방법’과 ‘비밀번호 변경 절차’처럼 같은 업무 의도를 표현하는 쌍이다. 총 29개 단어를 공백으로 나누어 사전에 등록한다. 이 분리는 실제 한국어 형태소 분석이나 subword tokenization이 아니다. 입력 표현과 손실의 연결을 단순하게 보기 위한 선택이다.

각 단어는 6차원 벡터를 갖는다. 처음에는 seed가 고정된 작은 난수로 초기화한다. 문장에 속한 단어 벡터의 평균을 구하고, 그 평균의 길이를 1로 정규화한다. anchor와 positive에 동일한 단어 벡터 표를 사용하므로 공유 인코더다. 양쪽에서 발생한 기울기가 같은 파라미터에 누적된다.

```mermaid
flowchart LR
    T[공백으로 나눈 단어] --> W[학습 가능한 단어 벡터 표]
    W --> M[문장 내 벡터 평균]
    M --> N[L2 정규화]
    N --> S[배치 후보와 내적]
    S --> L[MNR 손실]
    L --> U[기울기로 단어 벡터 업데이트]
    U --> W
```

**관찰 질문**: ‘주소 변경 방법’과 ‘배송 조회 방법’은 ‘방법’을 공유한다. 단어 벡터 표를 공유하면 이 단어는 한 쌍만의 학습에 속하지 않는다. 여러 문장에서 받은 기울기가 한 벡터에 모인다. 이런 공유가 일반화의 재료가 될 수 있지만, 작은 데이터의 훈련 적합만으로 일반화가 입증되지는 않는다.

**명확한 한계**: 단어 순서를 바꾸어도 평균은 같다. 부정·문맥·문장 순서를 이해하는 Transformer가 아니다. 사전에 없는 단어를 다루는 경로도 없다. 이 예제를 한국어 검색 모델로 배포해서는 안 되는 이유는 데이터가 작다는 것뿐 아니라 표현 구조가 매우 제한적이기 때문이다.

## 3 출력 묶음 1 MNR 손계산

정답 후보의 코사인 0.8을 고정하고, 경쟁 후보를 0.1, 0.6, 0.78로 바꾼다. 세 번째 후보는 −0.1이다. 기본 temperature 0.2에서 실제 출력은 다음과 같다.

| 경쟁 후보 점수 | 정답 확률 | 한 행 손실 |
|---:|---:|---:|
| 0.10 | 0.960332 | 0.040476 |
| 0.60 | 0.725169 | 0.321350 |
| 0.78 | 0.521935 | 0.650212 |

학습 노트의 손계산은 세 번째 후보가 0.1인 별도 예다. 이 실습은 −0.1로 설정했으므로 숫자가 조금 다른 것이 정상이다. 두 예 모두 같은 식을 쓴다.

핵심은 정답 점수 하나만으로 손실을 결정할 수 없다는 것이다. 분모에 경쟁 후보가 포함되어 상대적 우위가 확률을 결정한다. `softmax()`는 최대 logit을 먼저 빼서 큰 지수값에 의한 수치 불안정을 줄인다. 최대값을 뺀 것은 확률 비율을 바꾸지 않는다.

중복 예에서는 `[4,4,−20]`을 logit으로 쓴다. 정답 후보와 동일한 두 번째 후보가 같은 값을 가지므로 손실은 `ln 2`에 아주 가깝다. ‘훈련이 부족해서 손실이 남았다’가 아니라 단일 정답 표시와 동일 후보가 충돌한다는 예다.

## 4 출력 묶음 2 파라미터를 실제로 업데이트하기

`objective()`는 여섯 anchor와 여섯 positive의 임베딩을 구한다. 6×6 코사인 행렬의 대각선을 정답으로 삼는다. 각 행에서 softmax 교차엔트로피를 구하고 배치 평균을 계산한다. 한 방향의 MNR이며, 양방향 손실이나 explicit negative 확장은 구현하지 않았다.

학습 단계마다 다음 순서로 계산한다.

1. 현재 단어 벡터로 문장 임베딩을 다시 계산한다.
2. 후보 점수와 MNR 손실을 구한다.
3. logit에 대한 미분 `확률−정답표시`를 계산한다.
4. 내적, L2 정규화, 평균 pooling을 거슬러 단어 벡터 기울기를 구한다.
5. `가중치 ← 가중치 − 학습률 × 기울기`로 갱신한다.

정규화 전 벡터가 `z`, 단위벡터가 `u=z/‖z‖`, 위에서 내려온 기울기가 `g`일 때 정규화의 역전파는 `(g−u(u·g))/‖z‖`이다. 코드의 주석과 이 식을 대응시키면 벡터 길이에 수직인 방향을 남기는 구조를 볼 수 있다. 영벡터에서는 나눌 수 없으므로 명시적으로 오류를 낸다.

첫 업데이트 전에는 단어 벡터의 한 좌표를 아주 조금 더하고 빼서 손실 차이를 측정한다. 이것이 finite difference다. 수식으로 구한 미분과 비교한 기본 실행의 오차는 약 `7.38e−11`이다. 이 검산은 구현한 작은 역전파가 손실 계산과 일치한다는 근거이며, 실제 언어 모델의 성능을 검증하는 테스트는 아니다.

| 단계 | MNR 손실 | 훈련 집합 top-1 |
|---:|---:|---:|
| 0 | 3.374441 | 0.000 |
| 1 | 1.184915 | 0.500 |
| 10 | 0.114909 | 1.000 |
| 50 | 0.030530 | 1.000 |
| 100 | 0.023069 | 1.000 |
| 200 | 0.020317 | 1.000 |

top-1은 각 훈련 anchor가 여섯 후보 중 자기 짝을 첫 번째로 고른 비율이다. 10단계 이후 top-1은 이미 1이지만 손실은 계속 내려간다. 순위가 맞은 뒤에도 정답과 오답 사이의 확률 여유를 늘릴 수 있기 때문이다. 따라서 같은 top-1을 가진 두 모델도 손실은 다를 수 있다.

## 5 출력 묶음 3 상관이 1이어도 오차는 남는다

사람 점수 `[0.0,0.2,0.6,0.8]`와 예측 `[0.1,0.3,0.7,0.9]`를 비교한다. 모든 예측이 0.1 높지만 Pearson과 Spearman은 모두 1이고 MSE는 0.01이다. 상관은 함께 움직이는 관계를, MSE는 절대적인 차이를 측정한다.

`pearson()`은 평균을 뺀 점수 목록의 내적을 각각의 길이로 나눈다. `ranks()`는 동점에 평균 순위를 부여한다. 상수 점수 목록의 Pearson은 정의되지 않으므로 오류를 반환한다. 어떤 라이브러리가 NaN이나 경고를 반환하더라도 문제의 본질은 분산이 0이라는 것이다.

**변경 활동**: 예측을 사람 점수의 순서를 반대로 뒤집은 목록으로 바꾸면 어떻게 될지 먼저 예상한다. 완벽하게 반대 순서·선형 관계라면 상관은 −1이 된다. 상관 범위를 0–1이라고 외웠다면 이 실험으로 바로잡을 수 있다.

## 6 출력 묶음 4 TSDAE의 손상 데이터 만들기

`deletion_noise()`는 단어마다 정해진 삭제 확률을 적용한다. 남는 단어가 하나도 없으면 한 단어를 남겨 빈 입력을 피한다. seed를 고정하여 결과를 재현할 수 있다. ‘삭제 확률 20%’라고 정확히 20%의 단어를 삭제하도록 강제하지는 않는다. 짧은 문장에서는 하나도 삭제되지 않을 수 있으며 기본 출력에서도 그런 사례가 나타난다.

이 단계는 손상 문장과 원래 문장을 쌍으로 만드는 전처리만 수행한다. Transformer 인코더, 디코더, 복원 손실의 학습은 포함하지 않는다. 출력에 원문이 보이는 이유는 학습용 정답을 함께 출력했기 때문이다. 모델이 그 문장을 복원했다고 해석하지 않는다.

## 7 직접 바꿔볼 실험

각 실험은 먼저 예측을 적고 실행 뒤 차이를 설명한다. 아래 옵션은 실제 지원되는 인자다.

```bash
python3 chapters/ch10/lab.py --steps 0
python3 chapters/ch10/lab.py --steps 50
python3 chapters/ch10/lab.py --temperature 0.5
python3 chapters/ch10/lab.py --lr 0.03
python3 chapters/ch10/lab.py --seed 23
```

| 바꿀 것 | 실행 전 질문 | 결과를 읽는 기준 |
|---|---|---|
| `--steps 0` | 학습하지 않아도 좋은 점수가 나오는가? | 초기화만 사용한 비교군 |
| 50 vs 200단계 | top-1이 같은데 손실은 왜 다른가? | 순위와 확률 여유의 차이 |
| temperature 0.2 vs 0.5 | 후보 확률이 더 평평해지는가? | 손실 규모와 학습 동역학도 함께 변함 |
| 학습률 0.12 vs 0.03 | 같은 단계 수에서 수렴 속도가 다른가? | 너무 큰 학습률이 항상 좋은 것은 아님 |
| seed 17 vs 23 | 초기 검색 결과가 달라지는가? | 작은 실험의 무작위성 |

**확장 과제**: PAIRS에 서로 다른 표기로 같은 정답을 표현한 문장 쌍을 추가한다. 같은 배치에서 서로 negative가 되는지 확인하고, 여러 positive를 허용하는 평가 정책을 먼저 설계한다. 단순히 마지막 top-1이 높게 나오도록 데이터를 편집하지 않는다.

## 8 원문의 실제 모델 학습으로 확장하기

아래는 실행 절차의 설계이며, 이 자료 작성 과정에서 원문의 BERT·MiniLM·MTEB·TSDAE GPU 학습을 실행하지 않았다. 책의 라이브러리 호출은 2024년 예제이며 환경을 만들 때 설치 버전과 공식 문서의 API를 확인해야 한다.

1. **독립 환경과 기록**: Python, PyTorch, sentence-transformers, datasets 등의 버전을 고정하여 기록한다. GPU 종류·메모리·seed·데이터 분할도 남긴다. 원문의 CUDA·FP16 설정은 모든 장치에 적용되지 않는다.
2. **기본 모델 평가**: 미세 조정 전 체크포인트를 고정된 검증 집합에서 평가한다. 처음 결과가 없으면 학습의 효과를 분리하기 어렵다.
3. **데이터 의미 확인**: MNLI label 0을 positive로 쓸지, 점수 회귀에 쓸지 결정한다. MNR에는 모순·중립 쌍을 positive로 그대로 넣지 않는다.
4. **배치 점검**: 첫 배치의 텍스트와 열 순서를 직접 출력해 확인한다. 같은 문장 또는 같은 정답이 서로 negative가 되는지 살핀다.
5. **짧은 시험 실행**: 작은 데이터로 한두 단계 학습하여 메모리와 손실, 평가 호출을 확인한 뒤 규모를 늘린다.
6. **평가와 저장 연결**: `eval_steps`뿐 아니라 평가 전략·저장 전략·최적 모델 기준·최적 체크포인트 로드를 확인한다. API가 자동으로 모든 의도를 추론한다고 기대하지 않는다.
7. **독립 최종 평가**: 모델 선택에 쓰지 않은 데이터에서 검색·분류 등 목표 작업을 측정한다. 책의 STS-B 상관계수를 자신의 성능으로 복사하지 않는다.

MNR 데이터 변환의 핵심은 다음 의사코드와 같다. 라이브러리별 실행 스크립트가 아니라 관계를 보존하는 로직이다.

```python
positive_rows = [row for row in mnli_rows if row["label"] == 0]
training_pairs = [
    {"anchor": row["premise"], "positive": row["hypothesis"]}
    for row in positive_rows
]
# 관계가 검증된 negative가 있다면 별도 열에 추가한다.
# 숫자 NLI label을 그대로 남겨 자동으로 관계가 처리된다고 가정하지 않는다.
```

Augmented SBERT라면 gold 평가 집합을 먼저 떼어 두고, gold 교사 학습→silver 라벨 생성→학생 학습을 한다. TSDAE라면 중복 정리한 목표 도메인 문장, 손상 버전·원문 쌍, pooling, 복원 디코더를 확인한다. 해당 단계의 좋은 손실과 최종 검색의 좋은 성능을 따로 기록한다.

원문에는 `dataset`/`train_dataset`, `model`/`embedding_model` 이름 혼용과 silver 개수, MNR 필터 누락 등의 주의점이 있으므로 [학습 노트의 보완표](study.md#corrections)를 함께 읽는다. 현재 라이브러리의 데이터·손실 연결은 [공식 학습 안내](https://www.sbert.net/docs/sentence_transformer/training_overview.html)에서 확인할 수 있다.

## 9 실습 완료 기준

- MNR 손실이 정답 코사인만으로 결정되지 않는 이유를 수치로 설명할 수 있다.
- 같은 positive가 중복될 때의 손실 하한을 이해한다.
- 코드에서 임베딩을 만드는 부분, 손실 계산, 기울기, 업데이트를 구별할 수 있다.
- 훈련 top-1 1.0과 새 문장 성능이 다르다고 명확히 말할 수 있다.
- Pearson 1과 MSE 0이 동일한 조건이 아님을 설명할 수 있다.
- TSDAE 손상 전처리와 실제 복원 모델 학습을 구분한다.
