# 11장 실습 안내 작은 계산으로 미세 조정 이해하기

[전체 목차](../../README.md) · [학습 노트](study.md) · [강의안](lecture.md) · [대본](lecture-script.md) · [시각화](visuals.html) · [실습](lab-guide.md) · [복습 문제](quiz.md)

이 실습은 **표준 Python으로 직접 계산하는 CPU 개념 실습**이다. BERT·SetFit 모델을 다운로드하거나 API를 호출하지 않는다. 작은 신경망은 실제 경사하강법으로 학습하지만 언어 모델이 아니다. 가상 좌표와 문장 분할에서 나온 점수를 실제 데이터셋의 성능으로 해석하지 않는다. 원문 PDF 449–485쪽의 네 가지 원리를 분리해 확인하는 목적이다.

## 실행과 결과

저장소 루트에서 실행한다.

```bash
python3 chapters/ch11/lab.py
```

장 폴더 안에서는 다음처럼 실행한다.

```bash
python3 lab.py
python3 lab.py --help
```

기본 실행의 실제 출력은 [lab-output.txt](lab-output.txt)에 저장되어 있다. 외부 패키지 설치는 필요 없다. seed는 21, 학습 단계는 300, 학습률은 0.15, 클래스당 문장 수는 16, 마스킹 확률은 0.15다. 난수 seed는 쌍 샘플링과 마스킹에 사용하며 작은 분류기의 초기값과 학습 데이터는 고정되어 있다.

| 실험 | 직접 계산하는 것 | 기본 실행에서 확인한 결과 |
|---|---|---|
| 표현 동결 | 작은 신경망의 교차 엔트로피와 역전파 | 동결 평가 정확도 0.500, 공동 학습 1.000 |
| 관계 쌍 | 고유 무순서 쌍과 반복 샘플링 | 양성 240, 음성 256, 전체 496; 샘플링 항목 1,280 |
| MLM 준비 | 토큰/단어 단위 선택과 목표 배열 | 특수 토큰 제외, 비선택 위치 -100 |
| NER | BIO 정렬과 엄격한 구간 평가 | 토큰 정확도 0.833, 개체 F1 0.500 |

첫 행의 점수는 매우 단순하게 설계한 가상 좌표에서 나온 결과다. BERT의 원문 F1과 같은 지표·데이터가 아니므로 숫자를 직접 비교하지 않는다. seed 21의 반복 샘플링에서는 고유 쌍 463개가 관측되지만, seed를 바꾸면 달라질 수 있다.

## 실험 1 표현 동결과 공동 학습

### 어떤 모델인가

입력은 두 좌표 `x=(x₁,x₂)`다. 표현은 `h=tanh(a₁x₁+a₂x₂)`라는 숫자 하나이고, 분류 확률은 `sigmoid(wh+b)`다. 정답은 `x₂>0`이면 1이다. 초기 표현은 `a=(1,0)`이라 정답에 필요한 두 번째 좌표를 무시한다. 분류 헤드는 이미 잃어버린 정보를 혼자 복구할 수 없다.

`loss_and_grad`는 배치 평균 이진 교차 엔트로피와 네 파라미터의 기울기를 직접 계산한다. `freezing_demo`는 같은 초기 상태에서 두 조건을 실행한다. 동결 조건에서는 a의 기울기를 0으로 두어 a를 업데이트하지 않는다. 공동 조건은 a와 w, b를 모두 업데이트한다. 매 단계의 기울기는 같은 현재 파라미터에서 계산한 뒤 동시에 반영한다.

**검산:** `gradient_check`는 각 파라미터를 아주 조금 증가·감소시킨 손실 차이로 수치 기울기를 계산한다. 기본 실행의 최대 오차는 약 `1.11e-10`으로 해석적 기울기와 일치했다. 이는 역전파 구현의 의미 있는 검산이며, 실제 모델의 정확도를 검증하는 시험은 아니다.

### 관찰 질문

1. 동결 조건에서 a가 정확히 `(1,0)`으로 남는가?
2. 공동 학습에서 a₂가 커지고 a₁이 작아지는 이유는 무엇인가?
3. 동결 학습의 손실이 약 0.693에 가까워지는 것은 어떤 예측 상태를 뜻하는가?
4. 두 조건 모두 순전파는 수행하는가?

0.693은 `-log(0.5)`에 가깝다. 이 대칭적인 데이터에서는 고정 표현으로 양성을 구분할 수 없어 확률을 0.5 가까이 내놓는 쪽으로 간다. 정확히 0.5일 때 어떤 클래스로 결정하는지는 임계값 규칙에 달려 있으므로, 정확도만 보지 말고 확률·손실도 함께 읽는다.

### 변경 실험

```bash
python3 lab.py --steps 30
python3 lab.py --steps 600 --learning-rate 0.05
```

단계와 학습률을 동시에 바꾼 결과는 원인 분리가 어렵다. 먼저 한 번에 하나씩 바꾸어 손실, a, 평가 정확도를 기록한다. 공동 학습 결과가 좋아지는지를 보기보다, 왜 그 방향으로 이동했는지 설명하는 것이 목표다. 큰 학습률이 항상 빠른 수렴을 보장하지 않는다는 점도 생각해 본다.

## 실험 2 SetFit 쌍의 수와 반복

`pair_demo`는 클래스 라벨 두 묶음으로 모든 서로 다른 문장 쌍을 열거한다. 실제 문장의 의미 임베딩은 계산하지 않는다. 같은 클래스는 양성 쌍, 다른 클래스는 음성 쌍이다. 관계 라벨을 생성하는 단계만 분리해 보는 실험이다.

```bash
python3 lab.py --per-class 4
python3 lab.py --per-class 8 --seed 7
```

클래스당 4개라면 양성 12, 음성 16, 합 28개가 되어야 한다. 클래스당 8개라면 양성 56, 음성 64, 합 120개다. ‘한 클래스의 양성 수’와 ‘전체 클래스의 양성 수’를 구분해 손으로 계산한 뒤 실행한다.

이어서 각 문장에서 양성 상대 20번, 음성 상대 20번을 복원 추출한다. 따라서 총 항목 수는 `문장 수×40`이다. 여러 번 같은 쌍이 뽑힐 수 있고 모든 고유 쌍이 반드시 포함되는 것도 아니다. 출력의 `실제 고유 쌍`은 집합으로 중복을 제거해 계산한다. 원문 1,280이라는 수와 최대 496이라는 수가 다른 이유를 직접 확인할 수 있다.

**한계:** 이 코드는 특정 SetFit 버전의 샘플러를 복제한 것이 아니다. 자기 자신을 제외한 상대를 선택하는 교육용 샘플러다. 실제 프레임워크의 전략·중복 처리·배치 구성은 별도로 확인한다. 데이터 분할은 쌍 생성보다 먼저 원문 단위로 해야 한다.

## 실험 3 MLM 마스킹 목표 만들기

`masked_example`은 수작업으로 정의한 토큰과 원래 단어 인덱스를 사용한다. 실제 BERT 토크나이저가 이 문자열을 이렇게 나눈다는 주장이 아니다. 토큰 방식은 각 일반 토큰을 독립적으로 선택하고, 단어 방식은 원래 단어를 선택한 뒤 그 단어의 모든 조각을 가린다.

```bash
python3 lab.py --seed 4 --mask-probability 0.3
python3 lab.py --seed 4 --mask-probability 0
python3 lab.py --seed 4 --mask-probability 1
```

확률 0이면 일반 토큰도 선택되지 않고, 확률 1이면 특수 토큰을 제외한 모든 일반 토큰이 선택된다. 중간 확률에서는 한 문장의 실제 선택 비율이 설정값과 다를 수 있다. Whole-word 방식에서 한 단어의 조각이 일부만 선택되지 않는지를 확인한다.

코드는 선택 위치의 목표에 원래 토큰을 두고, 나머지에는 `-100` 표시를 둔다. 이 실습의 목표 배열은 사람이 읽을 수 있도록 문자열로 만든 것이다. 실제 모델의 loss에는 어휘 ID가 필요하다. 또한 단순화를 위해 모든 선택 위치를 `[MASK]`로 바꾸며, 실제 BERT의 마스킹 교체 정책 전체를 재현하지 않는다. 이 단계는 MLM 모델 학습이나 성능 평가가 아니라 **학습 입력과 목표를 만드는 과정**이다.

## 실험 4 NER 정렬과 개체 평가

`align_labels`는 원래 단어 ID를 따라 라벨을 토큰에 맞춘다. 추가 조각에 B 태그를 그대로 반복하지 않고 I로 바꾼다. `first_only=True`에서는 추가 조각을 `-100`으로 제외한다. 두 방식 모두 특수 토큰을 제외한다.

`spans`는 BIO 시퀀스에서 `(시작, 끝, 유형)`을 얻는다. 끝은 포함하지 않는 `[시작, 끝)` 범위다. 예를 들어 두 토큰 사람 이름은 `(0,2,'PER')`다. 이 교육용 구현은 잘못된 I 연결을 만나면 오류를 내므로, 일부 평가 라이브러리의 관대한 복원 정책과 동일하지 않다.

`entity_metrics`는 문장 ID도 포함해 예측·정답 개체의 집합을 비교한다. 같은 문장 인덱스에서 경계와 유형이 모두 일치해야 TP다. 기본 예제에서는 사람 이름의 절반만 예측하고 조직은 맞힌다.

- 정답: 사람 하나, 조직 하나.
- 예측: 짧아진 사람 하나, 정확한 조직 하나.
- TP=1, FP=1, FN=1.
- 정밀도=1/2, 재현율=1/2, F1=1/2.
- 토큰은 6개 중 5개가 맞아 정확도=5/6.

**변경 과제:** 코드의 가상 예측을 모두 `O`로 바꾸거나 사람 이름의 두 조각을 각각 `B-PER`로 바꿔 본다. 실행 전에 예측 개체 수, TP, FP, FN을 적어 보고 결과와 비교한다. 원래 파일을 유지하고 싶다면 파일을 복사해 변경한다.

## 원문의 실제 모델 실습으로 확장하는 순서

이 부분은 실행 계획이며 GPU 모델 학습을 수행한 결과가 아니다. 책의 2024년 예제 코드와 설치한 패키지의 API 차이를 확인해야 한다.

1. 사용할 모델과 데이터의 접근 조건을 확인하고 환경을 분리한다. 모델·토크나이저·데이터 버전과 seed를 기록한다. 다운로드 크기와 필요한 메모리는 선택한 모델·배치·길이에 따라 확인한다.
2. 분류 데이터의 train/validation/test를 먼저 고정한다. 원문처럼 테스트셋을 평가 인자로 연결하더라도 반복 선택에 쓰면 최종 독립 평가가 아니라는 점을 고려한다.
3. BERT 분류에서는 문장 분류 모델, 동적 패딩, 올바른 라벨 매핑을 준비한다. 새 초기 모델에서 전체·헤드·부분 미세 조정을 각각 비교한다. 동결 파라미터와 trainable 파라미터 수를 직접 출력해 확인한다.
4. SetFit에서는 클래스당 예제를 여러 seed로 샘플링하고 관계 학습과 최종 분류기 학습을 구분한다. 고유 원문 수와 샘플링 쌍 수를 별도로 기록한다.
5. 도메인 MLM은 학습에 허용된 라벨 없는 문서로 수행한다. 토크나이저와 모델을 함께 저장한 뒤, 별도 분류 목표로 다시 미세 조정한다. 마스크 예측 예시는 정성 점검이며 최종 성능 검증이 아니다.
6. NER은 단어·서브토큰 정렬, label mapping, `-100` 제외, 문장 경계, 단어 단위 복원을 확인한다. 배치 전체를 길이 1 시퀀스로 펼치지 않는다.
7. 최종 결과에는 사용한 지표의 단위와 평균 방식, 여러 seed의 변동, 시간·메모리, 실패 사례를 함께 기록한다. 원문 점수를 재현했다고 말하려면 같은 조건을 확인해야 한다.

실행 API는 [공식 Transformers 토큰 분류 안내](https://huggingface.co/docs/transformers/tasks/token_classification)와 [SetFit 샘플링 설명](https://huggingface.co/docs/setfit/conceptual_guides/sampling_strategies)을 참고한다. 이 안내에서 제공한 CPU 실습 외의 실제 모델 학습은 검증하지 않았다.
