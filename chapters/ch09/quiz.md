## 1. 입력과 출력의 모달리티

사진과 질문을 받아 텍스트로 답하지만 새 사진을 만들지는 못하는 모델은 멀티모달인가? 어떤 정보를 추가로 확인해야 기능을 정확히 설명할 수 있는가?

<details>
<summary>해설과 채점 기준</summary>

멀티모달이다. 이미지와 텍스트라는 다른 모달리티를 입력으로 처리하기 때문이다. 입력 종류와 출력 종류는 각각 기술해야 한다. 사진을 입력받는 사실만으로 이미지 생성 능력을 추정하면 안 된다. 지원하는 파일·크기·여러 이미지 처리·출력 종류 등 실제 사용 조건을 확인하면 더 정확하다.

채점 3점: 멀티모달이라고 판단 1점, 입출력 비대칭 설명 1점, 구체적인 추가 확인 항목 1점. [학습 노트 0절](study.md#sec-00).

</details>

## 2. 패치와 토큰 수 계산

224×224 RGB 이미지를 16×16 픽셀 패치로 나눈다. 패치 수, 펼친 패치 한 개의 길이, 클래스 토큰 하나를 포함한 시퀀스 길이, attention 점수 행렬의 원소 수를 계산하라.

<details>
<summary>해설과 채점 기준</summary>

패치 수는 `(224/16)²=196`, 펼친 길이는 `16²×3=768`, 시퀀스 길이는197이다. 점수 행렬은 `197×197`이므로 38,809개의 원소를 가진다. 이 수는 한 attention 점수 행렬의 형상에 대한 계산이며 전체 모델의 연산량·메모리 총량이 아니다. head와 batch, 층 수 등을 아직 포함하지 않았다.

채점 4점: 각 계산 1점. “16×16개의 패치”라고 해석하면 패치 크기와 격자 크기를 혼동한 것이다. [학습 노트 1절](study.md#sec-01).

</details>

## 3. 선형 투영의 형상

패치 행렬이 `49×3072`이고 투영 후 벡터 폭이768이어야 한다. 투영 행렬의 형상과 결과 형상을 쓰고, 위치 정보가 필요한 이유를 설명하라.

<details>
<summary>해설과 채점 기준</summary>

투영 행렬은 `3072×768`, 결과는 `49×768`이다. 패치의 개수49는 유지된다. 위치 정보는 패치의 배치·순서를 모델이 구분하도록 한다. 패치들의 내용만으로는 어떤 조각이 위·아래·왼쪽에 있는지를 명시적으로 표현할 수 없기 때문이다. 실제 위치 표현 방식은 모델 구조를 확인한다.

채점 4점: 두 형상 각1점, 개수와 폭 구분 1점, 위치의 역할 1점.

</details>

## 4. 같은 차원의 함정

임의의 텍스트 임베딩 모델과 임의의 이미지 임베딩 모델이 모두 512차원을 출력한다. 두 벡터의 내적으로 사진 검색을 만들었다. 계산 오류가 없으면 의미 검색도 타당한가? 반례를 들어 설명하라.

<details>
<summary>해설과 채점 기준</summary>

그렇지 않다. 두 표현은 차원이 같아도 의미 좌표계가 정렬되어 있지 않을 수 있다. 예를 들어 이미지 표현의 첫 축이 관련 있는 방향을 나타내지만 텍스트 표현에서는 같은 의미가 다른 방향에 놓이면, 내적 값이 의미 대응을 반영하지 않는다. 같은 2차원 점을 회전한 공간과 회전하지 않은 공간에서 바로 비교하는 모형이 반례가 된다. CLIP 같은 학습은 두 표현의 관계를 함께 학습한다.

채점 4점: 형상과 의미 구분 1점, 정렬 필요성 1점, 타당한 반례 2점. [시각 실험 2](visuals.html).

</details>

## 5. 코사인 손계산

`v=(3,4)`, `t=(4,3)`의 코사인 유사도를 계산하라. v만 열 배로 바꾸면 어떻게 되는가? 이 점수를 정답 확률로 읽어도 되는가?

<details>
<summary>해설과 채점 기준</summary>

내적24, 각 길이5이므로 유사도는24/25=0.96이다. v를 양수10배 해도 분자·분모의 배율이 상쇄되어0.96으로 유지된다. 코사인 값은 방향의 유사도이며 정답 확률96%라는 뜻이 아니다. 영벡터에서는 분모가0이라 정의할 수 없다.

채점 4점: 수치 1점, 크기 불변성 계산·설명 1점, 확률과 구분 1점, 영벡터 예외 1점.

</details>

## 6. 온도와 잘못된 확신

후보 두 개의 유사도가0.8과0.2이다. 온도1과0.1에서 첫 후보의 softmax 값을 대략 구하라. 만약 첫 후보가 실제 오답이라면 낮은 온도는 어떤 문제를 드러내는가?

<details>
<summary>해설과 채점 기준</summary>

온도1에서 첫 후보는 `1/(1+exp(-0.6))≈0.6457`, 온도0.1에서는 `1/(1+exp(-6))≈0.9975`이다. 유사도와 순위가 바뀐 것이 아니라 상대 가중치가 날카로워졌다. 첫 후보가 오답이면 틀린 후보에 매우 높은 가중치를 주므로 실제 신뢰도를 개선했다고 볼 수 없다. 점수의 calibration과 정답률은 별도로 평가해야 한다.

채점 4점: 각 값 1점, 순위 불변 설명 1점, 잘못된 확신의 의미 1점.

</details>

## 7. 배치 대응 디버깅

이미지 순서는 `[고양이, 자동차, 나무]`인데 캡션만 `[자동차, 고양이, 나무]`로 바꾸었다. 학습 코드는 여전히 대각선을 정답으로 사용한다. 어떤 오류가 생기며 어떻게 수정해야 하는가?

<details>
<summary>해설과 채점 기준</summary>

첫 이미지와 첫 캡션, 둘째 이미지와 둘째 캡션의 짝이 틀린데 대각선 정답으로 간주되어 잘못된 학습 신호가 생긴다. 이미지·캡션 쌍을 함께 shuffle하거나, 캡션을 재정렬한 순서에 맞게 정답 인덱스도 바꿔야 한다. 현재 행 기준 정답 열은 `[1,0,2]`다. 대각선은 쌍을 동일 순서로 배치했다는 가정의 결과다.

채점 4점: 오류 원인 2점, 수정 방식 1점, 정답 인덱스 1점. [실습 3단계](lab-guide.md).

</details>

## 8. 모두 같은 벡터라면

세 이미지와 세 문장 벡터를 모두 똑같이 만들었다. 모든 코사인이1이므로 학습이 성공했다고 주장한다. 왜 틀린가? 각 행의 softmax와 정답 손실을 계산하라.

<details>
<summary>해설과 채점 기준</summary>

모든 후보 점수가 같아 구별할 수 없다. 양성뿐 아니라 음성도 높은 점수이므로 검색이나 분류에 유용한 표현이 아니다. 온도가 어떤 양수여도 각 후보의 softmax는1/3이고, 정답 cross entropy는 `-log(1/3)=log(3)≈1.098612`다. 대칭 목적의 두 방향도 같은 값이다.

채점 4점: 구별 실패 설명 2점, 확률 1점, 손실 1점.

</details>

## 9. 원문 CLIP 예제의 입출력

원문 예제의 텍스트 특징은 `[1,512]`, 이미지 processor 출력은 `[1,3,224,224]`, 최종 이미지 특징은 `[1,512]`다. 각 축을 설명하고, 세 이미지·다섯 문장의 유사도 행렬을 이미지 행 기준으로 만들면 형상이 무엇인지 쓰라.

<details>
<summary>해설과 채점 기준</summary>

텍스트 특징의1은 문장 수, 512는 비교용 특징 폭이다. 이미지 processor 출력은 배치1·RGB 채널3·높이224·너비224다. 최종 이미지 특징은 이미지 수1·특징 폭512다. 세 이미지 특징 `3×512`와 다섯 텍스트 특징의 전치 `512×5`를 곱하면 `3×5`가 된다. 원문 절 제목은 OpenCLIP이지만 구체적 코드는 Transformers와 `openai/clip-vit-base-patch32`를 쓴다는 점도 구분하면 좋다.

채점 4점: 텍스트 축 1점, 영상 네 축 1점, 최종 특징 축 1점, 행렬 형상 1점.

</details>

## 10. BLIP-2의 동결과 학습

BLIP-2의 시각 인코더·Q-Former·투영층·LLM을 나열하고 이 장에서 설명하는 학습 가능 여부를 표시하라. 동결된 LLM 앞의 연결부는 왜 여전히 학습할 수 있는가?

<details>
<summary>해설과 채점 기준</summary>

시각 인코더와 LLM은 동결하고, Q-Former와 연결 투영은 학습한다. 동결은 해당 파라미터를 갱신하지 않는다는 뜻이며, 출력이 입력에 의존하지 않는다는 뜻이 아니다. 언어 모델의 출력 손실에 대한 입력 방향의 미분을 통해 앞쪽 연결부에 학습 신호를 줄 수 있다. 전체 경로를 잘못 끊으면 필요한 신호가 사라질 수 있으므로 훈련 그래프를 확인한다.

채점 5점: 네 부품의 구분 3점, 동결의 정확한 의미 1점, 연결부로 흐르는 신호 설명 1점. [학습 노트 7절](study.md#sec-07).

</details>

## 11. Q-Former query와 사용자 질문

“Q-Former는 사용자가 질문을 입력할 때만 작동한다”는 설명을 평가하라. query 2개가 key4개, value 폭3을 읽고, 이어서 3×4 투영을 통과하면 각 결과의 형상은 무엇인가?

<details>
<summary>해설과 채점 기준</summary>

틀린 설명이다. Q-Former의 학습 가능한 query 벡터와 사용자 자연어 질문은 다른 것이다. 질문 없이 이미지 캡셔닝을 할 때도 시각 특징을 읽는 query가 사용될 수 있다. attention 가중치는2×4, value 가중합은2×3, 투영 후에는2×4다. 두 번 등장하는4는 각각 key 개수와 투영 출력 폭으로 의미가 다르다.

채점 5점: query 구분 2점, 세 형상 각1점.

</details>

## 12. 생성 코드 디버깅

다음 설명에서 세 가지 문제를 찾아 바로잡아라. “processor가 이미지를 캡션으로 번역한다. generate는 이미지 ID를 반환한다. batch_decode가 그 ID를 보고 사진을 이해해 텍스트를 만든다.”

<details>
<summary>해설과 채점 기준</summary>

processor는 이미지를 픽셀 텐서 등 모델 입력으로 전처리하며 캡션을 생성하지 않는다. 이 BLIP-2 흐름에서 generate는 생성된 텍스트 토큰 ID를 반환한다. batch_decode는 그 텍스트 토큰 ID를 문자열로 변환한다. 이미지 정보의 추출·연결과 언어 생성은 모델 내부에서 수행된다. 올바른 흐름은 `이미지 → 전처리 → 시각 인코더·연결부·LLM → 텍스트 ID → 문자열`이다.

채점 4점: 세 오류 수정 각1점, 전체 흐름 1점. [학습 노트 9절](study.md#sec-09).

</details>

## 13. 전처리 설계 문제

가로로 긴 표가 포함된 사진에서 모델이 오른쪽 열을 계속 놓친다. 모델을 더 크게 바꾸기 전에 확인할 원인을 세 가지 제시하고, 각 원인을 확인할 실험을 설계하라.

<details>
<summary>예시 해설과 채점 기준</summary>

가능한 원인은 중앙 crop으로 오른쪽이 잘린 경우, 축소로 글자가 너무 작아진 경우, 종횡비 왜곡으로 글자 형태가 변한 경우다. processor 출력의 이미지 범위를 직접 시각화하고 원본의 오른쪽 경계와 비교한다. 같은 표를 오른쪽 영역만 따로 잘라 입력해 판독이 개선되는지 확인한다. 비율 유지와 허용된 다른 전처리 설정을 비교하되, 체크포인트가 지원하는 조건을 확인한다. 행·열 관계 오류는 별도 평가한다.

유일한 정답 설계를 요구하지 않는다. 채점 6점: 서로 다른 원인3개에 각1점, 각 원인과 연결된 관찰 실험3개에 각1점. 단순히 “더 좋은 프롬프트를 쓴다”만 적으면 입력 정보 손실 가설을 검증하지 못한다.

</details>

## 14. 제로샷 상품 분류 설계

상품 사진을 CLIP으로 다섯 카테고리 중 하나에 분류하려 한다. 일부 사진은 다섯 카테고리 어느 것에도 속하지 않는다. 후보 문장 구성, 거절 판단, 평가 자료를 어떻게 설계할지 설명하라.

<details>
<summary>예시 해설과 채점 기준</summary>

카테고리 설명은 의미가 구체적이고 서로 겹치는 범위를 줄이도록 작성한다. 단어의 다의성이나 언어 지원을 확인하고, 문장 표현에 따른 결과 변화도 측정한다. 최고 점수만 무조건 반환하지 말고 검증 자료에서 절대 점수·상위 점수 차이 등을 조사해 거절 기준의 효용을 평가한다. 임의의 코사인 임계값을 보편적 확률처럼 사용하지 않는다. 평가에는 정상 카테고리, 경계 사례, 시각적으로 비슷한 오답, 카테고리 밖 사진을 포함한다.

채점 6점: 후보 설계 2점, 근거 있는 거절 설계 2점, 평가 자료 구성 2점. 한 가지 숫자 임계값이 모든 모델·데이터에서 통한다는 주장은 감점한다.

</details>

## 15. 이미지 대화 시스템 설계

사용자가 자동차 사진을 올린 뒤 “이 차는 무슨 색인가?”, “얼마인가?”, 다른 자동차 사진을 올린 뒤 “그럼 이건?”이라고 묻는다. 이미지·대화 이력·근거를 어떻게 관리할지 설계하라.

<details>
<summary>예시 해설과 채점 기준</summary>

사진마다 식별자를 부여하고 현재 질문이 어느 이미지를 참조하는지 분명히 관리한다. 새 사진에서 이력을 비우거나, 이전 사진·답변을 명시적으로 구분하는 방식을 선택한다. 색은 직접 시각 단서를 근거로 답할 수 있지만 가격은 차종·연식·상태·시장 조건 등이 필요하므로 추가 질문이나 외부 조회가 필요할 수 있다. 이전 모델 답변을 검증된 사실로 재사용하지 않고, 근거와 추정을 구별한다. 긴 이력은 토큰 한도 안에서 관리한다.

채점 6점: 이미지 전환·참조 관리 2점, 시각 근거와 외부 정보 구분 2점, 이력 오류·길이 관리 2점.

</details>

## 16. 전체 구조를 설명하는 응용 과제

사진 자료실에서 “조건에 맞는 사진을 찾아 그 사진을 세 문장으로 설명하는” 도구를 설계한다. CLIP·ViT·BLIP-2의 역할을 도식으로 그리고, 검색 실패와 생성 실패를 구분해 평가할 방법을 제시하라.

<details>
<summary>예시 해설과 채점 기준</summary>

사진을 CLIP의 이미지 인코더로 표현해 저장하고, 사용자 질의를 CLIP의 텍스트 인코더로 표현해 후보를 검색한다. 이미지 인코더가 ViT라면 그 내부에서 패치 시퀀스를 처리한다. 선택한 사진과 설명 요청을 BLIP-2 같은 생성 경로에 넣어 문장을 만든다. 같은 사진 표현을 두 모델이 무조건 공유할 수 있다고 가정하지 말고 각 모델의 processor·인코더·연결부를 따른다.

검색 평가는 정답 사진이 상위 후보에 있는지 확인하고, 생성 평가는 실제 선택된 사진에 대해 존재·속성·관계·근거 없는 단정을 확인한다. 검색이 틀리면 정답 사진을 직접 공급해 생성 경로를 따로 테스트하고, 검색이 맞아도 잘못 설명하면 생성 오류로 분리한다. 세 문장이라는 형식 준수와 내용 정확성도 별개로 기록한다.

채점 8점: 세 구조의 역할·데이터 경로 4점, 검색·생성 분리 평가 3점, 형식과 사실 구분 1점.

</details>
