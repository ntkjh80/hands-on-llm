# 9장 강의안 멀티모달 언어 모델

[전체 목차](../../README.md) · [학습 노트](study.md) · [강의안](lecture.md) · [강의 대본](lecture-script.md) · [시각 실험](visuals.html) · [실습 안내](lab-guide.md) · [복습 문제](quiz.md)

이 수업은 학습자가 이미지와 텍스트를 연결하는 세 구조를 자신의 말로 구별하고, 데이터의 차원을 추적할 수 있게 하는 **85분 수업**이다. 시간은 설명·질문·손계산·실습을 포함한 설계이며 대본 낭독 시간과 같지 않다. 원문 범위는 *Hands-On Large Language Models*, Chapter 9, PDF 물리 페이지 360~397쪽이다.

## 교사가 준비할 것

- [학습 노트](study.md)를 읽고 3개의 핵심 흐름을 판서할 준비를 한다.
- [시각 실험](visuals.html)을 브라우저에서 열고 첫 실험의 기본값을 224/32로 맞춘다.
- Python 3 환경에서 `python3 chapters/ch09/lab.py`가 실행되는지 확인한다. 외부 패키지·GPU·API 키는 필요 없다.
- 원문 모델의 결과를 직접 재현한 수업이 아니라, 합성 데이터로 원리를 계산하는 수업임을 처음에 알린다.
- 학습자에게 종이 한 장을 준비하게 하고 왼쪽에 “배치·길이·폭”, 오른쪽에 “입력·처리·출력”을 적게 한다.

## 0~7분 도입과 사전 점검

**판서:** `사진 + 글 → ?`를 적고 가능한 출력을 세 가지 묻는다. 기대 답은 관련 이미지의 순위, 설명 문장, 질문에 대한 답이다. “사진을 받을 수 있으면 사진도 만들 수 있나요?”라는 질문을 던져 입출력 모달리티가 별도임을 확인한다.

**교사의 설명 포인트:** 모달리티는 데이터 표현의 종류이며 멀티모달은 입력과 출력의 범위를 따로 명시해야 한다. 사진에 관련한 문장을 찾는 계산과 새 문장을 생성하는 계산은 서로 다른 최종 목적이다. 원문 Figure 9-1의 논지를 [학습 노트 0절](study.md#sec-00)과 연결한다.

**1분 진단:** “512차원 사진 벡터와 512차원 문장 벡터가 있다. 바로 의미를 비교할 수 있는가?”에 찬반과 이유를 쓰게 한다. 지금 정답을 길게 설명하지 말고 수업 중 다시 확인한다. 좋은 초기 답은 “차원 외에 두 표현이 같은 의미 좌표계인지 확인해야 한다”이다.

## 7~21분 ViT와 차원 계산

**판서 순서:** `이미지 H×W×3 → 패치 N개 → N×(P²×3) → 선형 투영 → N×D → 위치·클래스 토큰 → 인코더`.

**교사의 설명 포인트:** 패치는 단어처럼 고정 ID를 조회하는 방식이 아니라 픽셀을 펼쳐 선형 투영한다. 패치 수와 벡터 폭은 다르다. 원문 도식의 3×3은 설명을 위한 격자이며, 16×16이라는 표현은 패치 픽셀 크기와 전체 격자 크기를 구분해야 한다. [학습 노트 1절](study.md#sec-01).

**3분 짝 활동:** 다음 세 줄을 채운다.

| 가정 | 패치 수 | 펼친 패치 길이 | 클래스 토큰 포함 길이 |
|---|---:|---:|---:|
| 224×224 RGB, P=32 | 49 | 3072 | 50 |
| 224×224 RGB, P=16 | 196 | 768 | 197 |
| 448×448 RGB, P=32 | 196 | 3072 | 197 |

질문은 “두 번째와 세 번째는 시퀀스 길이가 같은데 왜 패치 길이가 다른가?”이다. 기대 답은 전체 이미지와 패치 픽셀 크기가 달라 한 패치의 원시 정보량이 다르기 때문이다. 인코더 입력 폭 `D`는 별도의 선형 투영으로 맞출 수 있다.

**시연:** 첫 시각 실험에서 224/32 → 224/16 → 448/32로 바꾼다. 학습자가 예측한 값과 비교한다. attention 점수 원소가 길이의 제곱으로 커짐을 보여 주되 전체 실행시간의 정확한 배수라고 말하지 않는다.

**학습 확인:** “패치를 작게 하면 벡터 폭도 반드시 작아지나요?” 기대 답은 원시 패치 길이는 줄지만, 투영 후 폭 `D`는 모델 설계가 정한다는 것이다.

## 21~39분 CLIP과 공동 공간

**판서:** 이미지 인코더와 텍스트 인코더 두 갈래를 그려 공동 벡터 공간으로 모은다. 서로 다른 지도가 같은 차원이어도 기준이 다르면 비교할 수 없다는 비유를 사용한다. 좌표 하나를 실제 사물 이름과 동일시하는 비유의 한계도 덧붙인다.

**3분 행렬 활동:** 아래 행렬에서 각 이미지에 가장 가까운 텍스트와 각 텍스트에 가장 가까운 이미지를 찾게 한다.

| 이미지 / 문장 | 강아지 | 자동차 | 풍경 |
|---|---:|---:|---:|
| 강아지 사진 | 0.33 | 0.12 | 0.09 |
| 자동차 사진 | 0.10 | 0.31 | 0.17 |
| 풍경 사진 | 0.08 | 0.14 | 0.29 |

값은 교육용 가상 값이다. “강아지 확률은 33%”라는 해석이 왜 틀린지 설명하게 한다. 정답 확률이 아닌 코사인 유사도이며 모델·후보·전처리와 함께 읽어야 한다는 답을 기대한다.

**설명 확장:** 제로샷 분류는 후보 설명 중 가장 가까운 것을 고르는 방식이다. 군집화·검색·이미지 생성 시스템에 조건을 제공하는 응용까지 원문 네 활용을 빠뜨리지 않고 짚는다. CLIP이 자체적으로 자유로운 문장이나 픽셀을 생성하는 모델이라고 말하지 않는다. [학습 노트 2~5절](study.md#sec-02).

**시연:** 두 번째 시각 실험의 회전값을 0°에서 90°로 바꾼다. 같은 두 차원이라도 순위가 틀려질 수 있음을 보인다. 회전은 고정하고 온도만 1.0과 0.05로 바꾼다. 유사도와 순위가 같아도 상대 가중치·손실이 바뀐다는 사실을 설명한다.

**학습 확인:** “모든 이미지·텍스트를 같은 벡터로 만들면 정답 유사도가 높아집니다. 좋은 학습인가요?” 기대 답은 경쟁 후보도 모두 같아 구별할 수 없으며, 부정 예제와 대조 목적이 필요하다는 것이다.

## 39~56분 BLIP-2의 연결부와 두 단계 학습

**판서:** `동결 시각 인코더 → Q-Former → 투영 → 동결 LLM`. Q-Former·투영에 동그라미를 하고 학습 가능이라고 적는다. 동결은 가중치 갱신 제외라는 뜻이며 계산 제외가 아님을 확인한다.

**교사의 설명 포인트:** query는 사용자의 문장 질문과 동일하지 않다. 학습 가능한 연속 벡터가 시각 특징에서 정보를 읽어 온다. 첫 단계는 이미지·문장 관계를 학습하고, 두 번째 단계는 LLM이 그 정보를 이용해 텍스트를 생성하도록 연결한다. 첫 단계의 세 목적을 이름만 읽지 말고 예로 설명한다. [학습 노트 7절](study.md#sec-07).

| 활동 카드 | 학습자가 분류할 목적 |
|---|---|
| 여러 문장 중 이 사진의 짝을 상대적으로 가깝게 | Image-text contrastive |
| 이 한 쌍이 실제로 맞는지 판별 | Image-text matching |
| 이미지 정보를 보고 관련 문장 예측 | Image-grounded generation |

**2분 손계산:** `Q-Former 출력 4×8`, `투영 행렬 8×12`이면 결과는 `4×12`이다. query 수가 네 개로 유지됨을 표시하게 한다. 시각 prompt가 “사람이 읽을 수 있는 캡션 네 단어”라는 잘못된 답을 수정한다.

**시연:** 세 번째 시각 실험에서 query 크기를 0으로 바꿔 균등 가중치를 확인한다. 크기를 2로 되돌리고 방향을 0°→90°로 바꿔 가중합이 변함을 본다. 단일 attention 계산이며 실제 학습된 Q-Former 전체가 아님을 명시한다.

**학습 확인:** “Q-Former가 학습되면 동결된 ViT 가중치도 바뀌나요?” 기대 답은 ViT 출력에서 읽는 방식이 바뀌는 것이며 ViT 파라미터는 그대로라는 것이다.

## 56~68분 전처리와 이미지 대화

**판서:** `원본 → processor → pixel_values + input_ids → generate → text token IDs → batch_decode → 문자열`.

**교사의 설명 포인트:** 이미지의 배치·채널·높이·너비 축을 확인하고, 토큰 ID는 정수여야 함을 말한다. 전처리의 crop·resize·padding은 남기는 정보를 바꿀 수 있다. 원문의 `Ġ`는 토큰의 공백 표시이며 실제 입력에 밑줄을 넣는 규칙이 아니다. `generate`의 출력은 이 흐름에서 텍스트 ID다. [학습 노트 8~10절](study.md#sec-08).

**4분 근거 분류 활동:** 자동차 사진이 있다고 가정하고 다음 질문을 세 범주에 분류하게 한다.

| 질문 | 기대 분류 | 교사 해설 |
|---|---|---|
| 차체는 어떤 색인가 | 직접 시각 단서 | 조명·해상도 때문에 오류 가능성은 남음 |
| 왜 해질녘처럼 보이는가 | 시각 단서의 해석 | 하늘색·그림자 등을 근거로 설명 |
| 차를 사는 가격은 얼마인가 | 외부 정보 필요 | 차종·연식·상태·지역·시점 필요 |
| 사진 소유자는 누구인가 | 외부 정보 필요 | 픽셀에 식별 근거가 없을 수 있음 |

원문의 구체적인 자동차 비용 답변은 검증된 가격 자료가 아님을 짚는다. 잉크 얼룩 캡셔닝은 모호한 입력을 익숙한 개념으로 해석하는 사례이며 심리 진단으로 취급하지 않는다.

**상태 관리 질문:** 대화 이력은 어디에 있는가? 기대 답은 예제에서는 프로그램의 `memory` 목록에 저장되어 프롬프트로 다시 전달된다는 것이다. 이미지를 바꾸면 이력을 어떻게 처리할지도 논의한다.

## 68~79분 Python 개념 실습

[실습 안내](lab-guide.md)에 따라 기본 실행 후 두 변형을 수행한다.

```bash
python3 chapters/ch09/lab.py
python3 chapters/ch09/lab.py --patch-size 4 --temperature 1
python3 chapters/ch09/lab.py --query-scale 0
```

**관찰표:** 실행 전에 예측을 쓰고 실행 후 실제 값을 적는다.

| 변경 | 예측해야 할 것 | 기대 관찰 |
|---|---|---|
| patch 2→4 | 패치 수·원시 폭·투영 폭 | 16→4, 12→48, 최종 폭3 유지 |
| 온도 .2→1 | 유사도·가중치·손실 | 유사도 그대로, 분포가 더 완만 |
| query scale 2→0 | 가중치와 요약 | 각 key 0.25, value 평균 |

교사는 합성 벡터에 붙인 `cat/car/tree` 이름을 인식 결과로 부르지 않는다. “정확도 100%”라는 식의 모델 성능 발표 대신, 정해 놓은 합성 대응에서 순위가 의도와 일치하는 계산 검산이라고 표현한다.

## 79~85분 정리와 출구 문제

학습자에게 다음 세 질문에 각각 두 문장 이내로 답하게 한다.

1. CLIP과 BLIP-2가 둘 다 이미지와 텍스트를 다루는데, 출력 목적은 어떻게 다른가?
2. 어떤 답이 이미지에서 나온 사실인지 확인하려면 무엇을 점검해야 하는가?
3. 오늘 배운 대조 관계가 10장의 텍스트 임베딩 학습과 어떻게 연결되는가?

**채점:** 첫 질문은 유사도·공동 표현 대 생성 구분에 2점, 둘째는 시각적 근거와 외부 지식·추정을 구분하면 2점, 셋째는 양성 쌍·경쟁 후보·표현 학습을 연결하면 2점이다. 점수가 낮은 학습자는 [복습 문제](quiz.md)의 1·4·8·12번을 먼저 푼다.

## 시간 조정과 과제

- **60분 수업:** 첫 계산 표는 사전 과제로 제공하고, 교실에서는 회전·온도 실험과 BLIP-2 구조에 집중한다. Python 실행과 심화 VQA 설계는 수업 후 수행한다.
- **90분 수업:** 마지막 5분을 더 사용해 정답 후보가 없는 제로샷 분류의 처리 방안을 토론한다.
- **과제:** 사진 검색 또는 사진 질의응답 중 하나를 선택하고 입력·전처리·모델 출력·평가 기준을 한 페이지로 설계한다. 최소 두 가지 실패 사례와 그 실패를 확인할 테스트 질문을 포함한다.
